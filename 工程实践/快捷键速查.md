## 基础知识补强

本篇以概念与学习方法为主：先理解快捷键的「语法」，再按场景成组地练，而不是一张大表从头背到尾。

### 核心概念与术语

- 修饰键：Ctrl、Shift、Alt、Win（Mac 上对应 Cmd、Option）是「前缀」，自己不干活，专门改造主键的含义。
- 主键：字母、数字、方向键、功能键（F1–F12）等真正触发动作的键。
- 组合键（chord 有两种含义）：一是同时按下的组合，如 Ctrl+S；二是 VS Code 式连续序列，先按一组再按一组，如先 Ctrl+K 再 Ctrl+S，中间可以松手。
- 上下文（context）：同一个键在不同焦点下做不同事——Ctrl+W 在浏览器是关标签，在编辑器可能删词，在终端可能是删前一个词。
- 焦点（focus）：当前接收键盘输入的那个控件；快捷键「没反应」一半是焦点不在你以为的地方。
- 命令面板：把全部功能做成可搜索列表的入口（VS Code、Obsidian、IDEA 都有），是快捷键体系的兜底：记不住键，搜命令名。
- 全局键与应用内键：Win+L 这类由系统截获、所有应用都生效的是全局键；编辑器里的键只在该应用有焦点时生效，两者冲突时全局优先。
- Leader 键：Vim 等工具里先按一个前缀键再接后续键的扩展方式，本质是把单键不够用变成序列。
- 键位记法：`Ctrl+Shift+P` 表示三键同时按；`Ctrl+K Ctrl+S` 表示两段序列；文档里写法不同，先认清是哪一种。
- 助记锚点：很多键取动作英文首字母（S=Save、F=Find、P=Print/命令面板因软件而异），知道规律后猜得出七成，比逐个死记可靠。
- 生态差异主要是修饰键的位置与叫法：Windows 的 Ctrl 到 Mac 多半对应 Cmd，Alt 对应 Option；手的位置变了，字母部分通常不变。
- 「一键多义」不是设计混乱，而是分层复用：系统层、应用层、编辑区层各管一段，理解分层后就不会奇怪同一个键为何换个窗口就变。
- Fn 层：笔记本上 F1–F12 常和音量、亮度共用一排键，谁是默认由 Fn 锁定状态决定，功能键「失灵」先查这个。
- 记忆组块（chunk）：大脑记的不是单个键，而是「重构这一组」「调试这一组」成套的动作序列，按组学比按字母序背快得多。

### 基础语法与用法

先补齐所有应用通用的文本编辑基本功（没列进前面表格，但使用频率最高）：

```
Ctrl+S / Ctrl+Z / Ctrl+Shift+Z(或 Ctrl+Y)   保存 / 撤销 / 重做
Ctrl+A / Ctrl+F                              全选 / 查找
Home / End                                   行首 / 行尾
Ctrl+Home / Ctrl+End                         文首 / 文尾
Ctrl+← / Ctrl+→                              按词跳（而不是按字符挪）
Shift+方向键                                 扩展选区；配合 Ctrl 按词扩展
Ctrl+Backspace / Ctrl+Delete                 按词删除（改长变量名神器）
Esc                                          取消 / 关弹窗 / 退回上一层
```

学习方法（照这个节奏练，比硬背有效）：

```
第 1 步：只选一组场景（如「导航」），把其中 3–5 个键贴在显示器边上
第 2 步：一周内刻意不用鼠标做这组动作，慢也忍着，肌肉记忆靠重复次数
第 3 步：这组动作不用看手就能按对后，再开下一组
第 4 步：每周从命令面板里「考古」1–2 个高频操作，反查它的快捷键补进清单
第 5 步：把个人最终清单控制在 40–60 个真正常用的，多了就是负担
```

遇到「我想做 X，有没有快捷键」的标准查法：

```
VS Code    Ctrl+Shift+P 搜命令名 → 右侧就显示当前绑定的键
IDEA       双击 Shift 搜动作名 → 或 Settings 里搜 Keymap
Obsidian   Ctrl+P 搜命令 → 设置里的「快捷键」可查可改
通用       鼠标悬停在按钮/菜单项上，提示里通常写着对应键
```

维护一份个人清单（比收藏别人的大表有用得多）：

```
# 我的快捷键（按场景分组，每组只留真用的）
## 导航：找文件 / 找符号 / 前进后退
## 编辑：多光标 / 整行操作 / 注释
## 重构：重命名 / 抽取 / 快速修复
## 调试：断点 / 步过步入 / 看表达式
## 窗口：分屏 / 终端 / 侧边栏
# 维护规则：新学的键先放「练级中」分组，连续用一周才转正；
# 三个月没按过的键直接删，清单长度不设自豪感。
```

冲突与改键的操作顺序：

```
1. 先确认是不是焦点问题：点一下目标区域再按一次
2. 再确认 Fn 状态：功能键和多媒体键谁在默认层
3. 再查系统级占用：输入法、截图工具、显卡工具常年抢键
4. 最后才改键：改到顺手区（左手可及处优先），并记下改了什么
```

### 关键机制速览

- 快捷键本质是「键位 → 命令」的映射表，不是写死在功能里的；所以任何键都能改绑，学快捷键其实是学命令名 + 映射表两件事。
- 事件先经系统、再到应用、再到焦点控件，任何一层截获就轮不到下一层——这解释了为什么换个输入法状态、开个弹窗，同一个键就变了行为。
- 大多数编辑器把「操作」抽象成命名命令（如 format、rename），快捷键、菜单、命令面板只是同一命令的三个入口；记住命令名，入口随便换。
- 多光标、多段序列这类设计都是在解决同一个问题：单键不够用，于是用「序列」和「模式」换取键位空间，代价是学习曲线。
- 肌肉记忆形成在「想都不用想」的层面，标准是：眼睛看代码、手自己动；达不到这个程度的高频键，就是还没练够次数，而不是没天赋。
- 同一生态内键位高度趋同（保存、撤销、查找全软件一致），跨生态（Win/Mac、IDEA/VS Code）主要差在少量键和修饰键位置，迁移时先对齐那十几个差异键即可。

### 新手易错点

- 拿着清单从头背到尾：一周后全忘。按场景分组、一次只练一组，留存率高得多。
- 在 VS Code 里把 `Ctrl+K Ctrl+S` 当四键同按：这是两段序列，第一组松手后再按第二组。
- 功能键按了没反应就断定软件坏了：先查 Fn 锁定，多媒体层在上面时 F5 可能变成了刷新以外的动作。
- 中文输入法开着时按快捷键：一半字母键被输入法吃掉；写代码时养成切英文输入法的习惯，或给输入法设中英文切换键。
- 改键改到和系统全局键冲突：如把常用组合设成被截图、输入法占用的键，表现为「有时灵有时不灵」。
- 只记键位不记命令：换软件就清零。正确顺序是先记住「这个操作叫什么」，再查它在当前软件绑哪个键。
- 笔记越记越多从不删减：半年后把从没用过的键从清单里划掉，清单只留真肌肉记忆，查漏才看得过来。
- 在远程桌面/虚拟机里按本机习惯：键位要穿过两层映射，个别组合会被宿主机截获（如 Win 键、Alt+Tab），属正常现象，改用远端内的菜单入口兜底。

## 面试与自测

1. 在 VS Code 里把 `Ctrl+K Ctrl+S` 当四键同按为什么是错的？键位记法里「同时按」和「序列」怎么区分？
2. 快捷键按了没反应，排查顺序是什么？为什么「改键」要放在最后？
3. 本篇反对「拿着清单从头背到尾」，推荐的学习节奏和清单长度各是什么？

### 参考答案

1. `Ctrl+K Ctrl+S` 是两段序列：先按 Ctrl+K，松手后再按 Ctrl+S，不是四键同按。记法规则是：`Ctrl+Shift+P` 表示三键同时按；`Ctrl+K Ctrl+S` 表示两段序列，文档里写法不同，先认清是哪一种。
2. 排查顺序是：先确认是不是焦点问题（点一下目标区域再按一次，快捷键「没反应」一半是焦点不在你以为的地方）；再确认 Fn 状态（笔记本上 F1–F12 常和音量、亮度共用一排键，谁是默认由 Fn 锁定状态决定）；再查系统级占用（输入法、截图工具、显卡工具常年抢键）；最后才改键（改到顺手区，左手可及处优先，并记下改了什么）。改键放最后，是因为前面三项才是常见根因，且改到和系统全局键冲突会表现为「有时灵有时不灵」。
3. 推荐节奏是：第 1 步只选一组场景（如「导航」），把其中 3–5 个键贴在显示器边上；第 2 步一周内刻意不用鼠标做这组动作；第 3 步这组动作不用看手就能按对后，再开下一组；第 4 步每周从命令面板里「考古」1–2 个高频操作，反查它的快捷键补进清单；第 5 步把个人最终清单控制在 40–60 个真正常用的，多了就是负担。拿着清单从头背到尾，一周后全忘；按场景分组、一次只练一组，留存率高得多。
