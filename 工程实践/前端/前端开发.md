## 后端联调要点

- **CORS**：前后端分离必配。后端（Spring Boot）放行来源、方法、头；预检请求（OPTIONS）别被拦截器拦了。
- **REST 约定**：资源名词复数、HTTP 动词表语义、状态码表结果（200/201/400/401/403/404/500）。
- **fetch 示例**：

```js
const res = await fetch('/api/chapters?page=1', {
  headers: { 'Authorization': 'Bearer ' + token }
});
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const data = await res.json();
```

- **时间/数字坑**：前后端统一用 ISO 8601 / 时间戳传时间；金额用字符串或分单位，别用 float 裸传。

## 5 个常见坑

1. **跨域调不通先看 Network**：是 CORS 预检失败、CORS 头缺失，还是后端根本没收到请求，三者排查路径完全不同。
2. **缓存背刺**：静态资源文件名不带 hash，发版后用户看到旧页面；Vite 默认带 hash，手动拷文件时注意。
3. **时区**：`new Date()` 用的是浏览器本地时区，和后端 UTC 对不上是常态，传输统一用 UTC 时间戳。
4. **大列表卡顿**：几千行直接渲染必卡，虚拟滚动（只渲染可视区）是标准解，原理与做法见 [开发语言/JavaScript.md](开发语言/JavaScript.md)「性能优化三板斧」。
5. **XSS**：用户输入拼进 `innerHTML` 就是漏洞；用 `textContent` 或框架默认转义，富文本走白名单过滤。

## 疑难杂症

### 1. history 路由刷新 404
- **现象**：Vue/React history 模式，首页正常，刷新子页面或直接访问报 404。
- **原因**：history 模式靠前端路由，刷新时浏览器直接请求 `/user/1`，Nginx/服务器没这个文件。
- **解决**：Nginx 配 `try_files $uri $uri/ /index.html;`；图省事用 hash 模式（URL 带 `#`）。

### 2. 大文件上传失败率高
- **现象**：几百 MB 文件上传经常断，失败重传又要从头来。
- **原因**：单次 HTTP 上传，中途断网就全废；Nginx 默认 `client_max_body_size` 才 1m。
- **解决**：前端分片（Blob.slice）+ 断点续传 + 秒传（hash 校验）；Nginx 调大 `client_max_body_size`；后端支持分片合并。

### 3. 开发环境正常，上线后接口 404
- **现象**：本地 `vite` 代理好好的，部署到 Nginx 后接口全 404。
- **原因**：vite 的 proxy 只在开发服务器生效，打包后不存在了。
- **解决**：生产环境在 Nginx 配同样的 `/api` 转发；前后端路径前缀保持一致，别只在 vite.config 里配。

## Vite 构建优化

```js
// vite.config.js
export default {
  build: {
    rollupOptions: { output: { manualChunks: {
      vendor: ['vue', 'vue-router'],   // 第三方单独分包，缓存命中率高
    } } },
    chunkSizeWarningLimit: 1000,
  }
}
```

- 首屏只加载首屏的：路由懒加载 `() => import('./views/xx.vue')` 是基本功。
- `vite-bundle-visualizer` 看包体积，echarts/lodash 全量引入是重灾区（按需引）。
- 生产 `sourcemap` 关掉，少一半体积还防源码泄露。

## 基础知识补强

### 核心概念与术语

- 网页的本质：浏览器向服务器要文件（HTML、CSS、JS、图片），拿到后在本地把页面「画」出来；前端代码跑在用户机器上，不在服务器上。
- URL 的构成：协议 + 域名 + 端口 + 路径 + 查询参数 + 锚点，每一段都有明确职责。
- 域名与 DNS：域名是给人看的名字，DNS 负责把它翻译成服务器 IP，翻译不了就没有后面一切。
- HTTP 请求：一行请求行（方法 + 路径 + 版本）、一堆请求头、一份可选的请求体；响应同理是状态行 + 响应头 + 响应体。
- 无状态：HTTP 每个请求互相独立，服务器不天然记得你是谁；登录状态靠 Cookie/Token 人为续上。
- DOM（文档对象模型）：浏览器把 HTML 解析成的一棵节点树，JS 操作页面就是操作这棵树。
- 渲染：浏览器把 DOM 和样式算成像素的过程，分解析、计算样式、布局、绘制、合成几步。
- 事件：用户点击、输入、滚动等动作被包装成事件对象交给 JS 处理，是页面「动起来」的唯一入口。
- 同步与异步、事件循环：JS 单线程靠事件循环调度异步回调，慢活必须异步等结果否则页面卡死；完整机制见 [开发语言/JavaScript.md](开发语言/JavaScript.md)。
- JSON：前后端传数据的默认格式，本质是受限的 JS 对象字面量（键必须双引号、不能有尾随逗号）。
- 浏览器存储三分工：Cookie 随请求自动发送（体积小、给登录态用），localStorage 持久存本地，sessionStorage 关标签即清。
- npm 生态三件套：Node.js 是运行环境，npm 是包管理器，package.json 是项目的「依赖与脚本清单」。

### 基础语法与用法

在浏览器里打开一个页面的完整链路（排查问题时按这条链逐段切）：

```
输入 URL → DNS 查 IP → 建 TCP/TLS 连接 → 发 HTTP 请求
→ 服务器返回 HTML → 浏览器解析并渲染
→ 遇到 CSS/JS/图片再逐个发请求取回 → JS 执行、绑定事件 → 页面可交互
```

DOM 操作（选中元素、改内容、绑事件）的完整最小例子见 [开发语言/JavaScript.md](开发语言/JavaScript.md)「DOM 基础」一节（所有框架最终都在做这件事）；联调视角只记一条：改文字用 `textContent`，别拼 `innerHTML`（XSS 入口，见本篇「5 个常见坑」第 5 条）。


表单取值的最小例子：

```html
<input id="name" placeholder="姓名">
<button id="save">保存</button>
<script>
  document.querySelector('#save').addEventListener('click', () => {
    const name = document.querySelector('#name').value.trim();
    if (!name) { alert('姓名不能为空'); return; }
    console.log('准备提交：', { name });
  });
</script>
```

npm 与 Node 的日常命令（init / install / run / build）见 [开发语言/JavaScript.md](开发语言/JavaScript.md)「Node 速查」；本篇只留 package.json 的读法。

package.json 里最先要看懂的两块：

```json
{
  "scripts": { "dev": "vite", "build": "vite build" },
  "dependencies": { "vue": "^3.5.0" },
  "devDependencies": { "vite": "^6.0.0" }
}
```

- `^3.5.0` 是语义化版本范围：主版本 . 次版本 . 修订号，`^` 表示允许次版本内升级，主版本变了多半有破坏性改动。
- `node_modules` 是装下来的依赖本体，不进 Git；换机器靠清单一条 `npm install` 还原。

### 关键机制速览

- 渲染流水线：HTML 解析成 DOM、CSS 解析成 CSSOM，两者合成渲染树，再算每个元素的位置（布局）和颜色（绘制）；JS 能阻塞这条流水线，所以 script 标签的位置和加载方式会影响首屏速度。
- 样式改了触发的代价分三档：改布局属性（宽高、位置）最贵，要重算布局；改颜色、背景次之；改 transform、opacity 最便宜，走合成层——动画卡不卡先看动的是哪类属性。
- 事件流三阶段：捕获（从根往下找目标）、目标、冒泡（从目标往上回传）；绝大多数监听挂在冒泡阶段，事件委托就是利用冒泡，把子元素的监听统一挂到父元素上。
- 状态驱动视图是所有现代框架的共同思想：不手动改 DOM，而是改数据（状态），框架负责把新状态映射成新界面；原生写法里手动 getElementById 改来改去的痛苦正是它要解决的。
- 打包工具做的事：把一堆模块、样式、图片按依赖关系拼成少量可部署文件，顺带做压缩、去无用代码和文件名加 hash；开发时不打包是为了改完立即看效果。
- Cookie 自动随同域请求发送，localStorage 不会；所以登录凭证放哪不是随手选的，涉及安全模型，别把敏感 Token 随手塞 localStorage 还长期不失效。

### 新手易错点

- 把 JS 写进 HTML 却不生效：先看 script 是否在元素之后执行（找不到元素是 null），或把脚本放到页面底部 / 加 defer。
- 改了后端数据前端没变化就怪缓存：先在 DevTools 的 Network 里看请求到底发没发、返回的是什么，再谈刷新问题。
- 类型与比较的坑（字符串混算、`==` 隐式转换、异步代码按同步顺序写）：都是语言层面的坑，完整版见 [开发语言/JavaScript.md](开发语言/JavaScript.md)「5 个常见坑」与「关键机制速览」；联调时只记一句：表单和 URL 取到的永远是字符串，运算前先 `Number()` 转换。
- 事件绑了多次：重复执行绑定代码会叠加监听，一次点击触发多回；绑定只在初始化时做一次。
- 本地跑通就以为上线没问题：本地有开发服务器的代理和热更新兜底，生产是纯静态文件 + 服务器转发，两套环境差异先在部署清单里对齐。
