# 观察者模式

## 模式介绍

**意图**：定义对象间一对多的依赖：被观察者状态变化时，自动通知所有订阅它的观察者，发布方不需要知道订阅者是谁、拿到通知做什么。

**结构与角色**：
- Subject（主题/被观察者）：维护订阅列表，提供 attach/detach/notify。
- Observer（观察者接口）：只声明一个更新方法，如 `update(event)`。
- ConcreteObserver（具体观察者）：短信、邮件、积分、日志等各自独立的实现，互不知情。

**效果**：
- 优点：发布与订阅彻底解耦，新增一种通知动作只加一个观察者类，不改发布方；订阅关系运行时可动态增减。
- 代价：通知顺序与失败隔离要自己管（一个观察者抛异常不能拖垮其他人）；链式触发容易失控（A 通知里改 B、B 又通知回 A）；异步化后排查顺序问题更难。

**适用信号**：一个事件要触发多个互相独立的后续动作（下单成功→发短信+加积分+记日志+推消息）；后续动作还会持续增加；发布方不应感知订阅方细节。

**落点**：
- Spring 的 `ApplicationEvent` + `@EventListener`：框架内置的观察者实现，业务里优先用它别手写。
- MQ 的发布-订阅：观察者的分布式版，一条事件扇出到多个消费组。
- GUI 事件监听、配置中心变更通知、缓存失效广播。

## 模式 Demo

```java
import java.util.*;

// 观察者接口：只关心"订单已支付"这个事件
interface OrderObserver {
    void onPaid(String orderId, int amount);
}

// 主题：订单服务，状态变化时通知全部订阅者
class OrderService {
    private final List<OrderObserver> observers = new ArrayList<>();

    void attach(OrderObserver o) { observers.add(o); }
    void detach(OrderObserver o) { observers.remove(o); }

    void pay(String orderId, int amount) {
        System.out.println("订单 " + orderId + " 支付成功: " + amount + " 元");
        for (OrderObserver o : observers) { // 只认接口，不认具体是谁
            try {
                o.onPaid(orderId, amount);
            } catch (Exception e) { // 单个订阅者失败不影响其他订阅者
                System.out.println("  某订阅者处理失败(已隔离): " + e.getMessage());
            }
        }
    }
}

// 具体观察者们：彼此独立，互不知情
class SmsObserver implements OrderObserver {
    public void onPaid(String orderId, int amount) {
        System.out.println("  [短信] 已发送支付成功通知: " + orderId);
    }
}

class PointObserver implements OrderObserver {
    public void onPaid(String orderId, int amount) {
        System.out.println("  [积分] 增加积分: " + amount / 10);
    }
}

class LogObserver implements OrderObserver {
    public void onPaid(String orderId, int amount) {
        System.out.println("  [日志] 落库: order=" + orderId + ", amount=" + amount);
    }
}

public class ObserverDemo {
    public static void main(String[] args) {
        OrderService orders = new OrderService();
        orders.attach(new SmsObserver());
        orders.attach(new PointObserver());
        orders.attach(new LogObserver()); // 加新动作只加一行 attach，支付代码零改动

        orders.pay("ORD-1001", 299);
    }
}
```

- **发布方零感知是核心收益**：pay() 里没有一行 if 判断「要不要发短信」，新增/下线通知动作全在 attach/detach 层完成，这就是与「在业务方法里顺手都调一遍」拉开差距的地方。
- **失败隔离与通知顺序要显式设计**：同步通知时单个观察者抛异常会中断整条链（Demo 里逐个 try-catch 隔离）；顺序有依赖的观察者别用观察者，改责任链或显式编排。
- **坑：内存泄漏来自忘了 detach**。长生命周期 Subject 持有短生命周期 Observer 引用，订阅者用完不取消订阅就永远被通知、也无法被 GC；框架实现（如 Spring 事件）无此问题，手写时必须成对提供取消订阅入口。
