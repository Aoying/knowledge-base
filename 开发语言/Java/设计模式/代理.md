# 代理模式

## 模式介绍

**意图**：给目标对象加一个「替身」，客户端访问替身，替身在转发前后插入控制逻辑：权限、延迟加载、缓存、日志、事务。

**结构与角色**：

- 抽象主题（Subject）：接口，真实对象和代理都实现它。
- 真实主题（RealSubject）：干活的对象。
- 代理（Proxy）：持有真实对象引用，方法 = 控制逻辑 + 转发。

实现方式：静态代理（手写一个代理类，简单但一接口一个类）；JDK 动态代理（运行时按接口生成，Spring AOP 默认）；CGLIB（生成子类，无接口时用）。

**效果**：

- 优点：横切逻辑（日志/事务/鉴权）从业务代码里彻底剥离；真实对象零改动。
- 代价：调用链变长、调试栈不直观；代理里藏重逻辑会让排查时「代码里看不到这段行为」。

**适用信号**：

- 一批方法都要在前后做同一件事（记日志、开事务、查权限、统计耗时）。
- 目标对象创建昂贵，想延迟到真正使用时再建（虚拟代理）；或目标在远程，想让本地替身屏蔽网络细节（远程代理，如 RPC 的 Stub）。

**落点**：Spring AOP 就是代理工厂——`@Transactional`、日志切面全靠它；MyBatis 的 Mapper 接口没有任何实现类，你拿到的就是 JDK 动态代理，`InvocationHandler` 里把方法翻译成 SQL 执行；Dubbo/RPC 客户端的接口存根是远程代理。

## 模式 Demo

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

// 抽象主题
interface OrderService {
    String createOrder(String sku, int num);
}

// 真实主题：纯业务，不关心日志和耗时
class OrderServiceImpl implements OrderService {
    public String createOrder(String sku, int num) {
        return "ORD-" + sku + "-" + num;
    }
}

// JDK 动态代理：一个 InvocationHandler 就能代理任意接口，这正是 MyBatis Mapper 的原理
class LogProxyHandler implements InvocationHandler {
    private final Object target;

    LogProxyHandler(Object target) { this.target = target; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        long start = System.nanoTime();
        System.out.println("[代理] 调用 " + method.getName() + " 开始");
        Object result = method.invoke(target, args); // 转发给真实对象
        long costMs = (System.nanoTime() - start) / 1_000_000;
        System.out.println("[代理] 调用 " + method.getName() + " 结束，耗时 " + costMs + "ms");
        return result;
    }
}

public class ProxyDemo {
    public static void main(String[] args) {
        OrderService real = new OrderServiceImpl();
        // 运行时生成代理对象：客户端拿到的类型还是 OrderService 接口
        OrderService proxy = (OrderService) Proxy.newProxyInstance(
                ProxyDemo.class.getClassLoader(),
                new Class<?>[]{OrderService.class},
                new LogProxyHandler(real));

        System.out.println(proxy.createOrder("SKU-9", 2));
    }
}
```

- JDK 动态代理只能代理接口（靠实现同一接口生成类）；目标没接口时用 CGLIB 生成子类，所以被代理类不能是 final、方法不能是 final。
- 与装饰器的区别：代理管「访问控制」，被代理对象常由代理自己创建/持有（如 Mapper、懒加载）；装饰器管「功能叠加」，被裹对象由外部组装传入。结构像，意图别混。
- 坑：`method.invoke` 抛出的异常被包成 `InvocationTargetException`，代理层要拆包再抛，否则上层看到的异常类型全变样。
- Spring 里自调用失效（同类方法互调不走代理、事务不生效）是代理最高频的实战坑，根因就是「绕过了替身直接摸到真身」。
