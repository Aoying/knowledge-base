# 正则表达式常用样例

样例篇，配 [正则表达式](开发语言/正则表达式.md) 主篇使用。主篇讲语法与机制，本篇只放可直接抄的模式与样例。

## 常用模式速查表

| 场景 | 模式 |
|---|---|
| 手机号（大陆） | `^1[3-9]\d{9}$` |
| 邮箱（宽松） | `^[\w.-]+@[\w-]+(\.[\w-]+)+$` |
| URL | `https?://[\w.-]+(/[\w./?%&=-]*)?` |
| IPv4 | `\b(?:\d{1,3}\.){3}\d{1,3}\b`（严格版再加 0-255 范围） |
| 身份证 18 位 | `^[1-9]\d{5}(19|20)\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])\d{3}[\dXx]$` |
| 中文 | `[\u4e00-\u9fa5]`（或 `/\p{Script=Han}/u`） |
| 密码（8+，含字母数字） | `^(?=.*[A-Za-z])(?=.*\d)[A-Za-z\d]{8,}$` |

- 校验类一律加 `^$` 锚定，不然 `138123456789` 也能"匹配出"手机号。
- 邮箱/URL 没有 100% 正确的正则，宽松版 + 实际发一封验证才是正解。

## 日常日用常用样例

以下均按整串校验写（`^…$`），提取片段时去掉锚点。正例、反例均已用 Python `re` 实测。记住一条：正则只管形状，业务合法性（号段、校验码、日期真实存在）要另做校验。

### 1. 手机号（宽松）
- 场景：表单里先拦住明显错的号，不追号段细节。
- 正则：`^1[3-9]\d{9}$`
- 说明：11 位、第 1 位 1、第 2 位 3–9；和速查表同款，够用版。
- 坑：新号段出来它照单全收，旧号段停用它也拦不住；强校验走短信验证。
- 实测：通过 13812345678、19900001111；挡住 12812345678、1381234567（10 位）。

### 2. 手机号（严格，按号段）
- 场景：想在前端就把号段写死，减少无效提交。
- 正则：`^1(?:3\d|4[5-9]|5[0-35-9]|6[2567]|7[0-8]|8\d|9[0-35-9])\d{8}$`
- 说明：第二三位按公开号段表枚举，如 149、167、191 都在内。
- 坑：号段会变，新号段一出模式就过期；不在枚举里的号段（如 144、154）也会被挡，重要业务宁用宽松版 + 短信验证。
- 实测：通过 13812345678、14912345678、16712345678；挡住 15412345678、19412345678、17912345678。

### 3. 邮箱（宽松）
- 场景：注册表单初步校验。
- 正则：`^[\w.-]+@[\w-]+(\.[\w-]+)+$`
- 说明：`@` 前允许字母数字下划线、点、连字符；域名至少一段点号后缀。
- 坑：没有 100% 正确的邮箱正则，`+` 标签地址（如 name+tag@example.com）这版通不过；真校验靠发一封验证邮件。
- 实测：通过 zhang.san@company.com；挡住 a@b、name+tag@example.com。

### 4. 身份证 18 位
- 场景：实名信息录入时的形状校验。
- 正则：`^[1-9]\d{5}(19|20)\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])\d{3}[\dXx]$`
- 说明：6 位地址码（首位非 0）+ 8 位生日（19/20 开头、月日范围已收紧）+ 3 位顺序码 + 校验码；最后一位 X 可大写可小写。
- 坑：正则只验形状不验校验码——110105194912310021 形状能通过，但校验码是错的。真校验要算 ISO 7064 MOD 11-2：前 17 位按权重 [7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2] 加权求和 mod 11，映射 [1,0,X,9,8,7,6,5,4,3,2]；如 11010519491231002 算出 X。
- 实测：通过 11010519491231002X；挡住 01010519491231002X（首位 0）、11010519491331002X（13 月）。

### 5. 日期 YYYY-MM-DD（严格月日范围）
- 场景：日期输入框的格式校验。
- 正则：`^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$`
- 说明：比 `\d{4}-\d{2}-\d{2}` 多一层月日范围，13 月、00 日直接挡掉；月份和日必须补零。
- 坑：2 月 30 日、4 月 31 日仍会通过，闰年 2 月 29 日也无法区分；日期真实存在与否交给日期库判断。
- 实测：通过 2026-10-25；挡住 2026-13-01、2026-2-5（未补零）。

### 6. URL（http/https）
- 场景：链接输入框校验。
- 正则：`^https?://[\w.-]+(?:\.[\w.-]+)+(?::\d+)?(?:[/?#]\S*)?$`
- 说明：只放行 http/https，域名至少一段点号后缀，可带端口、路径、查询、锚点。
- 坑：裸域名（www.example.com）没有 scheme 会被挡；用户信息段（user@example.com）不在此版内；中文域名在 Python 的 `\w` 下会放行、JS 下会被挡，跨语言用前按目标语言实测。
- 实测：通过 https://www.example.com/path?q=1、https://example.com:8080/api；挡住 ftp://example.com、www.example.com。

### 7. IPv4（严格 0–255）
- 场景：IP 输入框、配置校验。
- 正则：`^((25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)\.){3}(25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)$`
- 说明：每段按 250–255、200–249、100–199、0–99 四档拆分，256 从根上进不来；比速查表的 `\d{1,3}` 版严格。
- 坑：前导零会被拒（192.168.01.1 不通过），如需放行要另写；IPv6 不在此版内。
- 实测：通过 192.168.0.1、255.255.255.255；挡住 256.1.1.1、192.168.01.1。

### 8. 密码强度
- 场景：注册密码初步校验。
- 正则：`^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[A-Za-z\d!@#$%^&*]{8,20}$`
- 说明：三个环视各管一类（小写、大写、数字），总长 8–20 位，符号只放行 `!@#$%^&*`；比速查表版多要求大小写分开、有长度上限。
- 坑：字符集外的符号（如 `~`、空格）会被挡，用前先对齐产品允许的符号表；正则不管密码是否撞库，重要场景配合强度计与泄露库检查。
- 实测：通过 Aa123456、Aa123456!；挡住 aa123456（无大写）、Aa12345（7 位）。

### 9. 中文姓名
- 场景：姓名输入框校验。
- 正则：`^[\u4e00-\u9fa5]{2,4}$`
- 说明：2–4 个基本区汉字，覆盖绝大多数姓名。
- 坑：少数民族姓名中的间隔符 `·` 不在范围；生僻字超出基本区（如扩展 A 区）也会被挡；字数上限是业务约定不是法律，特殊姓名要放宽到 `[\u4e00-\u9fa5·]{2,10}` 这类写法并配人工复核。
- 实测：通过 王小明、欧阳修；挡住 王（1 字）、王·小明。

### 10. 金额/小数（非负，最多 2 位小数）
- 场景：价格、金额输入框。
- 正则：`^(0|[1-9]\d*)(\.\d{1,2})?$`
- 说明：整数部分不许前导零（0 本身除外），小数部分可有可无、最多 2 位。
- 坑：负数、千分位逗号、`.5` 这种写法都不通过，需要就另加分支；格式过了不等于算对，金额计算用 Decimal 别用 float。
- 实测：通过 0.50、123.45；挡住 007、123.456。

### 11. 车牌
- 场景：车牌号录入校验。
- 正则：传统 `^[京津沪渝冀豫云辽黑湘皖鲁新苏浙赣鄂桂甘晋蒙陕吉闽贵粤青藏川宁琼使领][A-HJ-NP-Z][A-HJ-NP-Z0-9]{5}$`；新能源 `^[京津沪渝冀豫云辽黑湘皖鲁新苏浙赣鄂桂甘晋蒙陕吉闽贵粤青藏川宁琼使领][A-HJ-NP-Z](?:[DF][A-HJ-NP-Z0-9]{5}|[A-HJ-NP-Z0-9]{5}[DF])$`
- 说明：省份简称 + 发牌机关字母 + 5 位（传统）或 D/F 开头或结尾的 6 位（新能源：小型 D/F 在前、大型 D/F 在后）；字母排除易与 1、0 混淆的 I、O。
- 坑：使领馆、港澳、挂、学、警等特殊号牌不在此版内；不要把两档合并成 `{5,6}`，那样会放行不带 D/F 的 8 位号（如京A123456）。
- 实测：通过 京A12345、京AD12345、京A12345D；挡住 京I12345（I 不用）、京A1234（6 位）。

## 搜索常见正则 demo

以下均为搜索/提取场景（整串校验类见日常日用常用样例一节），正反例均已用 Python `re` 实测。提取时一般不用 `^$` 锚定，锚定了反而找不到中间内容。

### 1. 文本中提取全部邮箱
- 场景：从一段文本里抠出所有邮箱地址。
- 正则：`[\w.-]+@[\w-]+(?:\.[\w-]+)+`
- 说明：与校验版的区别是去掉了 `^$`，配合 `findall` 全文扫；`(?:...)` 非捕获组，只分组不占编号。
- 坑：`a@b` 这种没点号后缀的不会被抠出；`+` 标签地址（如 name+tag@example.com）这版也抠不出，需要就把 `+` 加进 `@` 前的字符集。
- 实测：从“联系 zhang.san@company.com 或 li@x.io，备用 a@b”抠出 zhang.san@company.com、li@x.io。

### 2. 文本中提取全部链接
- 场景：从文本里抠出 http/https 链接。
- 正则：`https?://[\w.-]+(?:\.[\w.-]+)+(?:[/?#][^\s"'<>。；，、！？）】]*)?`
- 说明：域名至少一段点号后缀；路径、查询、锚点部分排除了空白、引号、尖括号与常见中文标点，避免把句末的句号、逗号吞进链接。
- 坑：链接末尾的英文句号、右括号仍可能被吞进（如 “…/page.”），提取后建议再 strip 掉末尾的 `.,;)]`；裸域名（无 scheme）这版不抠，需要就另加分支。
- 实测：从“见 https://example.com/a?x=1，官网 http://a.io/b。”抠出两条完整链接，句末标点未被吞入。

### 3. HTML 标签剥离与内容提取
- 场景：取标签里的纯文本，或取某标签的内容。
- 正则：剥离用 `re.sub(r'<[^>]+>', '', s)`；取 p 标签内容用 `re.findall(r'<p>(.*?)</p>', s)`。
- 说明：`[^>]+` 表示“不是右尖括号的字符”，配合 `.*?` 懒惰量词，避免 `<.*>` 一口吃掉整段。
- 坑：属性值里含 `>`、注释、script 块、嵌套同名标签都会让这版失手；取一两个简单字段可以，解析整体请用专门解析器（见主篇易错点）。
- 实测：`<p>你好<b>世界</b></p>` 剥离后为“你好世界”；`<p>你好</p><p>世界</p>` 提取出“你好”“世界”。

### 4. 去除首尾空白与压缩多余空白
- 场景：清洗用户输入、日志里的不规则空白。
- 正则：首尾用 `re.sub(r'^\s+|\s+$', '', s)`；多空白压成一个用 `re.sub(r'\s+', ' ', s).strip()`。
- 说明：`\s` 覆盖空格、制表符、换行等；Python 的 `\s` 还覆盖全角空格 `\u3000`，中文文本里的全角空白同样能清。
- 坑：只清首尾不要用 `\s+` 全文替换，会把词间正常空格也压掉；想保留换行分段就别用 `\s`，改用 `[ \t]+` 只压横向空白。
- 实测：`a  b\t c\n d` 压成“a b c d”；`\u3000 hello \u3000` 清首尾后为“hello”。

### 5. 千分位分隔
- 场景：金额展示加逗号。
- 正则：`re.sub(r'(?<=\d)(?=(\d{3})+$)', ',', int_part)`，小数部分先按 `.` 切开、只对整数部分操作。
- 说明：环视不消耗字符：`(?<=\d)` 要求前面是数字，`(?=(\d{3})+$)` 要求后面恰好是 3 的倍数个数字到结尾，两个条件同时成立的位置就是逗号落点。
- 坑：负号、小数点不能直接套整串，先 `partition('.')` 分离整数与小数部分；整数不足 4 位时无落点、原样返回，这是对的。
- 实测：1000000 → 1,000,000；1234567.89 → 1,234,567.89；999 原样。

### 6. 驼峰与下划线互转
- 场景：字段名在 userName 与 user_name 之间转换。
- 正则：驼峰转下划线用两步——先 `re.sub(r'([A-Z]+)([A-Z][a-z])', r'\1_\2', s)`，再 `re.sub(r'([a-z0-9])([A-Z])', r'\1_\2', s).lower()`；下划线转驼峰用 `re.sub(r'_([a-z])', lambda m: m.group(1).upper(), s)`。
- 说明：两步法先把连续大写里的最后一个大写让给后面的小写词（如 IDName → ID_Name），再处理小写到大写的边界。
- 坑：朴素版 `re.sub(r'(?<!^)(?=[A-Z])', '_', s)` 会把 userNameID 切成 user_name_i_d；首尾下划线、连续下划线转驼峰时要先处理，否则首字母大小写会错。
- 实测：userNameID → user_name_id；user_name → userName。

### 7. 匹配中文字符
- 场景：从混合文本里抠出中文段落。
- 正则：`[\u4e00-\u9fa5]+`
- 说明：基本区汉字范围，配合 `+` 一次抠出连续中文段；`findall` 直接给中文段列表。
- 坑：生僻字超出基本区（如扩展 A 区）会被漏掉；Python 的 `re` 不支持 `\p{Script=Han}`，要 Unicode 属性写法得用 `regex` 第三方库，JS 则写 `/\p{Script=Han}/u`（见主篇疑难杂症第 2 条）。
- 实测：从“hello世界123你好”抠出“世界”“你好”。

### 8. 十六进制颜色
- 场景：从样式文本里抠出颜色值。
- 正则：`#(?:[0-9a-fA-F]{6}|[0-9a-fA-F]{3})\b`
- 说明：6 位写在 3 位前面是关键，否则 `#ff8800` 会先匹配成 `#ff8`；末尾 `\b` 挡住位数不对的颜色。
- 坑：`#ff88`（4 位）、`#1234567`（7 位）这版都抠不出，这是符合预期的，不是漏——位数不对的颜色本就不该放行；要放行 8 位带透明通道版就再加一个 8 位分支。
- 实测：从“颜色 #ff8800 和 #FFF，还有 #ff88 与 #1234567”抠出 #ff8800、#FFF。

### 9. MAC 地址
- 场景：网卡地址格式校验。
- 正则：`^([0-9A-Fa-f]{2})([:-])(?:[0-9A-Fa-f]{2}\2){4}[0-9A-Fa-f]{2}$`
- 说明：先用第 2 组记住分隔符（冒号或连字符），后面 4 次用 `\2` 反向引用同一分隔符，保证全文分隔符一致。
- 坑：不带反向引用的简版 `^([0-9A-Fa-f]{2}[:-]){5}[0-9A-Fa-f]{2}$` 会放行混用分隔符的 `AA:BB-CC:DD:EE:FF`；大小写不敏感，AA 与 aa 都算合法。
- 实测：通过 AA:BB:CC:DD:EE:FF、AA-BB-CC-DD-EE-FF；挡住 AA:BB-CC:DD:EE:FF（混用）、AA:BB:CC:DD:EE（5 段）。

### 10. 邮编与座机
- 场景：地址表单里的邮编、座机校验。
- 正则：邮编 `^[1-9]\d{5}$`；座机 `^0\d{2,3}-\d{7,8}$`。
- 说明：邮编 6 位、首位非 0；座机区号 0 开头 3–4 位、横杠、7–8 位号码。
- 坑：400/800 电话、分机号（转 123）都不在此版内，需要就另加分支；区号位数是业务约定，写死前先对齐产品要求。
- 实测：邮编通过 100000，挡住 010000；座机通过 010-12345678，挡住 01012345678（缺横杠）。

### 11. 查找重复单词
- 场景：文本校对，揪出“的 的”“is is”这类重复。
- 正则：`\b(\w+)\s+\1\b`
- 说明：`(\w+)` 先记住一个词，`\s+` 吃掉中间空白，`\1` 要求后面出现一模一样的词；`\b` 保证词边界，不会把长词里的一截误当重复。
- 坑：带捕获组时 `findall` 只返回组内容（['is', 'test']），要整段重复词用 `finditer` 取 `group(0)`；跨标点的重复（如“word, word”）这版不匹配；忽略大小写要加 `re.IGNORECASE`。
- 实测：从“this is is a test test”找出 is、test；中文“好 好 天气”找出“好”。

### 12. 文件扩展名与版本号
- 场景：取文件名后缀、从文本里抠版本号。
- 正则：扩展名 `\.([A-Za-z0-9]+)$`；版本号（semver 风格）`\bv?(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)(?:-[0-9A-Za-z.-]+)?(?:\+[0-9A-Za-z.-]+)?\b`。
- 说明：扩展名取最后一个点号后的部分；版本号三段数字（每段不许前导零，可选 v 前缀、预发布段与构建元数据），`[1-9]\d*` 与 `0` 的分支就是用来挡前导零的。
- 坑：隐藏文件 `.gitignore` 会被扩展名版误当成后缀 gitignore，真实场景用 `os.path.splitext`；版本号只验形状不比大小，`1.10.0` 大于 `1.9.0` 不能靠字符串比较，比较要按段转整数。
- 实测：report.final.pdf → pdf；v1.2.3 → v1.2.3；2.0.0-beta.1+build.5 全段抠出；v1.02.3（前导零）无匹配。

## 日常文本搜索

以下都是“在一大段文本里找东西”的场景，不校验整串；锚点只在需要按行过滤时用。

### 1. 找含关键词的行（grep 式）
- 场景：日志、聊天记录、笔记里翻出含某个词的整行。
- 正则：`^.*关键词.*$`，配合 `re.M`（多行模式，`^$` 匹配每行首尾）。
- 说明：`.*` 吃掉关键词前后的整行内容；不加 `re.M` 时 `^$` 只认全文首尾，中间行翻不出来。
- 坑：关键词本身含正则元字符（如 `C++`、`a.b`）要先 `re.escape()`，不然 `+`、`.` 会按量词/通配走；大小写不定就加 `re.IGNORECASE`。
- 实测：从 4 行文本里找出“第二行有关键词”“关键词在行首”两行。

### 2. 找 TODO / FIXME 注释行
- 场景：代码里扫一遍待办。
- 正则：`^\s*(?:#|//)\s*(TODO|FIXME)\b.*$`（`re.M`）。
- 说明：行首可有缩进，`#` 或 `//` 开头，后跟 TODO/FIXME；`\b` 挡住 TODOX 这种前缀。
- 坑：行尾注释（如 `print(1)  # TODO`）这版抓不到，要抓行尾就去掉行首部分、改用 `.*(TODO|FIXME).*`；`/* */` 块注释也不在此版内。
- 实测：`# TODO: 修掉这里`、`// FIXME: 下周重构` 命中；行尾注释未命中（符合预期）。

### 3. 提取中文引号、书名号里的内容
- 场景：从文章、聊天记录里抠出引用、书名。
- 正则：双引号 `“([^”]+)”`；书名号 `《([^》]+)》`；直角引号 `「([^」]+)」`。
- 说明：括号对用否定字符集 `[^”]` 封口，比 `.*?` 更稳——不会跨过下一个右引号吃多。
- 坑：英文直引号 `"..."` 要另写 `"([^"]+)"`；嵌套引号（引号里还有引号）正则处理不了，见主篇易错点。
- 实测：从“他说“明天见”，又提到《红楼梦》和「三体」”抠出 明天见、红楼梦、三体。

### 4. 文本里抠多种写法的日期
- 场景：聊天记录、笔记里日期写法不统一，先全抠出来再归一化。
- 正则：`20\d{2}[-/年]\d{1,2}[-/月]\d{1,2}日?`
- 说明：年限定 20 开头（够用到 2099 年）；分隔符 `-`、`/`、`年月日` 三种都认；月日 1–2 位（补零不补零都行，搜索场景放宽）。
- 坑：这版只抠形状不验真假（2026-13-40 也能抠出），抠出来后要过日期库；年份超出 20xx（如 1998 年）要把 `20` 改成 `(19|20)`。
- 实测：从“会议在2026-10-25，备选2026/10/26，旧记录写2026年10月27日”抠出三条。

### 5. 文本里抠金额
- 场景：账单、报价文本里抠出带 ¥ 的金额。
- 正则：`¥\s?\d+(?:,\d{3})*(?:\.\d{1,2})?`
- 说明：`¥` 后可带一个空格；整数部分允许千分位逗号；小数最多 2 位。
- 坑：没 ¥ 符号的裸数字（如 1234.50）这版不抠——裸数字太多误伤（年份、编号），搜索时宁可先限定 ¥；人民币也常写“元”，要连“元”一起抠就再加分支。
- 实测：从“预算 ¥1,234.50，另有 ¥999 和 1234.50（无符号）”抠出 ¥1,234.50、¥999，裸数字未抠出。

### 6. 找 @人 与 #话题#
- 场景：社交文本、群聊记录里抠提及与话题。
- 正则：`@[\w\u4e00-\u9fa5]{1,30}`；话题 `#[^#\s]+#`。
- 说明：`@` 后允许字母数字下划线与中文，限 30 字防吃整行；话题用 `[^#\s]` 封口，遇到空格或下一个 `#` 即停。
- 坑：邮箱里的 `@` 也会被 @人版抠出（如 zhang@company.com 的 @company），要排除就要求 `@` 前不是词字符：`(?<![\w@])@[\w\u4e00-\u9fa5]{1,30}`；话题里含空格（如 #双十一 购物#）这版会在空格处断开。
- 实测：从“@王小明 明天 #开会# 别忘了 @LiLei”抠出 @王小明、@LiLei 与 #开会#。

### 7. 忽略大小写搜索并高亮原词
- 场景：编辑器式查找：不论大小写找到关键词，并把原文原样标出来。
- 正则：`re.sub(r'(?i)(error)', r'【\1】', text)`。
- 说明：`(?i)` 只管匹配时忽略大小写，`\1` 回填的是原文里的实际大小写，不会把 Error 统一改成 error。
- 坑：关键词含元字符要 `re.escape()`；替换模板里 `\1` 后面紧跟数字时会被当成 `\12` 这类组号，要写成 `\g<1>`。
- 实测：“Error: failed, error again, ERROR total” → “【Error】: failed, 【error】 again, 【ERROR】 total”。

### 8. 找连续重复的字符
- 场景：校对文本里的“哈哈哈”“！！！”“？？？”这类重复。
- 正则：`(.)\1{2,}`。
- 说明：`(.)` 记住一个字符，`\1{2,}` 要求它再出现 2 次以上，即连续 3 个起；Python 里 `.` 一个字符就是一个汉字，中文同样适用。
- 坑：`findall` 只返回组内容（哈、！、？），要整段重复串用 `finditer` 取 `group(0)`；想限定只查标点就把 `.` 换成 `[!！?？~～]` 这类字符集。
- 实测：从“哈哈哈，太好了！！！真的吗？？？”用 finditer 取 group(0) 得 哈哈哈、！！！、？？？。

## 业务组合示例

### 1. 日志行提取
- 场景：从 Nginx/应用日志里一次抠出时间、IP、方法、路径、状态码、耗时。
- 正则：`(?P<time>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) (?P<ip>(?:\d{1,3}\.){3}\d{1,3}) (?P<method>[A-Z]+) (?P<path>\S+) (?P<status>\d{3}) (?P<cost>\d+)ms`
- 说明：命名分组一次到位，后续按名字取字段；IP 这里用宽松版，严格版换 0–255 那段（见日常样例第 7 条）；状态码、耗时先按数字抠，分段统计时再转整数判断。
- 坑：日志格式一变（多字段、换顺序、耗时单位变 s）模式就得跟着改；多格式混写时先按行分流再匹配，别写一个万能模式。
- 实测：`2026-10-25 14:32:01 192.168.1.10 GET /api/orders 200 123ms` → time=2026-10-25 14:32:01、ip=192.168.1.10、method=GET、path=/api/orders、status=200、cost=123。

### 2. 版本号比较：按段转整数
- 场景：判断 `1.10.0` 是否比 `1.9.0` 新。
- 做法：先用版本号提取模式（见搜索 demo 第 12 条）抠出三段，再按段转整数成元组比较；不要直接比字符串——字符串比较时 `'1.10.0' < '1.9.0'`（第二段首位 `'1' < '9'` 就定了胜负）。
```python
import re
def parse_ver(s):
    m = re.search(r"v?(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)", s)
    return tuple(int(x) for x in m.groups())
parse_ver("v1.10.0") > parse_ver("1.9.0")  # True
```
- 坑：预发布段（`-beta.1`）与构建元数据（`+build.5`）不参与大小比较，semver 规则里预发布版小于同号正式版；真要完整比较用 `packaging.version` 这类库，别手写。
- 实测：`1.10.0 > 1.9.0` 为 True；字符串直接比较 `'1.10.0' > '1.9.0'` 为 False。

## 小技巧与冷知识

【小技巧】Python 里写正则一律用 `r"..."` 原始字符串：`r"\d+"` 里的 `\d` 原样交给正则引擎；不用 `r` 前缀时，`"\d"` 还能靠 Python 不认识 `\d` 而侥幸保留反斜杠，可一旦写到 `"\b"`（退格符）、`"\n"` 这类 Python 认识的转义，模式就悄悄变了意思。原始字符串是写正则的默认姿势，不是风格偏好。

【小技巧】校验数字类模式（手机号、身份证、邮编）用 `[0-9]` 而不用 `\d`：Python 的 `\d` 默认匹配 Unicode 十进制数字，不只是 0–9，实测 `re.match(r'^1[3-9]\d{9}$', '1381234567٣')` 能通过——尾部一个阿拉伯数字就混进来了。`[0-9]` 只认 ASCII 数字，校验场景更保险；想匹配各国数字时才用 `\d`，或者显式加 `re.ASCII`。

【小技巧】整串校验用 `re.fullmatch(模式, 串)` 代替手写 `^...$`：`fullmatch(r'1[3-9]\d{9}', s)` 和 `match(r'^1[3-9]\d{9}$', s)` 等价，但意图更直白——读代码的人一眼就知道“这是整串校验”，不用再数锚点有没有漏。原文里所有校验样例都可以这样改写，模式本身不用动。

【小技巧】循环里反复用的模式先 `re.compile` 预编译：`pat = re.compile(r'...')` 之后 `pat.findall(text)`、`pat.sub(...)` 直接用，模式只解析一次，flags 也只写一次。Python 的 `re` 内部其实有缓存，短程序不编译也感觉不到差别；但模式要在多处复用、或者要挂 `re.M | re.I` 这类组合 flags 时，显式编译让意图和性能都一次到位。

【小技巧】长模式用 `re.VERBOSE` 拆成多行加注释：`re.compile(r"""^\d{4}  # 年
- \d{2}      # 月
$""", re.VERBOSE)`，空白和 `#` 后的内容会被忽略，模式可以像普通代码一样分段写。身份证、车牌这类“一段式长模式”最适合这么写，三个月后回看不用重新逐字符反推；注意：VERBOSE 模式下想匹配真正的空格要写成 `[ ]` 或 `\ `。

【小技巧】点号 `.` 默认不匹配换行，跨行取内容要先开 `re.DOTALL`：`re.search(r'a.b', 'a\nb')` 匹配不到，加 `re.DOTALL` 才能跨过换行；或者用 `[\s\S]` 这种“空白加非空白等于一切”的写法，不依赖 flags。反过来也成立：想让 `.` 停在行尾、不跨行吃进下一行时，别加 DOTALL，这是默认行为在帮你。

【小技巧】嵌套量词是灾难性回溯的重灾区，写模式时先扫一眼有没有 `(a+)+`、`(\w+\s*)*` 这类结构：回溯型引擎遇到不匹配的长串时，组合数会指数级爆炸，一个短模式能把程序卡死。Python 3.11 起可以用原子分组 `(?>...)` 或占有量词 `*+` 把已匹配的部分锁死、不许回溯（实测 `(?>a+)b`、`a++b` 均可用）；更稳妥的是改写模式本身，比如把 `(\d+)+$` 直接写成 `\d+$`。

【小技巧】改模式之前先把正反例写成一小段回归测试再动手：原文每节的“实测”就是现成的清单——通过的、挡住的各留两三条，改完模式跑一遍，确认新需求进了、旧 case 没破。正则最常见的事故不是“写不出”，而是“修 A 放行了 B”；没有正反例兜底，调模式就是盲改。

【小技巧】大文本里提取用 `finditer` 而不是 `findall`：`findall` 会把所有匹配一次拉进内存，日志文件几百 MB 时直接吃满；`finditer` 是惰性迭代器，一条一条产出，配合 `for m in pat.finditer(text)` 可以边读边处理。只在“结果集本身就小、还要随机取下标”时用 `findall`。

【冷知识】正则表达式来自 1950 年代数学家 Stephen Kleene 提出的“正则语言”：他用代数方式描述神经网络与有限自动机能识别的语言，1968 年 Ken Thompson 把这套理论写进 QED 编辑器，`grep` 这个名字就是从 ed 编辑器的 `g/re/p`（global regular expression print）命令来的。今天写在 Python 里的 `re`，血统可以一路追到这篇论文和这个编辑器。

【冷知识】正则引擎分两大类，性能保证完全不同：Python 的 `re`、PCRE、JavaScript 都是回溯型，功能最强（反向引用、环视都能做），但坏模式会指数级回溯；RE2、Go 的 `regexp`、Rust 的 `regex` 是自动机型，编译成有限自动机后保证线性时间、绝无灾难性回溯，代价是不支持反向引用和环视。选引擎之前先问“这段模式会不会被不可信输入喂给它”，答案是会的话，自动机型才是安全选择。

【冷知识】Python 的 `\d`、`\w`、`\s` 默认都是 Unicode 语义：`\w` 能匹配中文（实测 `re.match(r'^\w$', '中')` 通过），`\s` 能匹配全角空格 `\u3000`——原文“去除首尾空白”一节正是利用了这一点。想切回纯 ASCII 语义时加 `re.ASCII` 标志，`\d` 就只认 0–9、`\w` 只认 `[a-zA-Z0-9_]`；同一个模式在 Python 和 JavaScript 里跑，`\d` 的含义都可能不一样，换语言先重测。

【冷知识】Python 3.11 给 `re` 补上了原子分组 `(?>...)` 和占有量词 `*+`、`++`、`?+`：它们的意思是“这一段一旦匹配成功就锁死，不许回溯让出来”。这在以前是 PCRE、Java 等引擎的专属能力，Python 用户遇到嵌套量词只能靠改写模式绕过去；3.11 之后，防回溯多了一个直接写在模式里的工具，不用再等重构。

【冷知识】在线调试正则要先选对 flavor 再贴模式：regex101、RegExr 这类工具默认可能是 PCRE 或 JavaScript，而 Python 的 `re` 在 `\d` 的 Unicode 语义、命名分组 `(?P<name>...)` 的写法、原子分组的支持版本上都和它们有差别。在工具里调通的模式，拿到 Python 里先跑一遍原文的正反例再用，否则“工具里是对的、代码里是错的”会反复出现。

## 面试与自测

1. 校验类模式为什么一律要加 `^$` 锚定？提取片段时又为什么要去掉锚点？
2. 身份证 18 位正则通过了，为什么还不能说校验码是对的？真校验要怎么算？
3. 速查表里的密码模式和日常样例第 8 条的密码模式有什么区别？字符集外的符号为什么会被挡？

### 参考答案

1. 校验类一律加 `^$` 锚定，不然 `138123456789` 也能「匹配出」手机号——不加锚点只是找到一段符合规则的子串，不等于整串都符合。反过来，提取片段时一般不用 `^$`，锚定了反而找不到中间内容（如文本中提取全部邮箱、全部链接的 demo 都去掉了锚点）。
2. 正则只验形状不验校验码：`110105194912310021` 形状能通过，但校验码是错的。真校验要算 ISO 7064 MOD 11-2：前 17 位按权重 `[7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]` 加权求和 mod 11，映射 `[1,0,X,9,8,7,6,5,4,3,2]`；如 `11010519491231002` 算出 `X`。
3. 速查表版是 `^(?=.*[A-Za-z])(?=.*\d)[A-Za-z\d]{8,}$`（字母数字、8 位以上）；日常样例第 8 条是 `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[A-Za-z\d!@#$%^&*]{8,20}$`——三个环视各管一类（小写、大写、数字），总长 8–20 位，符号只放行 `!@#$%^&*`。字符集外的符号（如 `~`、空格）会被挡，用前先对齐产品允许的符号表；正则也不管密码是否撞库，重要场景配合强度计与泄露库检查。
