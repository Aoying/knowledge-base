# 正则表达式

## 元字符速查

| 符号 | 含义 |
|---|---|
| `.` | 任意单个字符（除换行） |
| `\d` / `\D` | 数字 / 非数字 |
| `\w` / `\W` | 单词字符（字母数字下划线）/ 非单词字符 |
| `\s` / `\S` | 空白 / 非空白 |
| `^` / `$` | 字符串开头 / 结尾 |
| `*` `+` `?` | 0 次以上 / 1 次以上 / 0 或 1 次 |
| `{n}` `{n,}` `{n,m}` | 恰好 n 次 / 至少 n 次 / n 到 m 次 |
| `[]` `[^]` | 字符集 / 取反 |
| `|` | 或 |
| `()` | 分组（捕获） |
| `\` | 转义 |

## 分组与捕获

- `(abc)`：捕获分组，可用 `\1` 或 `$1` 反向引用
- `(?:abc)`：非捕获分组，只分组不记住，性能更好
- `(?<name>abc)`：命名分组，用 `\k<name>` 引用

## 贪婪 vs 懒惰

- 默认贪婪：`.*` 尽量多吃
- 加 `?` 变懒惰：`.*?` 尽量少吃
- 例：`<.*>` 会匹配整个 `<a>1</a>`，`<.*?>` 只匹配 `<a>`

## 常用模式

```text
邮箱：^[\w.-]+@[\w.-]+\.\w+$
手机号（大陆）：^1[3-9]\d{9}$
URL：https?://[\w.-]+(?:\.[\w.-]+)+(?:/\S*)?
IPv4：^(?:\d{1,3}\.){3}\d{1,3}$
日期 YYYY-MM-DD：^\d{4}-\d{2}-\d{2}$
```

## 三语言写法差异

| | Java | Python | JavaScript |
|---|---|---|---|
| 字面量 | `"\\d+"`（双反斜杠） | `r"\d+"`（推荐 raw string） | `/\d+/g` |
| 匹配 | `Pattern.compile().matcher()` | `re.search` / `re.match` / `re.findall` | `str.match` / `regex.test` |
| 替换 | `replaceAll` | `re.sub` | `str.replace` |

Java 里反斜杠要写两遍，是最常见的报错来源。

## 5 个常见坑

1. **贪婪匹配吃多**：想取标签内容用 `<.*?>` 而不是 `<.*>`。
2. **特殊字符没转义**：`.`、`(`、`[` 在模式里有含义，匹配字面量要写 `\.` `\(` `\[`。
3. **灾难性回溯**：`(a+)+$` 这类嵌套量词在长字符串上能卡死；能确定边界就用具体字符集。
4. **`^$` 和多行的误会**：默认 `^$` 是整个字符串的开头结尾；要按行匹配才加多行模式（`re.MULTILINE` / `(?m)`）。
5. **`\d` 不等于 `[0-9]`**：Unicode 模式下 `\d` 能匹配全角数字等；严格校验用 `[0-9]`。

## 疑难杂症

### 1. 环视断言在旧环境直接报语法错
- **现象**：`(?<=@)\w+` 在新版 Chrome/Node 正常，老浏览器或旧 Java 报 `invalid regex`。
- **原因**：后行断言 `(?<=)` / `(?<!)` 是 ES2018 才进标准的，各语言支持时间不一。
- **解决**：要兼容就别用后行断言，改用捕获组取第 1 组；或先检测环境再降级。

### 2. \p{Script=Han} 匹配中文的前提
- **现象**：`\p{Script=Han}` 写出来没效果或报错。
- **原因**：Unicode 属性转义需要 `u` 标志（JS）或对应语言的 Unicode 模式；Python 的 `re` 不支持，得用 `regex` 第三方库。
- **解决**：JS 写成 `/\p{Script=Han}/u`；Python 要么用 `regex` 库，要么退回 `[\u4e00-\u9fa5]`。

### 3. 捕获组编号错乱
- **现象**：加了个 `(?:...)` 或嵌套分组后，`$2` 取到的内容变了。
- **原因**：只有捕获组才占编号，非捕获组不占；数编号时容易把 `(?:)` 算进去。
- **解决**：复杂模式用命名分组 `(?<name>...)`，引用时按名字取，不再数数字。

## 常用模式速查表

| 场景 | 模式 |
|---|---|
| 手机号（大陆） | `^1[3-9]\d{9}$` |
| 邮箱（宽松） | `^[\w.-]+@[\w-]+(\.[\w-]+)+$` |
| URL | `https?://[\w.-]+(/[\w ./?%&=-]*)?` |
| IPv4 | `\b(?:\d{1,3}\.){3}\d{1,3}\b`（严格版再加 0-255 范围） |
| 身份证 18 位 | `^[1-9]\d{5}(19|20)\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])\d{3}[\dXx]$` |
| 中文 | `[\u4e00-\u9fa5]`（或 `/\p{Script=Han}/u`） |
| 密码（8+，含字母数字） | `^(?=.*[A-Za-z])(?=.*\d)[A-Za-z\d]{8,}$` |

- 校验类一律加 `^$` 锚定，不然 `138123456789` 也能"匹配出"手机号。
- 邮箱/URL 没有 100% 正确的正则，宽松版 + 实际发一封验证才是正解。

## 日常日用常用样例

以下均按整串校验写（`^…$`），提取片段时去掉锚点。正例、反例均已用 Python `re` 实测。记住一条：正则只管形状，业务合法性（号段、校验码、日期真实存在）要另做校验。

### 1. 手机号（宽松）
- 场景：表单里先拦住明显错的号，不追号段细节。
- 正则：`^1[3-9]\d{9}$`
- 说明：11 位、第 1 位 1、第 2 位 3–9；和速查表同款，够用版。
- 坑：新号段出来它照单全收，旧号段停用它也拦不住；强校验走短信验证。
- 实测：通过 13812345678、19900001111；挡住 12812345678、1381234567（10 位）。

### 2. 手机号（严格，按号段）
- 场景：想在前端就把号段写死，减少无效提交。
- 正则：`^1(?:3\d|4[5-9]|5[0-35-9]|6[2567]|7[0-8]|8\d|9[0-35-9])\d{8}$`
- 说明：第二三位按公开号段表枚举，如 149、167、191 都在内。
- 坑：号段会变，新号段一出模式就过期；不在枚举里的号段（如 144、154）也会被挡，重要业务宁用宽松版 + 短信验证。
- 实测：通过 13812345678、14912345678、16712345678；挡住 15412345678、19412345678、17912345678。

### 3. 邮箱（宽松）
- 场景：注册表单初步校验。
- 正则：`^[\w.-]+@[\w-]+(\.[\w-]+)+$`
- 说明：`@` 前允许字母数字下划线、点、连字符；域名至少一段点号后缀。
- 坑：没有 100% 正确的邮箱正则，`+` 标签地址（如 name+tag@example.com）这版通不过；真校验靠发一封验证邮件。
- 实测：通过 zhang.san@company.com；挡住 a@b、name+tag@example.com。

### 4. 身份证 18 位
- 场景：实名信息录入时的形状校验。
- 正则：`^[1-9]\d{5}(19|20)\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])\d{3}[\dXx]$`
- 说明：6 位地址码（首位非 0）+ 8 位生日（19/20 开头、月日范围已收紧）+ 3 位顺序码 + 校验码；最后一位 X 可大写可小写。
- 坑：正则只验形状不验校验码——110105194912310021 形状能通过，但校验码是错的。真校验要算 ISO 7064 MOD 11-2：前 17 位按权重 [7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2] 加权求和 mod 11，映射 [1,0,X,9,8,7,6,5,4,3,2]；如 11010519491231002 算出 X。
- 实测：通过 11010519491231002X；挡住 01010519491231002X（首位 0）、11010519491331002X（13 月）。

### 5. 日期 YYYY-MM-DD（严格月日范围）
- 场景：日期输入框的格式校验。
- 正则：`^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$`
- 说明：比 `\d{4}-\d{2}-\d{2}` 多一层月日范围，13 月、00 日直接挡掉；月份和日必须补零。
- 坑：2 月 30 日、4 月 31 日仍会通过，闰年 2 月 29 日也无法区分；日期真实存在与否交给日期库判断。
- 实测：通过 2026-10-25；挡住 2026-13-01、2026-2-5（未补零）。

### 6. URL（http/https）
- 场景：链接输入框校验。
- 正则：`^https?://[\w.-]+(?:\.[\w.-]+)+(?::\d+)?(?:[/?#]\S*)?$`
- 说明：只放行 http/https，域名至少一段点号后缀，可带端口、路径、查询、锚点。
- 坑：裸域名（www.example.com）没有 scheme 会被挡；用户信息段（user@example.com）不在此版内；中文域名在 Python 的 `\w` 下会放行、JS 下会被挡，跨语言用前按目标语言实测。
- 实测：通过 https://www.example.com/path?q=1、https://example.com:8080/api；挡住 ftp://example.com、www.example.com。

### 7. IPv4（严格 0–255）
- 场景：IP 输入框、配置校验。
- 正则：`^((25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)\.){3}(25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)$`
- 说明：每段按 250–255、200–249、100–199、0–99 四档拆分，256 从根上进不来；比速查表的 `\d{1,3}` 版严格。
- 坑：前导零会被拒（192.168.01.1 不通过），如需放行要另写；IPv6 不在此版内。
- 实测：通过 192.168.0.1、255.255.255.255；挡住 256.1.1.1、192.168.01.1。

### 8. 密码强度
- 场景：注册密码初步校验。
- 正则：`^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[A-Za-z\d!@#$%^&*]{8,20}$`
- 说明：三个环视各管一类（小写、大写、数字），总长 8–20 位，符号只放行 `!@#$%^&*`；比速查表版多要求大小写分开、有长度上限。
- 坑：字符集外的符号（如 `~`、空格）会被挡，用前先对齐产品允许的符号表；正则不管密码是否撞库，重要场景配合强度计与泄露库检查。
- 实测：通过 Aa123456、Aa123456!；挡住 aa123456（无大写）、Aa12345（7 位）。

### 9. 中文姓名
- 场景：姓名输入框校验。
- 正则：`^[\u4e00-\u9fa5]{2,4}$`
- 说明：2–4 个基本区汉字，覆盖绝大多数姓名。
- 坑：少数民族姓名中的间隔符 `·` 不在范围；生僻字超出基本区（如扩展 A 区）也会被挡；字数上限是业务约定不是法律，特殊姓名要放宽到 `[\u4e00-\u9fa5·]{2,10}` 这类写法并配人工复核。
- 实测：通过 王小明、欧阳修；挡住 王（1 字）、王·小明。

### 10. 金额/小数（非负，最多 2 位小数）
- 场景：价格、金额输入框。
- 正则：`^(0|[1-9]\d*)(\.\d{1,2})?$`
- 说明：整数部分不许前导零（0 本身除外），小数部分可有可无、最多 2 位。
- 坑：负数、千分位逗号、`.5` 这种写法都不通过，需要就另加分支；格式过了不等于算对，金额计算用 Decimal 别用 float。
- 实测：通过 0.50、123.45；挡住 007、123.456。

### 11. 车牌
- 场景：车牌号录入校验。
- 正则：传统 `^[京津沪渝冀豫云辽黑湘皖鲁新苏浙赣鄂桂甘晋蒙陕吉闽贵粤青藏川宁琼使领][A-HJ-NP-Z][A-HJ-NP-Z0-9]{5}$`；新能源 `^[京津沪渝冀豫云辽黑湘皖鲁新苏浙赣鄂桂甘晋蒙陕吉闽贵粤青藏川宁琼使领][A-HJ-NP-Z](?:[DF][A-HJ-NP-Z0-9]{5}|[A-HJ-NP-Z0-9]{5}[DF])$`
- 说明：省份简称 + 发牌机关字母 + 5 位（传统）或 D/F 开头或结尾的 6 位（新能源：小型 D/F 在前、大型 D/F 在后）；字母排除易与 1、0 混淆的 I、O。
- 坑：使领馆、港澳、挂、学、警等特殊号牌不在此版内；不要把两档合并成 `{5,6}`，那样会放行不带 D/F 的 8 位号（如京A123456）。
- 实测：通过 京A12345、京AD12345、京A12345D；挡住 京I12345（I 不用）、京A1234（6 位）。

## 环视断言实战

不消耗字符、只看前后文的"隐形条件"：

| 写法 | 含义 | 例子 |
|---|---|---|
| `(?=...)` | 前面是…（肯定顺序环视） | `\d+(?=元)` 匹配"100元"里的 100 |
| `(?!...)` | 前面不是… | `\d+(?!元)` 匹配不带"元"的数字 |
| `(?<=...)` | 后面是…（肯定逆序环视） | `(?<=@)\w+` 取 @ 后面的用户名 |
| `(?<!...)` | 后面不是… | `(?<!\$)\d+` 排除 $ 开头的金额 |

```python
import re
re.findall(r'\d+(?=元)', '100元和200块')      # ['100']
re.sub(r'(?<=\d),(?=\d)', '', '1,000,000')  # 去千分位逗号 -> '1000000'
```

- 逆序环视 `(?<=)` 里大多语言要求定长（如 `(?<=ab|abc)` 非法定长会报错），写之前确认。
- 密码强度校验是环视的经典场景：`^(?=.*[A-Z])(?=.*\d).{8,}$`。

## 回溯优化：从灾难性回溯说起

```python
# 灾难版：(a+)+$ 遇到 "aaaaaaaaaaaaaab" 直接卡死
# 优化1：占有量词（Java/PCRE）/ 原子组
# (?>a+)$          # 原子组：匹配了就不回吐
# 优化2：改写成等价的无嵌套形式
# a+$             # 本来就这么简单
```

- 嵌套量词 `(x+)+`、`(a|ab)*` 是重灾区，review 正则时先扫这个形状。
- 在线验证：regex101.com 有"debugger"看步数，步数爆炸就别上线。
- 日志清洗这种高频场景，宁可写两遍简单正则，也别写一遍炫技的。

## 基础知识补强

### 核心概念与术语

- **正则表达式（regex）**：用一串特殊符号描述"文本长什么样"的微型语言，用来在文本里查找、校验、切分、替换。
- **模式（pattern）**：你写的那串规则本身，如手机号规则就是一段模式；被检查的文本叫目标串。
- **匹配（match）**：模式在目标串里找到符合规则的一段，就算匹配成功；成功不等于整串都符合，要看是否用了锚点。
- **字面量字符**：普通字母数字在模式里就表示它本身，`abc` 匹配的只有连续的 abc 三个字符。
- **转义**：元字符想当普通字符用就加反斜杠，如 `\.` 只匹配小数点本身；反过来，普通字母加反斜杠常变成字符类（如 `\d`）。
- **字符类**：表示"这一位可以是这些字符之一"，有速记式（`\d \w \s`）和方括号自选式两大类。
- **量词**：紧跟在某个元素后面，表示它能重复几次；量词只作用于紧挨着它前面的那一个元素（或一组）。
- **锚点**：不匹配任何字符，只限定位置，如开头、结尾、单词边界；是"隐形条件"。
- **单词边界 \b**：单词字符（`\w`）与非单词字符交界处就是边界，`"cat"` 里的开头与结尾处各有一个。
- **分组**：用小括号把几个元素绑成一个整体，量词、或运算就能作用于整组。
- **或运算的优先级最低**：`ab|cd` 是"ab 或 cd"，不是"a 后跟 b 或 d"；拿不准就加括号圈范围。
- **标志（flags）**：写在模式外的开关，改引擎行为：`i` 忽略大小写、`g` 全局找全部、`m` 多行、`s` 让点号能匹配换行、`u` Unicode 模式（具体支持以官方文档为准）。
- **引擎心智模型**：主流引擎按"从左到右、逐位尝试、失败就回退重试"的方式工作，所以模式写法的顺序与具体程度会影响速度与结果。

### 基础语法与用法

```python
import re

text = "订单 2026 号, 金额 88 元, 电话 13812345678"

# 三个最常用的动作：找、校验、全找
print(re.search(r"\d+", text).group())      # 找到第一处数字 -> '2026'
print(re.fullmatch(r"\d{11}", "13812345678"))  # 整串校验 -> 匹配对象（不是 None 即通过）
print(re.findall(r"\d+", text))              # 全部找出 -> ['2026', '88', '13812345678']

# match 只从开头试，search 从任意位置试：新手最常混的一对
print(re.match(r"\d+", "abc123"))    # None：开头不是数字
print(re.search(r"\d+", "abc123").group())   # '123'
```

```python
# 字符类方括号：自选范围、取反、连字符位置
print(re.findall(r"[aeiou]", "regex"))        # ['e', 'e'] 元音
print(re.findall(r"[^0-9]+", "a1b22c"))       # ['a', 'b', 'c'] 非数字段
print(re.findall(r"[a-z0-9_]+", "Hi_2026"))    # 小写字母数字下划线段
# 注意：方括号里 . * + 等元字符大多失去特殊含义，不用再转义
# 连字符想表示字面量就放最后，如 [a-z-]；放中间表示范围
```

```python
# 单词边界：避免把长单词里的一截误匹配出来
print(re.findall(r"\bcat\b", "cat scatter cat"))  # ['cat', 'cat']
print(re.findall(r"cat", "cat scatter cat"))       # 3 处，scatter 里的也算

# 分组加量词：重复的是整组
print(re.fullmatch(r"(ab)+", "ababab"))   # 通过：ab 重复 3 次
print(re.fullmatch(r"ab+", "ababab"))      # 不通过：+ 只管前面的 b

# 或运算写具体分支，别写万能点号
print(re.findall(r"猫|狗|鸟", "我家有猫和狗"))   # ['猫', '狗']
```

```javascript
// JS 侧基础动作对照：test 只问真假，match 取内容
const tel = /^1[3-9]\d{9}$/;
console.log(tel.test('13812345678'));   // true

const s = 'a1 b22 c333';
console.log(s.match(/\d+/));            // 只拿第一处（无 g 标志）
console.log(s.match(/\d+/g));           // ['1', '22', '333'] 拿全部

// 标志写在结尾的斜杠外
console.log(/HELLO/i.test('hello'));    // i: 忽略大小写 -> true
console.log('第一行\n第二行'.match(/^第.行/gm));  // m: ^$ 按行算
```

```python
# 替换与切分：sub 的第一个参数是模式，第二个是替换文本
print(re.sub(r"\s+", " ", "a  b\tc"))        # 多空白压成一个 -> 'a b c'
print(re.sub(r"\d", "*", "a1b2"))            # 数字打码 -> 'a*b*'
print(re.split(r"[,;，；]", "a,b；c"))        # 按多种分隔符切 -> ['a', 'b', 'c']

# 捕获组在替换里的引用：Python 用 \1，分组顺序按左括号出现次序数
print(re.sub(r"(\d{4})-(\d{2})-(\d{2})", r"\2/\3/\1", "2026-10-22"))  # '10/22/2026'
```

```text
读一段模式的拆解练习（从左到右逐段念）：
^1[3-9]\d{9}$
^          锚定：从字符串开头
1          第 1 位必须是数字 1
[3-9]      第 2 位是 3 到 9 任一数字
\d{9}      后面恰好 9 位数字
$          锚定：到字符串结尾为止
合起来：11 位、第 1 位 1、第 2 位 3-9、总长不多不少——这就是手机号校验。
```

### 关键机制速览

- **先写需求再写模式**：固定四步——目标串长什么样、要整串还是找一段、有没有必须排除的情况、拿 3 个正例 2 个反例自测。
- **最左最长倾向**：引擎从最左边的位置开始尝试，该位置能匹配多长就先吃多长（懒惰量词除外），所以结果常是"第一处且尽量长"。
- **量词的作用范围**：量词只绑定它前面的单个元素；想重复多个字符必须先用括号分组，这也是分组最朴素的用途。
- **字符类减法做不到**：想表达"除了某几个的其他数字"这类需求，方括号只能对字符取反（如 `[^5]`），其余靠分支或环视（原文已述）。
- **点号的边界**：默认 `.` 不匹配换行符，跨行文本要用 `s` 标志或显式写 `[\s\S]`（空白与非空白的并集等于任意字符）。
- **空匹配陷阱**：模式能匹配空串时（如 `a*` 对 "bbb"），全局查找会在每个位置都报一处空匹配，结果一堆空字符串，先想清楚是否允许零次。
- **锚点与多行**：没有 `m` 标志时 `^` 只认整串开头；按日志逐行筛必须开多行模式，否则只有第一行能中。
- **预编译**：同一模式反复用时先编译再复用（Python 的 `re.compile`、Java 的 `Pattern`），既可读错又少重复解析（各语言细节以官方文档为准）。
- **校验与提取写法不同**：校验整串必须加 `^...$` 或用整串匹配函数；提取片段反而不加锚点，加了反而找不到中间内容。
- **调试手法**：写不对时把模式拆小逐段验证，先固定字面量部分跑通，再逐个换上字符类和量词，比盯着整串猜快得多。

### 新手易错点

- **拿正则解析 HTML/JSON**：嵌套结构不是正则能完整描述的，取一两个简单字段可以，解析整体请用专门解析器。
- **在模式里写空格求好看**：多数引擎默认空格是字面空格，会悄悄匹配失败；想分组排版就用注释模式（具体开关以官方文档为准）或老实写紧凑。
- **忘记原始字符串**：在代码里直接写 `"\d"` 时，字符串层先吃掉一层反斜杠，常变成别的意思；各语言有各自的免转义写法（原文对照表已给）。
- **量词叠在量词后面**：`a**` 不是"更贪"，多数引擎直接报语法错；`a*?` 才是懒惰量词，别混。
- **范围写反**：`[z-a]` 这类起止颠倒的范围会报错或无结果，写范围时起小终大。
- **方括号里乱放 `^`**：`^` 只在方括号第一个位置才是取反，写到中间就是普通的脱字符本身。
- **用 \w 校验中文名等场景**：`\w` 默认含字母数字下划线（及部分 Unicode 字母），它不是"英文字母"的同义词，严格场景写明确的方括号范围。
- **日期只验形状不验合法性**：`\d{4}-\d{2}-\d{2}` 会放行 2026-13-40，正则管形状，月份天数合不合法交给日期库判断。
- **手机号邮箱抄宽松版当严格校验**：速查表里的模式多为"够用版"，注册、支付等强校验场景要走业务校验或发送验证，不能只靠一段模式。
- **对用户输入直接拼模式**：把外部输入原样拼进模式，括号、星号会改变语义甚至触发回溯；拼前先做字面量转义处理。
