# 微调入门 LoRA

> 微调改的是模型的**行为**，不是往里灌知识。本篇讲方法论与可行边界：全量微调与 LoRA/QLoRA 的区别、显存账怎么算、数据怎么备、怎么评估。涉及本机（12GB 独显 + 48GB 内存）的可行性判断全部是**按显存账推算的估算，标「待验证」**，本机未真正训练过任何模型，不虚构训练结果与效果数字。

## 1. 先判断：该不该微调

三种手段先分工，别一上来就训：

| 需求 | 手段 | 原因 |
|---|---|---|
| 模型不知道某个事实/资料 | RAG（见 [RAG-评测与分块策略](AI与大模型/RAG/RAG-评测与分块策略.md)） | 知识要可更新、可溯源；灌进权重里改不动也查不着 |
| 临时约束输出格式与风格 | 提示词 + [结构化输出与JSON约束](AI与大模型/结构化输出与JSON约束.md) | 零成本先试，多数「不听话」其实是提示没写清 |
| 行为要长期固化：固定口吻、固定判断风格、特定任务模式反复用提示也调不稳 | 微调 | 把行为练进参数，省提示长度、稳复现 |

小说引擎的例子：矛盾检测的判断口径若长期固定、且评测证明提示方案到了上限，才轮到考虑微调；世界状态、剧情事实这类知识永远走 RAG 与状态库，不进权重。

## 2. 全量微调 vs LoRA / QLoRA

- **全量微调**：更新全部参数。显存账的大头不是权重本身，而是训练状态：梯度一份、优化器状态（Adam 类优化器要为每个参数存两份动量）一份，加起来是参数量的数倍（混合精度下常见估算是每参数十几字节量级）。结论：全量微调的显存门槛远高于同尺寸模型推理，消费级单卡只适合很小的模型。
- **LoRA**：冻结基座权重，只在选定的线性层旁挂一对低秩矩阵（秩 r 是核心超参，r 越大可训容量越大、显存与产物也越大），只训这部分增量。可训参数通常只占总量很小的比例，梯度与优化器状态随之骤降；产物是体积很小的适配器（adapter），可单独保存、按需挂载、多个适配器共用同一基座。
- **QLoRA**：基座先量化到 4bit 冻结，再挂 LoRA 训练。基座那笔账按 4bit 算，显存门槛再降一档，代价是基座精度已先损一层，且训练速度受量化/反量计算开销影响。
- 取舍一句话：本机这类消费级硬件谈微调，默认就是 QLoRA 路线；LoRA（基座不量化）适合更小模型或显存更宽裕时；全量微调不在本机讨论范围内（第 3 节算账）。

## 3. 显存估算方法（按 12GB 显存 + 48GB 内存推算）

训练显存账 = **基座权重 + 可训参数的梯度与优化器状态 + 激活值**。逐项估：

1. **基座**：QLoRA 按 4bit 算，约 参数量(B) × 0.5 字节再加量化元数据开销；7~8B 级约 4~5GB 量级。LoRA 不量化则按 FP16 约 2 字节/参数，8B 级即约 16GB——未进训练已超 12GB，这就是小模型在本机也优先 QLoRA 的原因。
2. **梯度与优化器**：只跟可训参数走。LoRA 可训量小，这笔通常不是瓶颈；全量微调则按第 2 节的倍数关系直接爆掉，这也是「全量不在本机范围内」的算账依据。
3. **激活值**：随 batch × 序列长度涨，是训练时最容易低估的一笔。用小 batch、短序列起步，配合梯度检查点（gradient checkpointing，用重算换显存）与梯度累积（多步攒一个大 batch）是常规组合拳。

据此划本机可行边界（**估算，待验证**）：

- 7~8B 级 QLoRA、短序列、小 batch：账面可装进 12GB，是本机微调的起步档。
- 14B 级 QLoRA：基座约 7~8GB 量级，留给激活与优化器的余量很紧，需短序列 + 梯度检查点 + 可能的 CPU offload，慢且易爆显存——只建议在 8B 级跑通全流程后再尝试。
- 30B 级及以上：基座本身已超显存账（见 [本地部署与Ollama](AI与大模型/本地部署与Ollama.md) 的推理账），微调不列入本机计划。

内存（48GB）的角色：数据预处理、offload 缓冲与系统余量，别把内存当显存平替——走内存的部分速度代价显著（推理篇同理）。

## 4. 数据准备

- **格式**：指令微调常用「指令/输入/输出」三段式，或直接套基座的对话模板（chat template）拼成多轮文本。模板必须与基座一致，模板错位训出来的行为会整体跑偏——与 [推理框架对比](AI与大模型/推理框架对比.md) 里「模板错位是输出变怪头号原因」是同一件事。
- **质量优先于数量**：通用经验是少量高质量、口径一致的样本胜过海量噪声样本。样本的输出部分就是你希望模型学会的样子，口径自相矛盾的样本训进去就是矛盾的行为。
- **来源与合规**：只用自有或许可清晰的数据；含隐私与受版权保护的文本不进训练集（本仓库公开原则同样适用：个人数据一律不入库、不入训练集）。
- **切分**：留出验证集（从训练样本中划一部分不参与训练），且验收最终要回到独立评测集（第 6 节），验证集与评测集别混用（泄漏问题见 [模型评测方法](AI与大模型/模型评测方法.md) 第 7 节）。

## 5. 工具链与最小可跑链路

- **LLaMA-Factory**：覆盖数据处理、LoRA/QLoRA/全量等多种训练方式的框架，带 WebUI 与配置化流程，常被用作入门入口。
- **Axolotl**：以 YAML 配置驱动的训练框架，配置即实验记录，适合脚本化与复现。
- 两者版本与参数变化快，命令与参数名以各自官方文档为准。产物回流路径：适配器可与基座合并成完整权重，或保持 adapter 形式挂载；要回到本地推理生态，需导出/转换为 GGUF 后按 [推理框架对比](AI与大模型/推理框架对比.md) 的分工加载（Ollama 对 adapter 的支持方式以官方文档为准）。

- **最小可跑骨架（LLaMA-Factory，命令与参数名以官方文档为准）**：

  ```yaml
  model_name_or_path: <基座，如 Qwen2.5-7B-Instruct>
  dataset: <数据集名，需在 dataset_info.json 注册>
  template: <与基座一致的对话模板>
  finetuning_type: lora
  lora_rank: 8
  quantization_bit: 4          # QLoRA：基座 4bit 冻结
  per_device_train_batch_size: 1
  gradient_accumulation_steps: 8
  gradient_checkpointing: true
  learning_rate: 0.0002
  num_train_epochs: 2
  output_dir: <适配器输出目录>
  ```

  命令：`llamafactory-cli train <配置文件.yaml>`。先小数据、小 r、短序列跑通一次全流程，再放大规模（第 7 节）。
- **数据集格式**：指令微调常用 Alpaca 式三段式 JSON：`{"instruction": "任务指令", "input": "可选输入，可为空", "output": "期望输出"}`；多轮对话用 messages 格式（role/content 列表）并配对话模板。LLaMA-Factory 侧需在 `dataset_info.json` 里注册数据集名与文件路径，否则训不到数据。
- **QLoRA 在 12GB 下的结论（估算，待验证，与第 3 节账一致）**：7B 级 QLoRA + 短序列 + 小 batch + 梯度检查点，账面可装进 12GB，是本机唯一建议的起步档；14B 级基座约 7~8GB，留给激活与优化器的余量很紧，需 CPU offload 且慢，只建议 8B 级跑通后再试；不要在 12GB 上同时开大 batch 与长序列。
- **导出 GGUF 闭环**：适配器与基座合并成完整权重（或按加载方支持保持 adapter 挂载）→ llama.cpp 的 `convert_hf_to_gguf.py` 转 GGUF → 按需量化（如 Q4_K_M）→ llama-server/Ollama 加载实测 → 回到第 6 节评测集做前后对比，分数没涨就回滚适配器。

## 6. 合并、rsLoRA 与 DoRA：标准 LoRA 之后的两条线

第 2 节只讲了标准 LoRA。练完适配器之后有三个实际问题：上线时合并不合并、r 开大后为什么效果不涨反跌、以及 LoRA 与全量微调之间有没有中间路线。

### 6.1 适配器合并：W = W₀ + (α/r)·BA

- **合并是一次性算术**：训练结束把 ΔW = (α/r)·BA 加回基座权重，得到一个完整模型文件，推理时与原基座完全一样，零额外延迟（第 2 节已提过这一点）。合并前先在评测集上验适配器本身，合并是不可逆操作——合完再想换回另一个适配器，得重新从基座出发。
- **上线前先定形态**：单任务常驻、长期只用一个行为 → 合并后部署最省事；多任务共用一基座、按需切换口吻或判断口径 → 保持 adapter 形式挂载，别合并（第 5 节导出 GGUF 闭环里两种形态都已提到，选型依据就是这里）。
- **多适配器合并不是效果相加**：两个适配器按权重加权合并成一个后，行为不等于两个适配器效果的简单相加，合并前必须在评测集上验（小技巧节已有提醒，此处是它对应的正文依据）。

### 6.2 可训参数量：一张算得出来的对照表

单矩阵 LoRA 参数量 = r × (输入维 + 输出维)。以 Qwen2.5-7B-Instruct 为例（隐藏层 3584、28 层、中间层 18944，GQA 结构下 k/v 投影输出维为 512），本地 Python 复算（2026-11-03）：

| r | 只挂 q、v | 挂全部线性层 |
|---|---|---|
| 8 | 约 252 万（占 7.6B 的 0.033%） | 约 2019 万（0.27%） |
| 16 | 约 505 万（0.066%） | 约 4037 万（0.53%） |
| 64 | 约 2019 万（0.27%） | 约 1.61 亿（2.1%） |

读法：r 翻倍，可训参数量翻倍；从“只挂 q、v”扩到“全部线性层”，参数量约涨 8 倍。显存吃紧时先只挂注意力层、r 取小（第 2 节与小技巧节的建议），这张表是它背后的算账依据。注意“可训参数占比小”不等于“训练显存小”——基座权重与激活值那两笔账仍在第 3 节里，别只盯着这一张表。

### 6.3 rsLoRA：r 开大后梯度坍缩的修正

- **问题**：标准缩放 α/r 里，r 越大缩放因子越小；Kalajdzievski（2023，arXiv:2312.03732）证明，r 增大时梯度量级会坍缩，高 r 适配器学得比低 r 还慢，等于白开了大 r。
- **修正**：把缩放因子改成 α/√r，即 rsLoRA（rank-stabilized LoRA）。α=16 时：r=8，标准 2.0、rsLoRA 5.66；r=64，标准 0.25、rsLoRA 2.0——r 越大，两者差距越大（本地 Python 复算，2026-11-03）。
- **落地口径**：r ≤ 16 时两者差异不大，沿用标准缩放即可；r ≥ 32 再考虑 rsLoRA。PEFT 的 `LoraConfig` 提供 `use_rslora` 开关，改一行配置即可切换，不用自己改缩放公式。本机实验若未来开大 r，先开这个开关再谈 r 的效果。

### 6.4 DoRA：把权重拆成幅度与方向

- **做法**：DoRA（Liu 等，2024，arXiv:2402.09353，ICML 2024 Oral）把预训练权重分解为幅度（magnitude，一个每列一个标量的向量）与方向（direction）两部分，LoRA 只更新方向，幅度向量单独可训。
- **动机**：论文的分解分析发现，全量微调会同时改变幅度与方向，而标准 LoRA 主要只改方向；把幅度单独拿出来训，是为了让学习行为更接近全量微调，缩小两者效果差距。
- **代价**：额外可训参数只有幅度向量，约比 LoRA 多 0.01% 量级；训练时每步多一次归一化计算，推理时同样可合并回单矩阵，零额外延迟。
- **选型小结**：默认标准 LoRA；r 要开大（≥32）先试 rsLoRA；想追全量微调效果、能接受训练稍慢再试 DoRA。三者都能合并，选型只影响训练过程，不锁定部署形态。

> 来源与核验日期：rsLoRA（Kalajdzievski，arXiv:2312.03732）、DoRA（Liu 等，arXiv:2402.09353，ICML 2024 Oral）、参数量对照表本地 Python 复算，2026-11-03 核验。

## 7. 过拟合与评估

- **过拟合长相**：训练 loss 一路降，但验证集表现先升后降；模型开始复读训练样本的措辞、只会处理与训练样本高度相似的输入。防法：控制轮数（epoch）、盯验证集曲线、用小学习率与适中 r 起步——具体数值靠实验，不写死。
- **灾难性遗忘**：练会新行为的同时把通用能力练丢。微调前后都要在原任务上回归，不只看新任务。
- **唯一可信的验收**：拿 [模型评测方法](AI与大模型/模型评测方法.md) 的评测集做微调前/后同集对比（类别指标 + 成本列），分数没涨就回滚适配器——LoRA 产物小、基座没动，回滚成本几乎为零，这是它对个人实验友好的另一面。本机尚无任何一次微调的前后对比数据，此节全部为流程设计，**待验证**。

## 8. 常见误区

- **想用微调给模型灌新知识**：灌进去的知识不可更新、不可溯源、还可能与真实事实混杂；知识问题用 RAG，行为问题才用微调（第 1 节）。
- **数据越多越好**：口径不一致的大数据只会把行为训得更混乱（第 4 节）。
- **只看训练 loss 报喜**：loss 是拟合训练集的程度，不是任务效果；没有评测集前后对比的微调等于没验收。
- **一上来就冲大模型、大 r、长序列**：显存账先算（第 3 节），从小档跑通全流程再放大，是本机实验的唯一稳妥顺序。

## 小技巧与冷知识

【冷知识】LoRA 出自微软 2021 年的论文《LoRA: Low-Rank Adaptation of Large Language Models》（Hu 等人，arXiv:2106.09685），核心论据是微调时权重更新的内在秩很低，小秩矩阵就能装下大部分任务变化。论文在 GPT-3 175B 上把可训参数压到全量微调的约万分之一、显存需求降到约三分之一，效果仍能打平全量微调；合并回基座后推理零额外延迟，这也是它成为默认方案的原因。

【冷知识】LoRA 的 B 矩阵初始化为零、A 矩阵随机高斯初始化，所以训练开始时 ΔW = BA 恰好是零，挂上适配器的模型行为与基座完全一致。反过来这也是个调试手段：先挂一个没训过的空适配器跑一遍推理，输出应与基座分毫不差；如果变了，问题不在训练，在挂载方式或对话模板。

【小技巧】α 不用单独调，跟 r 走就行：原论文把 ΔW 的缩放定为 α/r，并建议把 α 直接设为第一次尝试的 r 值，之后只调 r。r 翻倍时 α 跟着翻倍，更新幅度保持稳定，省掉一个超参的搜索维度；社区常见默认则是 r=8 配 α=16（即 α=2r），LLaMA-Factory 的默认配置就是这个路数，两种取法都不用把 α 当独立超参去搜。

【冷知识】QLoRA 出自 Dettmers 等人 2023 年的论文《QLoRA: Efficient Finetuning of Quantized LLMs》（arXiv:2305.14314），三件套是 4-bit NormalFloat（NF4）、双重量化、分页优化器。它把 65B 模型的微调从 780GB 以上的显存需求压到单张 48GB 显卡上，Guanaco 系列单卡训 24 小时就在 Vicuna 基准上达到 ChatGPT 约 99.3% 的水平；原文只讲了“基座 4bit 冻结”，这三项技术才是 QLoRA 能落地的具体原因。

【小技巧】LoRA 的学习率别照搬全量微调的数值：全量微调常用 1e-5 到 2e-5，LoRA 因为只训极少数参数，常见做法是用 1e-4 到 2e-4，高出一个量级。原文示例的学习率 2e-4 就是这个区间；把全量的小学习率直接套过来，几轮下来 loss 几乎不动，容易误判为数据或 r 的问题。

【小技巧】训练前先按输入去重查一遍口径冲突：同一条输入在训练集里出现两次、输出口径却不一样，模型学到的是两种行为的平均，训完在同类输入上会随机摇摆。原文第 4 节只说“口径自相矛盾的样本训进去就是矛盾的行为”，落地时先跑一次按输入分组的去重检查，把冲突样本统一口径再开训，比训完再排障便宜得多。

【冷知识】原论文实验里 LoRA 主要只挂在注意力层的 Wq、Wv 两个矩阵上，就达到了接近全量微调的效果；后来实践中常把所有线性层都挂上，效果更好但可训参数也更多。理解这一点就明白，r 相同的情况下“挂哪些层”本身也是一个超参：显存吃紧时先只挂注意力层，跑通了再考虑全层挂载。

【小技巧】多个适配器可以叠加或切换着用，不必每个任务训一个完整模型：风格适配器管口吻、任务适配器管判断口径，同一基座上按需挂载，PEFT 这类库支持运行时切换。原文只提了“多个适配器共用同一基座”，更进一步的做法是把两个适配器按权重合并成一个（加权相加），上线只挂一个，推理时不用反复切换；合并前先在评测集上验一下，合并后的行为不等于两个适配器效果的简单相加。

## 面试与自测

3. 本机 12GB 显存上微调的起步档是什么？14B 级为什么只建议在 8B 级跑通后再尝试？

4. 适配器合并后还能切换回其他适配器吗？r 开到 64 时，为什么标准 LoRA 的效果可能不涨反跌，该用什么修正？

### 参考答案

1. 微调改的是模型的行为，不是往里灌知识：灌进权重的知识改不动也查不着。模型不知道的事实或资料应该走 RAG，因为知识要可更新、可溯源；只有行为要长期固化（固定口吻、固定判断风格、特定任务模式反复用提示也调不稳）时，才轮到微调。
2. 全量微调的显存大头不是权重本身，而是训练状态：梯度一份、Adam 类优化器要为每个参数存两份动量，加起来是参数量的数倍。LoRA 冻结基座权重，只在选定的线性层旁挂一对低秩矩阵（秩 r 越大可训容量越大、显存与产物也越大），梯度与优化器状态只跟可训参数走，因而骤降；产物是体积很小的适配器，可单独保存、按需挂载，多个适配器可共用同一基座。
3. 起步档是 7~8B 级 QLoRA、短序列、小 batch，配合梯度检查点，账面可装进 12GB。14B 级 QLoRA 的基座约 7~8GB 量级，留给激活与优化器的余量很紧，需短序列 + 梯度检查点 + 可能的 CPU offload，慢且易爆显存；30B 级及以上基座本身已超显存账，不列入本机计划。以上边界均为原文按显存账推算的估算，标“待验证”。

4. 不能。合并是把 ΔW = (α/r)·BA 一次性加回基座权重，合完就是一个完整模型文件，想换适配器得重新从基座出发；多任务共用一基座、按需切换时应保持 adapter 形式挂载，别合并。r 开大后标准缩放 α/r 越来越小，Kalajdzievski（2023，arXiv:2312.03732）证明这会让梯度量级坍缩，高 r 适配器学得比低 r 还慢；修正是用 rsLoRA，把缩放因子改成 α/√r（α=16、r=64 时标准缩放 0.25、rsLoRA 2.0），r ≥ 32 再考虑，PEFT 的 LoraConfig 有 use_rslora 开关。
