# 微调入门 LoRA

> 微调改的是模型的**行为**，不是往里灌知识。本篇讲方法论与可行边界：全量微调与 LoRA/QLoRA 的区别、显存账怎么算、数据怎么备、怎么评估。涉及本机（12GB 独显 + 48GB 内存）的可行性判断全部是**按显存账推算的估算，标「待验证」**，本机未真正训练过任何模型，不虚构训练结果与效果数字。

## 1. 先判断：该不该微调

三种手段先分工，别一上来就训：

| 需求 | 手段 | 原因 |
|---|---|---|
| 模型不知道某个事实/资料 | RAG（见 [RAG-评测与分块策略](AI与大模型/RAG/RAG-评测与分块策略.md)） | 知识要可更新、可溯源；灌进权重里改不动也查不着 |
| 临时约束输出格式与风格 | 提示词 + [结构化输出与JSON约束](AI与大模型/结构化输出与JSON约束.md) | 零成本先试，多数「不听话」其实是提示没写清 |
| 行为要长期固化：固定口吻、固定判断风格、特定任务模式反复用提示也调不稳 | 微调 | 把行为练进参数，省提示长度、稳复现 |

小说引擎的例子：矛盾检测的判断口径若长期固定、且评测证明提示方案到了上限，才轮到考虑微调；世界状态、剧情事实这类知识永远走 RAG 与状态库，不进权重。

## 2. 全量微调 vs LoRA / QLoRA

- **全量微调**：更新全部参数。显存账的大头不是权重本身，而是训练状态：梯度一份、优化器状态（Adam 类优化器要为每个参数存两份动量）一份，加起来是参数量的数倍（混合精度下常见估算是每参数十几字节量级）。结论：全量微调的显存门槛远高于同尺寸模型推理，消费级单卡只适合很小的模型。
- **LoRA**：冻结基座权重，只在选定的线性层旁挂一对低秩矩阵（秩 r 是核心超参，r 越大可训容量越大、显存与产物也越大），只训这部分增量。可训参数通常只占总量很小的比例，梯度与优化器状态随之骤降；产物是体积很小的适配器（adapter），可单独保存、按需挂载、多个适配器共用同一基座。
- **QLoRA**：基座先量化到 4bit 冻结，再挂 LoRA 训练。基座那笔账按 4bit 算，显存门槛再降一档，代价是基座精度已先损一层，且训练速度受量化/反量计算开销影响。
- 取舍一句话：本机这类消费级硬件谈微调，默认就是 QLoRA 路线；LoRA（基座不量化）适合更小模型或显存更宽裕时；全量微调不在本机讨论范围内（第 3 节算账）。

## 3. 显存估算方法（按 12GB 显存 + 48GB 内存推算）

训练显存账 = **基座权重 + 可训参数的梯度与优化器状态 + 激活值**。逐项估：

1. **基座**：QLoRA 按 4bit 算，约 参数量(B) × 0.5 字节再加量化元数据开销；7~8B 级约 4~5GB 量级。LoRA 不量化则按 FP16 约 2 字节/参数，8B 级即约 16GB——未进训练已超 12GB，这就是小模型在本机也优先 QLoRA 的原因。
2. **梯度与优化器**：只跟可训参数走。LoRA 可训量小，这笔通常不是瓶颈；全量微调则按第 2 节的倍数关系直接爆掉，这也是「全量不在本机范围内」的算账依据。
3. **激活值**：随 batch × 序列长度涨，是训练时最容易低估的一笔。用小 batch、短序列起步，配合梯度检查点（gradient checkpointing，用重算换显存）与梯度累积（多步攒一个大 batch）是常规组合拳。

据此划本机可行边界（**估算，待验证**）：

- 7~8B 级 QLoRA、短序列、小 batch：账面可装进 12GB，是本机微调的起步档。
- 14B 级 QLoRA：基座约 7~8GB 量级，留给激活与优化器的余量很紧，需短序列 + 梯度检查点 + 可能的 CPU offload，慢且易爆显存——只建议在 8B 级跑通全流程后再尝试。
- 30B 级及以上：基座本身已超显存账（见 [本地部署与Ollama](AI与大模型/本地部署与Ollama.md) 的推理账），微调不列入本机计划。

内存（48GB）的角色：数据预处理、offload 缓冲与系统余量，别把内存当显存平替——走内存的部分速度代价显著（推理篇同理）。

## 4. 数据准备

- **格式**：指令微调常用「指令/输入/输出」三段式，或直接套基座的对话模板（chat template）拼成多轮文本。模板必须与基座一致，模板错位训出来的行为会整体跑偏——与 [推理框架对比](AI与大模型/推理框架对比.md) 里「模板错位是输出变怪头号原因」是同一件事。
- **质量优先于数量**：通用经验是少量高质量、口径一致的样本胜过海量噪声样本。样本的输出部分就是你希望模型学会的样子，口径自相矛盾的样本训进去就是矛盾的行为。
- **来源与合规**：只用自有或许可清晰的数据；含隐私与受版权保护的文本不进训练集（本仓库公开原则同样适用：个人数据一律不入库、不入训练集）。
- **切分**：留出验证集（从训练样本中划一部分不参与训练），且验收最终要回到独立评测集（第 6 节），验证集与评测集别混用（泄漏问题见 [模型评测方法](AI与大模型/模型评测方法.md) 第 7 节）。

## 5. 工具链与最小可跑链路

- **LLaMA-Factory**：覆盖数据处理、LoRA/QLoRA/全量等多种训练方式的框架，带 WebUI 与配置化流程，常被用作入门入口。
- **Axolotl**：以 YAML 配置驱动的训练框架，配置即实验记录，适合脚本化与复现。
- 两者版本与参数变化快，命令与参数名以各自官方文档为准。产物回流路径：适配器可与基座合并成完整权重，或保持 adapter 形式挂载；要回到本地推理生态，需导出/转换为 GGUF 后按 [推理框架对比](AI与大模型/推理框架对比.md) 的分工加载（Ollama 对 adapter 的支持方式以官方文档为准）。

- **最小可跑骨架（LLaMA-Factory，命令与参数名以官方文档为准）**：

  ```yaml
  model_name_or_path: <基座，如 Qwen2.5-7B-Instruct>
  dataset: <数据集名，需在 dataset_info.json 注册>
  template: <与基座一致的对话模板>
  finetuning_type: lora
  lora_rank: 8
  quantization_bit: 4          # QLoRA：基座 4bit 冻结
  per_device_train_batch_size: 1
  gradient_accumulation_steps: 8
  gradient_checkpointing: true
  learning_rate: 0.0002
  num_train_epochs: 2
  output_dir: <适配器输出目录>
  ```

  命令：`llamafactory-cli train <配置文件.yaml>`。先小数据、小 r、短序列跑通一次全流程，再放大规模（第 7 节）。
- **数据集格式**：指令微调常用 Alpaca 式三段式 JSON：`{"instruction": "任务指令", "input": "可选输入，可为空", "output": "期望输出"}`；多轮对话用 messages 格式（role/content 列表）并配对话模板。LLaMA-Factory 侧需在 `dataset_info.json` 里注册数据集名与文件路径，否则训不到数据。
- **QLoRA 在 12GB 下的结论（估算，待验证，与第 3 节账一致）**：7B 级 QLoRA + 短序列 + 小 batch + 梯度检查点，账面可装进 12GB，是本机唯一建议的起步档；14B 级基座约 7~8GB，留给激活与优化器的余量很紧，需 CPU offload 且慢，只建议 8B 级跑通后再试；不要在 12GB 上同时开大 batch 与长序列。
- **导出 GGUF 闭环**：适配器与基座合并成完整权重（或按加载方支持保持 adapter 挂载）→ llama.cpp 的 `convert_hf_to_gguf.py` 转 GGUF → 按需量化（如 Q4_K_M）→ llama-server/Ollama 加载实测 → 回到第 6 节评测集做前后对比，分数没涨就回滚适配器。

## 6. 过拟合与评估

- **过拟合长相**：训练 loss 一路降，但验证集表现先升后降；模型开始复读训练样本的措辞、只会处理与训练样本高度相似的输入。防法：控制轮数（epoch）、盯验证集曲线、用小学习率与适中 r 起步——具体数值靠实验，不写死。
- **灾难性遗忘**：练会新行为的同时把通用能力练丢。微调前后都要在原任务上回归，不只看新任务。
- **唯一可信的验收**：拿 [模型评测方法](AI与大模型/模型评测方法.md) 的评测集做微调前/后同集对比（类别指标 + 成本列），分数没涨就回滚适配器——LoRA 产物小、基座没动，回滚成本几乎为零，这是它对个人实验友好的另一面。本机尚无任何一次微调的前后对比数据，此节全部为流程设计，**待验证**。

## 7. 常见误区

- **想用微调给模型灌新知识**：灌进去的知识不可更新、不可溯源、还可能与真实事实混杂；知识问题用 RAG，行为问题才用微调（第 1 节）。
- **数据越多越好**：口径不一致的大数据只会把行为训得更混乱（第 4 节）。
- **只看训练 loss 报喜**：loss 是拟合训练集的程度，不是任务效果；没有评测集前后对比的微调等于没验收。
- **一上来就冲大模型、大 r、长序列**：显存账先算（第 3 节），从小档跑通全流程再放大，是本机实验的唯一稳妥顺序。
