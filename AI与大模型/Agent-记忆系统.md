# Agent 记忆系统

> [Agent](AI与大模型/Agent.md) 篇说过：长期记忆的关键是「检索得准」，不是「存得多」。本篇展开这句话：记忆分层怎么分、状态为什么必须外置、以及一个反直觉的风险——**记性太好、记得太多，反而会把 Agent 变笨**（Anti-Persistence）。小说引擎是这套理论最极端的使用方：它的「记忆」要撑几百章。

## 1. 核心概念

| 层 | 内容 | 载体 | 生命周期 |
|---|---|---|---|
| 工作记忆 | 当前任务的上下文：最近对话、工具结果、中间结论 | 上下文窗口 | 单次任务内 |
| 短期记忆 | 本轮会话/本次运行内要跨步骤保持的信息 | State 对象、会话变量 | 一次会话/一次运行 |
| 长期记忆 | 跨会话保留的事实：实体、关系、事件、偏好、结论 | 结构化库（SQLite 等）+ 向量库 | 长期 |

三层不要混：把长期事实塞进上下文当工作记忆用，窗口很快被淹没；把工作记忆的临时推测写进长期库，就是下文说的记忆污染。

## 2. 基础知识：状态外置原则

**原则：权威状态只存一处，且在模型之外。**

- 上下文里的内容是「给模型看的副本」，不是数据源。模型在推理中复述、概括过的状态不能反过来当事实写回——复述过程会丢字段、改数值、夹带推测。
- 写回长期记忆必须走结构化通道：模型输出结构化增量（见 [结构化输出与JSON约束](AI与大模型/结构化输出与JSON约束.md)），程序校验后落库。模型没有直接写库的权力。
- 每条长期记忆要带**出处与时间**（来自哪次任务/哪一章、什么时候写入），没有出处的信息事后无法审计、无法纠错、无法判断新旧。
- 更新要有「历史」概念：状态变化记成变更流水而不是直接覆盖，覆盖式存储会让「之前是什么样」永久丢失——这正是叙事引擎里 StateHistory 的存在理由。

## 3. 进阶知识：记忆污染与 Anti-Persistence

### 污染的三种来源

1. **幻觉入库**：模型编造的事实被写入长期记忆，之后被当作真事实反复检索出来，形成「自我证实」循环。防线：写回通道的业务校验 + 出处标记。
2. **推测与事实混存**：沙盒推演、假设性讨论产生的结论与确认事实存在同一张表里、同一个字段里，检索时不分彼此。防线：记忆分级——事实 / 推测 / 方案分开存、分开检索，推测永远不能自动升格为事实。
3. **过期事实不失效**：世界状态变了，旧事实还留在「当前状态」里与新事实并存。防线：状态类记忆要带时效与版本，检索默认只取当前版本，历史版本只在显式查历史时出场。

### Anti-Persistence：记忆会反噬

2026 年的一项研究（《More Memory, Worse Agents》，arXiv 2610.27406）提出 Anti-Persistence 现象：给 Agent 无差别地保留全部历史记忆，表现反而下降——过期信息、已推翻的结论、早期错误会持续参与决策，记忆量越大，噪声占比越高。结论不是「不要记忆」，而是：**记忆系统必须有淘汰与降权机制**——按时效衰减、按被引用效果筛选、冲突时以新代旧并保留审计痕，而不是只进不出。

这条对长链路项目的指导意义很具体：设计记忆系统时，「怎么删」和「怎么存」要同时设计；只存不删的系统，规模上来后必然劣化。

### 检索侧的配合

长期记忆的取出同样走混合路线：结构化查询（按实体、时间、类型精确取）为主，向量语义检索（见 [Embedding与向量数据库](AI与大模型/Embedding与向量数据库.md)）为辅，再加一层与当前任务的相关性过滤，不要把「取回来的一切」无差别塞进上下文——塞多少也是记忆设计的一部分，评测方法见 [RAG-评测与分块策略](AI与大模型/RAG-评测与分块策略.md)。

## 4. 实战应用：小说引擎的长期记忆

小说引擎把这套原则做成了数据库：Entity / EntityState / StateHistory 存人物与实体的当前状态和变更史，Relation 存关系，Timeline / Event 存事件序列，StoryFact 存已确立的剧情事实，ChapterContextService 在写每章前聚合出一份「世界状态上下文」给 LLM。这正是「状态外置 + 结构化写回 + 按需聚合检索」的完整形态，细节见 [小说创作引擎](../项目沉淀/小说创作引擎.md)。

而它当前最大的痛点也在这里：几百章尺度上，哪些旧事实该进上下文、伏笔状态怎么维护、过期状态如何不干扰新章——本质都是记忆系统的淘汰与检索问题，不是生成模型够不够大的问题。

## 5. 常见误区

- **把聊天记录全文当长期记忆**：原始对话是日志，不是记忆；记忆是提炼后的结构化事实。
- **只存不删**：见 Anti-Persistence，淘汰机制是记忆系统的一半。
- **模型复述即更新**：让模型「总结一下目前状态」再存回去，等于每轮有损压缩一次，累积失真。
