# 大模型基础

> Agent、RAG、Skills 都是"用法"，这篇补"底座"：模型是怎么工作的、为什么有那些限制。

## Transformer 与 Attention

- 一句话：Attention 让模型"写下一个词时回头看整句话"，Q/K/V 三个矩阵算相关性。
- 自回归生成：一次吐一个 token，接到后面再算下一个 → 生成慢的根本原因。
- KV Cache：把算过的 K/V 存下来，推理加速的核心，也是显存大户之一。

## Token

- 模型不认字，只认 token（BPE 切分）：英文约 1 token = 0.75 词，中文约 1 token = 1–1.5 字。
- 上下文窗口按 token 计费/计长：128K 上下文 ≠ 128K 字。
- 超长 prompt 先数 token 再发，别靠感觉。

## Embedding

- 把文字变成向量，语义相近的在空间里也相近。
- 文本 embedding（如 embeddinggemma）≠ 大模型的词向量，但思想同源。
- 余弦相似度是默认度量；归一化后点积 = 余弦。

## 向量检索与 Reranker

- 向量检索：ANN（HNSW/IVF），毫秒级从百万向量里找 TopK，召回快但粗。
- Reranker：cross-encoder 对 TopK 精排，慢但准。标准链路：向量召回 50 → rerank 取 5。
- 实战见 [AI与大模型/RAG-Skills.md](AI与大模型/RAG-Skills.md) 混合检索节。

## RAG 全链路

切分 → 向量化 → 召回 → 重排 → 生成 → 评测，缺一不可。
评测指标（Hit Rate / MRR / 忠实度）见 [AI与大模型/RAG-Skills.md](AI与大模型/RAG-Skills.md)。

## Function Calling 与 MCP

- Function Calling：模型输出结构化"调哪个工具 + 参数"，由代码执行，结果再喂回模型。
- MCP：工具的"USB-C 接口"，一次实现，到处可用。
- Agent 工作流：ReAct（想→做→看）/ Plan-and-Execute（先计划再执行），详见 [AI与大模型/Agent.md](AI与大模型/Agent.md)。

## 量化、推理、显存

| 精度 | 大小（7B） | 质量 |
|---|---|---|
| FP16 | ~14GB | 基准 |
| Q8 | ~7GB | 几乎无损 |
| Q4_K_M | ~4GB | 轻微损失，常用 |
| Q2 / IQ2 | ~2.5GB | 明显损失，应急用 |

- 显存公式：参数量 × 精度字节数 + KV Cache（随上下文涨）+ 激活值。
- nemotron-3.5-bolt（74B-A9B，原生 2-bit，25GB）就是"大参数 + 低精度"的代表。
- 推理速度看 token/s；首 token 延迟和持续吞吐是两回事。

## 上下文窗口

- 标 128K 不等于能用满 128K："大海捞针"测试里很多模型中部信息召回率掉一半。
- 工程做法：RAG 只喂 TopK 相关片段，别把整库倒进窗口；长文档先摘要再问。

## Prompt 注入与 Agent 安全

- 直接注入："忽略之前的指令……"；间接注入：网页 / RAG 文档里藏指令。
- 防护：工具权限最小化（只读工具和写库工具分开）、高风险操作人工确认、输出过滤。
- Agent 越自主，护栏越重要：审批卡就是 Human-in-the-Loop 的实例。

## 训练链路（一句话版）

预训练（海量文本学语言）→ SFT（指令微调学"听话"）→ RLHF/DPO（人类偏好对齐）。

- 预训练决定"知道多少"，SFT 决定"会不会干活"，对齐决定"说得好不好"。
- 微调场景：LoRA 只训小部分参数，单卡就能做；全量微调是烧钱行为。

## MoE（混合专家）

- 模型里养 N 个"专家"子网络，每次只激活其中几个（如 8 选 2）。
- 总参数大（知识多），激活参数小（推理快）——nemotron-3.5-bolt 的 74B-A9B 就是这个路数。
- 代价：显存要装下所有专家，通信开销大。

## 解码参数

| 参数 | 作用 |
|---|---|
| temperature | 随机性；0 最确定，越高越发散 |
| top_p | 只从累积概率 p 的词里选 |
| top_k | 只从 top-k 个词里选 |
| max_tokens | 最多吐多少 |

- 抽取/JSON 任务：temperature=0；创意写作：0.7–0.9。
- 小说引擎抽取用 0，RAG 问答用 0.1–0.3。

## KV Cache 显存估算

- 公式：`2 × 层数 × hidden × seq_len × 精度字节`（K 和 V 各一份）。
- 70B 模型、128K 上下文，KV Cache 能吃掉几十 GB——这就是长上下文贵的硬件原因。
- 工程：窗口不是越大越好，够用就行；vLLM 的 PagedAttention 就是 KV Cache 的内存管理优化。

## 基础知识补强

### 核心概念与术语

- 参数（权重）：模型内部可调的数字，总量就是常说的 7B、70B（B 是十亿）。参数是训练的产物，知识就以这种形式存着。
- 神经元与层：神经元做一次"加权求和再过一个非线性函数"；大量神经元分层堆叠，前一层的输出是后一层的输入。
- 训练 vs 推理：训练是拿数据调参数（慢、贵、一次性）；推理是参数固定、只做计算产出结果（日常调用的全是推理）。
- 损失函数：衡量模型预测与正确答案差多远的一个数；训练就是想办法让它变小。
- 梯度下降：按"往哪个方向挪参数能让损失降得最快"反复微调参数，是所有训练算法的共同骨架。
- 过拟合：把训练数据背下来了，换新数据就拉胯；表现是训练集分数高、真实场景分数低。
- 词表（Vocab）：分词器认识的全部 token 清单，模型最后一层要在词表范围内挑下一个 token。
- 幻觉：模型流畅地编造不存在的事实。成因是它只在学"像样的下文"，从不核查真伪，答得像对的不等于对。
- 涌现能力：模型规模跨过某个量级后突然具备的、之前完全不会的能力（如多步推理），是"大力出奇迹"的来源之一。
- 困惑度（Perplexity）：衡量模型对一段真实文本"有多意外"的指标，越低说明语言建模越好，只反映像不像，不反映对不对。
- 解码器架构：当下主流大模型基本是"只解码"结构——只做一件事，根据已有 token 预测下一个 token，聊天、写代码都是这件事的副产品。
- 标记与特殊 token：词表里除了普通词，还有表示开头、结尾、填充、对话轮次切换的特殊标记，接口里的角色分隔就靠它们实现。

### 基础知识与用法

Attention 的计算公式，原文讲了 Q/K/V，这里补齐它到底怎么算：

```text
Attention(Q, K, V) = softmax(QK^T / √d) × V
Q（查询）：我现在想找什么；K（键）：每段内容挂的标签；V（值）：内容本身
QK^T：拿查询和每个标签算匹配分；除以 √d 是防分数过大让 softmax 饱和
softmax：把一组分数变成总和为 1 的权重；最后按权重把 V 加权求和
一句话：注意力 = 按相关性给上下文各部分分配权重，再按权重汇总信息。
```

位置编码为什么必须存在：

```text
注意力计算本身对词序无感：打乱句子顺序，单看注意力结果不变。
所以要给每个位置额外注入一个"位置信号"（固定公式生成或训练学出来），
模型才能区分"猫追狗"和"狗追猫"这类只差语序的句子。
```

上下文学习（In-Context Learning），不改参数也能"教"模型：

- 零样本（Zero-shot）：只给任务说明，不给例子，全靠模型预训练的底子。
- 少样本（Few-shot）：在提示里塞几个"输入到输出"的示范例，模型照葫芦画瓢，格式对齐立竿见影。
- 思维链（Chain-of-Thought）：给示范时把推理步骤也写出来，或要求模型先写步骤再给结论，复杂推理题准确率明显提升。
- 本质：这些都没动参数，只是把"任务说明书和例题"写进了上下文，关掉会话就全忘。

对话消息的三种角色，调接口时天天见：

```text
system：定角色、规则、边界，优先级最高，放最前面
user：用户本轮的输入
assistant：模型历轮的输出
多轮对话的原理：每轮都把之前的消息整段重发，模型本身没有记忆，
所谓"它记得上文"，是客户端每次都把历史打包再喂一遍——这也是长对话越来越贵的原因。
```

蒸馏，一句话补齐这个高频词：

- 用大模型（教师）的输出当教材训练小模型（学生），让小模型用更低成本逼近大模型在某类任务上的表现。
- 代价是能力上限被教师框住，泛化不如同规模原生训练；好处是部署便宜，适合把通用能力压进专用小模型。

模型文件与推理引擎，分工看清：

```text
模型文件：只存参数和结构信息（如 GGUF、safetensors 一类格式，区别在量化支持与加载方式）
推理引擎：负责真正跑计算的程序（加载权重、管理 KV Cache、做批处理）
同一个模型换引擎，速度和显存占用可以差很多；选型时两者要分开评估。
```

### 关键机制速览

- 多头注意力：把注意力拆成多组并行算，每组盯一种关系（指代、搭配、句法），最后拼起来，比单组看得全。
- 残差连接：每层输出等于"变换结果加上原输入"，让深层网络不至于越训越差，是堆几十上百层的前提。
- 归一化：把每层数值拉回稳定范围，防训练中数值爆炸或消失，属于不起眼但缺了就训不动的部件。
- 模型知识有截止时间：训练数据到某个时间点为止，之后的事它不知道，只能靠 RAG 或工具去查。
- 同一问题每次答得不一样是设计使然：采样环节带随机性；温度调到 0 也只是趋向确定，并行计算的浮点误差仍可能让结果漂移。
- 首字延迟主要耗在"读完整段提示并算完第一步"（预填充阶段），之后逐字生成的速度由模型大小和显存带宽决定。
- 批量推理更划算：多个请求拼一批一起算，GPU 利用率远高于逐个处理，服务端框架都在做连续批处理。
- 评测一个模型分三层看：公开基准分数（参考）、自己业务集的实测（为准）、人工抽检输出质量（兜底），只看第一层最容易踩坑。
- 自回归的误差会滚雪球：前面生成的一个错 token 会被当成既定前提继续往下写，长输出尾部跑偏常源于此，所以关键结论要复核不能只看开头。
- 向量维度的直觉：维度越高能区分的语义越细，但存储和检索成本同比上涨，选 embedding 模型时维度是成本项不是面子项。

### 新手易错点

- 把参数量直接等同于知识量和智商：训练数据质量、训练方法影响同样大，小参数新模型打赢大参数老模型很常见。
- 以为模型能实时查资料：不给它联网工具和检索时，它回答的全是训练数据的记忆，时效问题必须靠外部喂。
- 中英文混着估长度：拿英文字数比例去估中文 prompt 的 token 数会严重低估，先分词计数再决定截断策略。
- 拿生成模型当向量模型用：生成模型的隐藏状态不是为相似度检索优化的，向量检索要用专门的 embedding 模型。
- 以为量化只有好处：低比特量化省显存的同时，长推理、精确计算类任务的质量下滑最先出现，要拿自己的任务实测。
- 把基准跑分当采购标准：公开基准可能被针对性优化过，和你的真实任务分布无关，自建小评测集才是决策依据。
- 认为提示写得越长越保险：无关信息会稀释注意力、抬高成本，提示要短而准，背景材料按需检索着喂。
- 把模型答得流畅当成答得对：流畅是语言模型的本职，事实正确性不在它的优化目标里，越是具体的人名、日期、数字越要另行核查。
- 换个问法答案就变了便判定模型"不靠谱"：输出对提示措辞敏感是采样生成的常态，重要问题固定问法、多问几遍取共识更稳。
- 忽略输出长度的成本：费用和延迟大头常在输出侧，回答前先限定格式和长度，比事后截断更省。
