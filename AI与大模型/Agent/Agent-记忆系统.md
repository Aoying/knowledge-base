# Agent 记忆系统

> [Agent](AI与大模型/Agent/Agent.md) 篇说过：长期记忆的关键是「检索得准」，不是「存得多」。本篇展开这句话：记忆分层怎么分、状态为什么必须外置、以及一个反直觉的风险——**记性太好、记得太多，反而会把 Agent 变笨**（Anti-Persistence）。小说引擎是这套理论最极端的使用方：它的「记忆」要撑几百章。

## 1. 核心概念

| 层 | 内容 | 载体 | 生命周期 |
|---|---|---|---|
| 工作记忆 | 当前任务的上下文：最近对话、工具结果、中间结论 | 上下文窗口 | 单次任务内 |
| 短期记忆 | 本轮会话/本次运行内要跨步骤保持的信息 | State 对象、会话变量 | 一次会话/一次运行 |
| 长期记忆 | 跨会话保留的事实：实体、关系、事件、偏好、结论 | 结构化库（SQLite 等）+ 向量库 | 长期 |

三层不要混：把长期事实塞进上下文当工作记忆用，窗口很快被淹没；把工作记忆的临时推测写进长期库，就是下文说的记忆污染。

## 2. 基础知识：状态外置原则

**原则：权威状态只存一处，且在模型之外。**

- 上下文里的内容是「给模型看的副本」，不是数据源。模型在推理中复述、概括过的状态不能反过来当事实写回——复述过程会丢字段、改数值、夹带推测。
- 写回长期记忆必须走结构化通道：模型输出结构化增量（见 [结构化输出与JSON约束](AI与大模型/结构化输出与JSON约束.md)），程序校验后落库。模型没有直接写库的权力。
- 每条长期记忆要带**出处与时间**（来自哪次任务/哪一章、什么时候写入），没有出处的信息事后无法审计、无法纠错、无法判断新旧。
- 更新要有「历史」概念：状态变化记成变更流水而不是直接覆盖，覆盖式存储会让「之前是什么样」永久丢失——这正是叙事引擎里 StateHistory 的存在理由。

## 3. 进阶知识：记忆污染与 Anti-Persistence

### 污染的三种来源

1. **幻觉入库**：模型编造的事实被写入长期记忆，之后被当作真事实反复检索出来，形成「自我证实」循环。防线：写回通道的业务校验 + 出处标记。
2. **推测与事实混存**：沙盒推演、假设性讨论产生的结论与确认事实存在同一张表里、同一个字段里，检索时不分彼此。防线：记忆分级——事实 / 推测 / 方案分开存、分开检索，推测永远不能自动升格为事实。
3. **过期事实不失效**：世界状态变了，旧事实还留在「当前状态」里与新事实并存。防线：状态类记忆要带时效与版本，检索默认只取当前版本，历史版本只在显式查历史时出场。

### Anti-Persistence：记忆会反噬

2026 年的一项研究（《More Memory, Worse Agents》，arXiv 2610.27406）提出 Anti-Persistence 现象：给 Agent 无差别地保留全部历史记忆，表现反而下降——过期信息、已推翻的结论、早期错误会持续参与决策，记忆量越大，噪声占比越高。结论不是「不要记忆」，而是：**记忆系统必须有淘汰与降权机制**——按时效衰减、按被引用效果筛选、冲突时以新代旧并保留审计痕，而不是只进不出。

这条对长链路项目的指导意义很具体：设计记忆系统时，「怎么删」和「怎么存」要同时设计；只存不删的系统，规模上来后必然劣化。

### 检索侧的配合

长期记忆的取出同样走混合路线：结构化查询（按实体、时间、类型精确取）为主，向量语义检索（见 [Embedding与向量数据库](AI与大模型/RAG/Embedding与向量数据库.md)）为辅，再加一层与当前任务的相关性过滤，不要把「取回来的一切」无差别塞进上下文——塞多少也是记忆设计的一部分，评测方法见 [RAG-评测与分块策略](AI与大模型/RAG/RAG-评测与分块策略.md)。


### 记忆提取：按权重取，按预算拼

检索侧的配合解决的是“从哪取”，本节解决的是“取哪些、取多少、怎么拼进上下文”。取的依据是三个维度的加权取舍，不是只看语义相似度：

| 维度 | 含义 | 取舍原则 |
|---|---|---|
| 相关性 | 与当前任务的匹配程度：语义相似 + 结构化匹配（同一实体、同一时间段、同一类型） | 主排序依据，但不能是唯一依据 |
| 最近性 | 写入时间近、近期被引用过的记忆 | 近期记忆加权，旧记忆不因“像”而压过新事实 |
| 重要性 | 写入时定的事实等级：核心事实高于细节，用户显式标注高于系统推测，被反复引用的高于只写不用的 | 重要性是慢变量，写入时定、引用中修正，不随每次检索波动 |

三者加权排序后，拼进上下文还有三条硬规则：

- **条数上限按 token 预算倒推**：先给记忆部分定 token 预算，再换算成条数，而不是先定条数。预算内按权重从高往低取，取满即止，不因为“多取一点更保险”超预算。
- **去重**：同一事实的多个版本只取当前版进上下文，历史版本不并列出现；同义的不同表述合并成一条，避免模型把重复出现误读成多方印证。
- **时间标注**：每条记忆进上下文时带上写入或生效时间，旧记忆显式标出时间。没有时间标注的旧记忆最容易被模型当成现况用，这是记忆类幻觉的常见来源。

### 遗忘策略：衰减、压缩、上限、安全边界

Anti-Persistence 一节讲了为什么必须淘汰，本节讲淘汰的具体机制。淘汰针对的是“当前检索池”，不是审计库：被淘汰的记忆应归档留痕，而不是物理删除，否则事后无法复核“当初为什么这么决策”。

- **衰减**：久未被引用的记忆权重随时间下降；反过来，被引用本身就是保值信号，常被取用的记忆不因时间久而被降权。衰减调的是检索权重，不是事实的真假——权重降到阈值以下的记忆不再进上下文，但仍可查。
- **摘要压缩**：定期把一批低频旧记忆聚合成摘要，摘要保留原文指针，需要时能追溯到原始条目。摘要本身也要参与衰减和再压缩，不能变成另一处只进不出的堆积。
- **容量上限与淘汰顺序**：检索池设上限（条数或 token 量），超限时按顺序淘汰：先是已过期、无出处、低权重者，再是已被摘要覆盖的原文，最后才是低频但仍有效的事实。每一次淘汰留痕：删了什么、按哪条规则删的。
- **“遗忘什么”的安全边界**：三类记忆不自动淘汰，只可人工归档——关键事实（身份、核心关系、已确立的结论）、用户显式表达的偏好、审计与合规类记录。摘要压缩时这三类不参与合并改写，只能原样保留或原样归档。

### 冲突消解：先裁决，裁不掉就并存标注

新记忆与旧记忆矛盾时，裁决按以下顺序取优先级，排在前面的胜出：

1. **来源权重**：用户显式确认高于系统观测，系统观测高于模型推测，权威记录高于转述。来源不明的记忆在冲突中默认落败。
2. **时间戳优先**：同来源、同权重的冲突以新胜旧，但旧条目不删除，进历史版本，供显式查历史时出场。
3. **置信度优先**：写入时带置信度标记的，冲突时高置信度胜出；没有置信度标记的，视为低置信度。

冲突一时无法裁决时，不允许静默选一边：

- **并存标注**：两条记忆同时保留并标注“存在冲突”，取用时同时呈现给模型或用户，注明各自的来源与时间，让决策方知情而不是被蒙蔽。
- **向用户确认**：冲突涉及关键事实或会影响不可逆操作时，在决策前主动向用户确认，而不是事后纠错。
- **兜底**：冲突消解失败且无法确认时，默认走保守策略——争议记忆不用于不可逆操作，条目标注“待核实”，进入人工复核队列。宁可一次决策少用一条记忆，不可让一条争议记忆悄悄驱动关键动作。

### 效果评估：命中率、幻觉率、抽查、反哺

记忆系统好不好，不能凭“存了多少条”判断，要量三件事，量法都对应到可执行的操作：

- **记忆命中率**：针对一批标注过的探针任务（任务明确需要某条记忆才能答对），统计所需记忆被成功取回的比例。命中率低说明提取环节有问题：权重失衡、召回渠道缺失、或记忆根本没写进长期库，逐项排查而不是笼统调参。
- **幻觉率**：抽查被取回并实际用于决策的记忆，事后核对其中与事实不符的比例。幻觉率高优先收紧写回通道（业务校验、来源标记、分级存储），而不是先调提取权重——写进来的脏数据，取的环节洗不干净。
- **人工抽查**：定期按固定比例抽样审计记忆条目，逐条核对出处、时效、正确性三项。抽查是唯一能发现“权重和指标都正常、但记忆本身已悄悄变质”的手段，抽查结果本身也要留痕。

评估结果要闭环回策略，而不是只出报告：

| 评估信号 | 反哺动作 |
|---|---|
| 命中率低 | 调提取权重、补召回渠道、检查应存未存的事实类型 |
| 幻觉率高 | 收紧写回校验、清理污染条目、复核分级存储是否混存 |
| 抽查发现过期事实仍在池中 | 收紧衰减与淘汰阈值、复核安全边界是否被误触 |
| 抽查发现关键事实被淘汰 | 收紧安全边界、复核淘汰规则与留痕 |

评估与 RAG 侧的量化方法互通，指标口径见 [RAG-评测与分块策略](AI与大模型/RAG/RAG-评测与分块策略.md)；语义检索层的实现见 [Embedding与向量数据库](AI与大模型/RAG/Embedding与向量数据库.md)。

## 4. 实战应用：小说引擎的长期记忆

小说引擎把这套原则做成了数据库：Entity / EntityState / StateHistory 存人物与实体的当前状态和变更史，Relation 存关系，Timeline / Event 存事件序列，StoryFact 存已确立的剧情事实，ChapterContextService 在写每章前聚合出一份「世界状态上下文」给 LLM。这正是「状态外置 + 结构化写回 + 按需聚合检索」的完整形态，细节见 [小说创作引擎](项目沉淀/小说创作引擎.md)。

而它当前最大的痛点也在这里：几百章尺度上，哪些旧事实该进上下文、伏笔状态怎么维护、过期状态如何不干扰新章——本质都是记忆系统的淘汰与检索问题，不是生成模型够不够大的问题。

## 5. 常见误区

- **把聊天记录全文当长期记忆**：原始对话是日志，不是记忆；记忆是提炼后的结构化事实。
- **只存不删**：见 Anti-Persistence，淘汰机制是记忆系统的一半。
- **模型复述即更新**：让模型「总结一下目前状态」再存回去，等于每轮有损压缩一次，累积失真。
