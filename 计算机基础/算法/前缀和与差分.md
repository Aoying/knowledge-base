# 前缀和与差分

前缀和与差分是一对互逆的预处理技巧：前缀和把“区间查询”变成 O(1)，差分把“区间修改”变成 O(1)。两者都不支持“边改边查”，那是树状数组/线段树的活。

## 一维前缀和

定义：`pre[0] = 0`，`pre[i+1] = pre[i] + nums[i]`，即 `pre[i]` 是前 `i` 个元素的和。区间和 `sum(l, r)`（闭区间）= `pre[r+1] - pre[l]`。

```python
def build_prefix(nums):
    pre = [0] * (len(nums) + 1)
    for i, x in enumerate(nums):
        pre[i + 1] = pre[i] + x
    return pre

def range_sum(pre, l, r):
    return pre[r + 1] - pre[l]
```

### worked 例

`nums = [3, 1, 4, 1, 5, 9]`，逐步累加得：

```
pre = [0, 3, 4, 8, 9, 14, 23]
```

- `sum(1, 3) = pre[4] - pre[1] = 9 - 3 = 6`，对应 `1 + 4 + 1 = 6`。
- `sum(0, 5) = pre[6] - pre[0] = 23 - 0 = 23`，即全数组和。

## 二维前缀和

定义：`ps[i+1][j+1] = mat[i][j] + ps[i][j+1] + ps[i+1][j] - ps[i][j]`。矩形 `(r1, c1)` 到 `(r2, c2)`（闭区间）的和 = `ps[r2+1][c2+1] - ps[r1][c2+1] - ps[r2+1][c1] + ps[r1][c1]`，最后加回来的 `ps[r1][c1]` 是被减了两次的左上角重叠区。

### worked 例

`mat = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]`：

- 右下角 `2x2` 子矩阵 `(1, 1)` 到 `(2, 2)`：`5 + 6 + 8 + 9 = 28`，公式算出 `45 - 6 - 12 + 1 = 28`。
- 全矩阵和：`45`。

## 差分数组

定义：`diff[0] = arr[0]`，`diff[i] = arr[i] - arr[i-1]`。差分是前缀和的逆运算：对 `diff` 求前缀和就还原出 `arr`。

区间加 `[l, r] += v` 只需两步：`diff[l] += v`；若 `r + 1 < n`，`diff[r+1] -= v`。还原时对 `diff` 做一次前缀和即可。

```python
def range_add(diff, l, r, v):
    diff[l] += v
    if r + 1 < len(diff):
        diff[r + 1] -= v

def restore(diff):
    out, s = [], 0
    for d in diff:
        s += d
        out.append(s)
    return out
```

### worked 例

`arr = [1, 2, 3, 4, 5]`，差分是 `[1, 1, 1, 1, 1]`。区间 `[1, 3] += 10` 后差分变为 `[1, 11, 1, 1, -9]`，还原得 `[1, 12, 13, 14, 5]`，与直接加逐项核对一致。

多次区间加（从全 0 数组起）：`[0, 2] += 5`，`[1, 4] += 3`，还原得 `[5, 8, 8, 3, 3]`。逐项核对：位置 0 只吃到第一次加法得 5；位置 1、2 两次都吃到得 8；位置 3、4 只吃到第二次得 3。

## 二维差分

一维差分的二维推广：对矩阵做矩形区间加。定义 `diff[i][j] = a[i][j] - a[i-1][j] - a[i][j-1] + a[i-1][j-1]`（越界项取 0），还原时对 `diff` 做二维前缀和。

矩形 `(r1, c1)` 到 `(r2, c2)` 加 `v`，只需改四个角（越界的角跳过）：

```python
def rect_add(diff, r1, c1, r2, c2, v, m, n):
    diff[r1][c1] += v
    if r2 + 1 < m:
        diff[r2 + 1][c1] -= v
    if c2 + 1 < n:
        diff[r1][c2 + 1] -= v
    if r2 + 1 < m and c2 + 1 < n:
        diff[r2 + 1][c2 + 1] += v
```

### worked 例

`3x3` 全 0 矩阵：`(0, 0)-(1, 1) += 5`，`(1, 1)-(2, 2) += 3`，还原得：

```
[5, 5, 0]
[5, 8, 3]
[0, 3, 3]
```

逐项核对：`(1, 1)` 同时落在两个矩形内得 `5 + 3 = 8`；`(0, 2)`、`(2, 0)` 不在任何矩形内为 0；其余位置只吃到一次加法。与直接逐格加的结果一致。

### 边界条件

- 四个角中 `r2 + 1 == m` 或 `c2 + 1 == n` 的直接跳过：矩形贴到矩阵下/右边界时没有“下一行/列”需要抵消，强行写会越界。
- `diff` 数组本身可比原矩阵多开一行一列（`(m+1) x (n+1)`），这样四个角永远不用判越界，还原时只读前 `m x n` 格；代价是多一点内存，换来代码零分支——工程实现常选这种写法。
- 二维差分同样只支持“先加后还原”，中间查某格的值要把还原算到该格，不能只看 `diff[i][j]`。

## 前缀和的变体

### 异或前缀和

前缀和的“加法”换成异或即得异或前缀和：`pre[i+1] = pre[i] ^ nums[i]`，区间异或 `xor(l, r) = pre[r+1] ^ pre[l]`。原理相同：`a ^ a = 0` 抵消掉前缀部分。适用：区间异或查询、子数组异或为 `k` 的计数（配合哈希表，与下面同理）。

worked 例：`nums = [3, 1, 4, 1, 5]`，`xor(1, 3) = pre[4] ^ pre[1] = 4`，直接算 `1 ^ 4 ^ 1 = 4`，一致。

### 前缀和 + 哈希表：子数组和为 k 的计数

前缀和的经典延伸：`sum(l, r) = pre[r+1] - pre[l] = k`，即 `pre[l] = pre[r+1] - k`。从左到右扫一遍，用哈希表记已出现过的前缀和次数，当前前缀和为 `s` 时，答案加上 `count[s - k]`。

```python
from collections import Counter

def count_subarray_sum(nums, k):
    cnt = Counter({0: 1})  # 空前缀,处理 l = 0 的情况
    s = ans = 0
    for x in nums:
        s += x
        ans += cnt[s - k]
        cnt[s] += 1
    return ans
```

worked 例：`nums = [1, 1, 1]`，`k = 2`，结果为 `2`（`[0, 1]`、`[1, 2]`）；`nums = [1, 2, 3]`，`k = 3`，结果为 `2`（`[0, 1]`、`[2, 2]`）。复杂度 O(n)，比暴力 O(n²) 少一个量级。

### 反例：有负数时不能用双指针找“和为 k 的子数组”

双指针（滑动窗口）找和为 `k` 的子数组，依赖“右移只增、左移只减”的单调性；数组含负数时单调性失效，会漏解。反例：`nums = [5, -3, 1, 1]`，`k = 3`，唯一解是 `[0, 2]`（`5 - 3 + 1 = 3`）；双指针右移到 `5` 时和已超 `k`，按规则左移收缩把 `5` 踢掉，此后累加再也凑不出 `3`，漏掉正确解（已用脚本逐项枚举验证：暴力枚举得 `[(0, 2)]`，双指针得 `[]`）。结论：含负数时用“前缀和 + 哈希表”，不要用双指针；只有全非负数组才能用滑动窗口。

## 复杂度对比

| 操作 | 暴力 | 前缀和 / 差分 |
|---|---|---|
| 一维区间和查询 | 每次 O(n) | 构造 O(n)，查询 O(1) |
| 二维矩形和查询 | 每次 O(mn) | 构造 O(mn)，查询 O(1) |
| 区间加 | 每次 O(n) | 每次 O(1)，最后还原 O(n) |

## 适用场景与边界

- 前缀和适合：静态数组 + 频繁区间和查询（如子数组和、矩阵区域和）。
- 差分适合：频繁区间加、最后统一看结果（如航班预订统计、区间加法题）。
- 边界：区间修改后前缀和失效——改一个元素，后面所有前缀和都要变；要“边改边查”请用树状数组或线段树，不要硬套前缀和。
- 坑：`pre` 长度是 `n + 1`，查询用 `pre[r+1] - pre[l]`，不是 `pre[r] - pre[l]`；二维公式最后要加回 `ps[r1][c1]`；差分区间加时 `r + 1` 越界要跳过，不要写出界。
- 溢出：元素是 `int` 时前缀和可能溢出（如 LeetCode 数据量级下 `int` 累加超 `2^31-1`），Java 里前缀和数组用 `long[]`、Python 不用操心（任意精度整数）；面试写 Java 代码时先声明 `long[] pre`，不要等跑挂了再改。
- 边改边查的取舍（按场景选结构，不硬套）：

| 场景 | 推荐 | 原因 |
|---|---|---|
| 静态数组，多次区间和查询 | 前缀和 | 构造 O(n)，查询 O(1)，最简单 |
| 多次区间加，最后统一看结果 | 差分 | 每次修改 O(1)，最后还原 O(n) |
| 单点改 + 区间和查询交错 | 树状数组 | 单点改与查询均为 O(log n) |
| 区间改 + 区间查交错 | 线段树（懒标记） | 区间改与查询均为 O(log n)，实现最重 |

## 小技巧与冷知识

【小技巧】Python 里建一维前缀和不用手写循环，用 `itertools.accumulate(nums, initial=0)` 一行搞定：`initial=0` 正好对应 `pre[0] = 0`，对原文例子 `[3, 1, 4, 1, 5, 9]` 直接得到 `[0, 3, 4, 8, 9, 14, 23]`。它返回的是迭代器，要多次随机访问先包一层 `list()`；NumPy 里对应的是 `cumsum`，记得同样在前面补一个 0。

【小技巧】固定窗口的滑动求和不用每窗重算：窗口大小为 `k` 时，第 `i` 个窗口的和就是 `pre[i+k] - pre[i]`，每个窗口 O(1)。对原文例子 `[3, 1, 4, 1, 5, 9]` 取 `k = 3`，四个窗口和依次是 8、6、10、15，都是两次减法算出来的；窗口一多，这个写法比“每窗循环加 k 个数”省一个量级。

【小技巧】非负数组的前缀和是单调递增的，可以直接二分：想找“累积和首次达到 K 的位置”，对 `pre` 用 `bisect_left(pre, K)`，不用从头扫。对原文的 `pre = [0, 3, 4, 8, 9, 14, 23]`，找首次 ≥ 10 的位置返回下标 5（`pre[5] = 14`），对应原数组下标 4；数组含负数时前缀和不再单调，这招就失效了。

【小技巧】只有可逆的运算能套前缀和的套路：加法和异或都有逆运算，所以 `pre[r+1] - pre[l]`、`pre[r+1] ^ pre[l]` 能把前缀抵消掉；最小值、最大值没有逆运算，区间最小值不能写成两个前缀最小值相减。判断一个区间查询能不能用前缀和，先问“这个运算可逆吗”，不能就换稀疏表或线段树。

【小技巧】差分只管“区间加 + 最后还原 / 单点查”，区间加之后还要反复查区间和，差分就不够用了：每次区间加只改两点，但区间和查询要把整个区间还原出来，代价回到 O(n)。这时要上树状数组双树维护或带懒标记的线段树，选结构前先确认“改完之后查什么”，而不是只看“改的代价”。

【小技巧】查询次数很少时别急着建前缀和：建表本身要 O(n)，如果整个程序只查一两次区间和，直接循环求和更便宜；前缀和的收益来自“一次建表、多次查询”摊薄成本。写题时先数查询次数，面试里把这句判断说出来，比直接背模板更显思路清楚。

【小技巧】差分数组加端点排序就是扫描线：求一批区间的最大重叠数，不用还原整个数组——每个区间在 `l` 处 +1、`r+1` 处 -1，把所有端点按坐标排序扫一遍，累加的最大值就是答案。四个区间 `(1, 3)`、`(2, 5)`、`(4, 6)`、`(2, 2)` 扫下来最大重叠是 3（在点 2 处）；这是差分思想在离线问题里的标准用法。

【小技巧】二维前缀和的查询公式本质是容斥原理：矩形和 = 右下角整块 − 左边长方形 − 上边长方形 + 左上角重叠区。记口诀“减左减上、加回左上”，对应公式里最后 `+ ps[r1][c1]` 那一项；公式写错时先画一张图数“每个区域被加减了几次”，比硬背符号可靠。

【小技巧】二维前缀和分两步建比直接套四项公式少出错：先对每一行做一维前缀和，再对结果按列做一维前缀和，两步都是原文一维前缀和的现成写法。二维差分同理，先按行做差分、再按列做差分；分步写每一步都能单独验证，合起来就是二维公式，调试时定位也更快。

【小技巧】异或前缀和也能配哈希表数“异或为 k 的子数组”：`pre[r+1] ^ pre[l] = k` 即 `pre[l] = pre[r+1] ^ k`，扫一遍查表计数，和原文加法版的套路一模一样。已验证的例子：`[4, 2, 2, 6, 4]` 里异或为 6 的子数组共 4 个；注意初始化同样要先把空前缀 `0` 计一次，否则会漏掉从下标 0 开始的答案。

【小技巧】SQL 里也有前缀和：窗口函数 `SUM(x) OVER (ORDER BY t)` 就是数据库帮你算的前缀和，常用来做累计销售额、累计用户数。写法上和数组版同理，但要注意窗口函数内部同样要先排序再累加，数据量大时 `ORDER BY` 的排序开销省不掉，别以为写了窗口函数就天然是 O(n)。

【冷知识】二维前缀和在图像处理里叫积分图（summed-area table）：Franklin C. Crow 在 1984 年的论文《Summed-Area Tables for Texture Mapping》里提出，用它算任意矩形的像素和只需四次查表。Viola 和 Jones 2001 年的人脸检测正是靠积分图，让每个矩形特征都能 O(1) 求和，才把实时人脸检测变成可能。

【冷知识】差分是离散微分，前缀和是离散积分：`diff[i] = arr[i] - arr[i-1]` 就是离散版的导数，对 `diff` 求前缀和还原 `arr` 就是离散版的积分，微积分基本定理在这里有离散对应物。有限差分法可追溯到牛顿 17 世纪末的插值工作，他用差分表做多项式插值，思路和今天的差分数组同源。

【冷知识】并行计算里前缀和有个专门的名字：scan。Guy Blelloch 在 1990 年的论文《Prefix Sums and Their Applications》里系统总结了 scan 的并行算法与应用；今天 GPU 编程里 scan 仍是基础并行基元之一，排序、流压缩、负载均衡都要用到它，串行版的前缀和只是它的单线程特例。

【冷知识】树状数组本质是“分块的前缀和”：前缀和把整个数组当成一块，改一个元素要重算后面全部；树状数组把数组按二进制切成大小不等的块，每个节点存一块的和，单点改只动 O(log n) 个块。所以原文说“边改边查请用树状数组”，根子上是“前缀和的块太大、改的代价太高”，换更细的块就解决了。

【冷知识】“前缀和”在不同语境下有好几个名字：英文常叫 prefix sum，也叫 cumulative sum 或 running total；Excel 表格里的“累计求和”、财报里的“累计收入”都是同一个概念。面试题里它也常以“累积和”“累计和”的名字出现，认出是同一东西，就不用再推导一遍。

## 面试与自测

1. 前缀和构造是 O(n)、查询是 O(1)，为什么不能反过来做到构造 O(1)、查询 O(1)？
2. 对数组做了一次区间修改后，为什么原来的前缀和不能继续用？
3. 差分数组还原为什么就是对差分求前缀和？
4. 数组含负数时，为什么不能用双指针找和为 `k` 的子数组？该用什么方法？

### 参考答案

1. 查询 O(1) 的代价就是构造时把累积信息提前算好：`pre` 的每一项都依赖前一项，必须从左到右扫一遍，所以构造至少是 O(n)；不存在不花时间就得到全部累积信息的方法。
2. 因为 `pre[i]` 的定义是前 `i` 个元素的和，改动位置 `p` 之后所有 `i > p` 的 `pre[i]` 都变了；只有把受影响的后缀重算一遍（O(n)）或换支持单点修改的数据结构才能继续查。
3. 因为差分定义就是相邻元素的差：`arr[i] = diff[0] + diff[1] + ... + diff[i]`，把差分从头累加恰好把每一步的差补回去，得到的就是原数组。
4. 双指针依赖“右移和只增、左移和只减”的单调性，负数会破坏它：右移可能让和变小、左移可能让和变大，收缩/扩张的判断失效，会漏解（如 `[5, -3, 1, 1]` 找和为 `3`，双指针漏掉唯一解 `[0, 2]`）。正确方法是“前缀和 + 哈希表”：`pre[r+1] - pre[l] = k` 即 `pre[l] = pre[r+1] - k`，扫一遍查表计数，O(n)，与元素正负无关。
