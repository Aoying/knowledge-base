# 字符串算法

以 KMP 为主的深篇。主篇 [数据结构与算法](计算机基础/算法/数据结构与算法.md) 只给了提纲，本篇把 KMP 的 next 数组、匹配过程、复杂度讲透。

## 暴力匹配为什么慢

暴力匹配是每个起始位置逐字符比对，失配就把模式串右移一位、文本指针回退重比。最坏复杂度 O(n·m)，典型惨案是文本一长串 A、模式串末尾一个 B，例如文本 `AAAAAB`、模式 `AAAB`：每个起始位置都要比到末尾才失配。

KMP 的核心思想只有一句话：失配时不回退文本指针，用模式串自身的结构决定模式串回退到哪里。

## next 数组（前缀函数）逐步演示

定义：对模式串 P，pi[i] = P[0..i] 的最长真前后缀相等长度（真 = 不能取整个串）。本文的 next 数组就是 pi 数组。

以 P = `ABABC` 为例，逐步构造：

| i | 当前字符 | 推导 | pi[i] |
|---|---|---|---|
| 0 | A | 约定，单个字符没有真前后缀 | 0 |
| 1 | B | B ≠ P[0] = A，无回退余地 | 0 |
| 2 | A | A = P[0]，j 从 0 涨到 1 | 1 |
| 3 | B | B = P[1]，j 从 1 涨到 2 | 2 |
| 4 | C | C ≠ P[2] = A，回退 j = pi[1] = 0；C ≠ P[0] = A | 0 |

结果：`pi = [0, 0, 1, 2, 0]`。

注意：有的教材把 next 定义为整体右移一位且 next[0] = -1（即 next[i] = pi[i-1]），失配时写 j = next[j]。两种写法等价，抄代码时先对齐定义，不要混用——混用的典型症状是死循环或越界。

## 匹配过程 worked 演示

文本 T = `ABABDABABC`，模式 P = `ABABC`（pi = [0, 0, 1, 2, 0]）：

- i = 0..3：依次匹配 `ABAB`，j 走到 4。
- i = 4：T[4] = D，P[4] = C，失配。j = pi[3] = 2：意思是前 2 个字符 `AB` 已确认对齐，不用重比。
- 仍在 i = 4：T[4] = D，P[2] = A，失配。j = pi[1] = 0。
- 仍在 i = 4：T[4] = D，P[0] = A，失配。j 已为 0，文本指针前进，i = 5。
- i = 5..9：依次匹配 `ABABC`，j 走到 5 = 模式串长度，命中，起始下标 = 10 - 5 = 5。

全程文本指针 i 只前进不回退，这是 KMP 快的根源。

## 代码

```python
def prefix_function(p):
    pi = [0] * len(p)
    j = 0
    for i in range(1, len(p)):
        while j > 0 and p[i] != p[j]:
            j = pi[j - 1]
        if p[i] == p[j]:
            j += 1
        pi[i] = j
    return pi

def kmp_search(t, p):
    pi = prefix_function(p)
    j = 0
    res = []
    for i, ch in enumerate(t):
        while j > 0 and ch != p[j]:
            j = pi[j - 1]
        if ch == p[j]:
            j += 1
        if j == len(p):
            res.append(i - len(p) + 1)
            j = pi[j - 1]
    return res

print(prefix_function("ABABC"))       # [0, 0, 1, 2, 0]
print(kmp_search("ABABDABABC", "ABABC"))  # [5]
```

## 为什么是 O(n+m)

- 文本指针 i 从 0 走到 n-1，只前进不回退：匹配过程最多 n 步。
- 模式指针 j 每次回退都严格减小，而 j 的增长总量不超过 n（匹配过程）或 m（构造过程）；回退总次数被增长总次数兜底，因此构造 O(m)、匹配 O(n)。
- 合起来 O(n + m)，且是确定的最坏保证，不是平均情况。

## 何时不用 KMP

- 单次查找、模式串短、文本不长：直接用内置 `str.find` / `in`，C 实现的常数小，实际更快。
- 模式含通配、字符类、重复结构：用正则，不要手写 KMP。
- KMP 的优势场景：同一模式串反复匹配多段文本、流式输入（边读边匹配）、或需要 O(n+m) 最坏保证的场合。
- 其他算法一句话定位：BM（Boyer-Moore）从后往前比对，靠坏字符与好后缀规则跳步，实际文本中常更快但实现复杂；Rabin-Karp 用滚动哈希批量比对，适合多模式串，但哈希碰撞要二次确认。

## 易错点

- pi 与 -1 版 next 混用：失配回退必须写成 j = pi[j-1]（pi 版）或 j = next[j]（-1 版），写错会死循环或越界。
- 构造时 `while j > 0` 的条件不能丢，否则回退到 0 还继续比对会错。
- 空模式串要先处理：按约定返回空结果，不要让 len(p) = 0 进入主循环。

## 小技巧与冷知识

【小技巧】调 KMP 先打印 pi 数组再追踪 j：实现写完别直接跑大文本，先对模式串打印 pi——"ABABC" 应该是 [0, 0, 1, 2, 0]，对不上就说明构造写错了，问题不在匹配循环里。失配时再打印 j 的回退链（比如 4 → 2 → 0），能一眼看出回退是不是按 pi[j-1] 在走，还是混用了 -1 版 next 的写法。

【小技巧】pi 数组的最后一项直接给出模式串的最小周期：最小周期 = m - pi[m-1]，当 m 能被它整除时，模式串就是该片段的重复。"ABCABCABC" 的 pi 末项是 6，最小周期 9 - 6 = 3；"AAAA" 的 pi 末项是 3，周期 4 - 3 = 1。想判断一个串是不是由某个子串重复构成，不用另写算法，算一次 pi 就够了。

【小技巧】想数“重叠出现”的次数，命中后别把 j 清零：原文代码里命中后写的是 `j = pi[j - 1]` 而不是 `j = 0`，这正是关键——"AA" 在 "AAAA" 里会出现 3 次（下标 0、1、2），因为后一个匹配的开头就藏在前一个匹配的尾巴里。改成 `j = 0` 会漏掉所有重叠出现，只在“不允许重叠”的题里才这么写。

【小技巧】KMP 天生适合流式输入：匹配循环的状态只有 j 一个整数，文本可以一个字符一个字符地喂进来，不用等整段文本到齐。边读网络流、边读文件边匹配的场景，j 就是全部的记忆；文本指针 i 只是计数，丢了也不影响继续匹配。

【小技巧】验证手写 KMP 别只测原文的例子，用随机小串对拍暴力：生成几十组随机的短文本和模式串（长度不超过 8，字母表只取 A、B），把 kmp_search 的结果和逐位比对的暴力结果逐组对比。pi 的边界错误在 "ABABC" 这种例子上可能藏得住，在 "AABAAB" 这类带重复前缀的随机串上几乎必现。

【小技巧】模式串全是重复字符时，暴力最惨、KMP 最赚：文本一长串 A、模式串 "AAAB" 这类例子，暴力每个起始位置都要比到末尾才失配，KMP 的 pi 却让 j 每次只退一格。手写测试用例时先造这种“高重复前缀”的输入，它是区分“真 KMP”和“写错回退的暴力”的试金石。

【小技巧】两种 next 定义可以一张表换算，不用重背两套代码：pi 版 `pi[i]` 是 P[0..i] 的最长真前后缀；-1 版 `next[i] = pi[i-1]`，且 next[0] = -1。抄别人的代码时先看它失配写的是 `j = pi[j-1]` 还是 `j = next[j]`，对上号再抄——原文易错点里说的死循环，十有八九是两种定义混着用了。

【小技巧】生产代码里先用 `str.find`，别急着手写 KMP：单次查找、模式串短时，C 实现的内置查找常数极小，纯 Python 手写 KMP 基本跑不过它。只有同一模式串反复匹配多段文本、流式输入、或明确要求 O(n+m) 最坏保证时，手写 KMP 才有意义；先测再换，别凭感觉换。

【冷知识】KMP 是三个人名的首字母：Donald Knuth、James Morris、Vaughan Pratt，论文《Fast pattern matching in strings》发表于 1977 年。Morris 和 Pratt 在 1970 年就各自独立得到了类似算法，Knuth 从自动机理论的角度重新发现了它——同一个算法被三个人从不同方向撞上，pi 数组本质上就是一台“模式串自动机”的转移表。

【冷知识】pi 数组不只是为匹配服务，它是“前缀函数”，在字符串算法里到处出现：判断重复子串、求最小周期、构造 Aho-Corasick 多模式匹配的失配指针，底层都是同一个前缀函数。学会 pi 等于同时拿到好几道题的钥匙，这也是原文只讲 KMP、却值得深挖 pi 定义的原因。

【冷知识】Boyer-Moore 和 KMP 是同一年发表的：Boyer 和 Moore 的论文也是 1977 年。BM 从后往前比对、靠坏字符规则大步跳，在自然语言文本里通常比 KMP 更快，这也是很多标准库字符串查找不用 KMP 的原因之一——KMP 赢在最坏保证，BM 赢在平均速度。

【冷知识】Rabin-Karp 的名字来自 Michael Rabin 和 Richard Karp，论文发表于 1987 年，比 KMP 晚了十年。它的滚动哈希一次能筛掉绝大多数不匹配位置，适合“同一文本里找很多个模式串”的场景；但哈希碰撞时要二次确认，严格说它给出的最坏复杂度不是 O(n+m)。

【冷知识】KMP 的思想可以反过来用：把“文本 + 分隔符 + 模式串”拼成一个串算 pi，pi 末项就告诉你模式串在文本里最长匹配了多长。这是很多字符串题（比如求最短回文串前缀补全）的标准套路——同一个 pi 函数，换个输入拼接方式就变成另一道题的解法。

【小技巧】空模式串和单字符模式串先单独处理再进主循环：空串按约定返回空结果，单字符模式串的 pi 是 [0]，构造循环一次都不跑。把这两类边界在函数入口处理掉，主循环就不用处处防 `len(p) == 0` 的越界，代码反而更干净——原文易错点只提了空串，单字符同样值得先想清楚。

## 面试与自测

1. KMP 的 next 数组（前缀函数）pi[i] 的定义是什么？为什么失配时 j 可以直接跳到 pi[j-1] 而不用回退文本指针？
2. 文本 `AAAAAB`、模式 `AAAB`，暴力匹配约比多少次字符比较？KMP 是什么量级？
3. 什么情况下不用 KMP，直接用 str.find 或正则？

### 参考答案

1. pi[i] 是模式串 P[0..i] 的最长真前后缀相等长度。失配发生在 P[j] 时，前 j 个字符已确认等于文本对应段；其中 pi[j-1] 长度的前缀与后缀相等，说明这部分前缀已经与文本对齐，无需重比，因此文本指针 i 不回退，只把 j 跳到 pi[j-1]。
2. 暴力约 12 次字符比较（3 个起始位置各比 4 次），最坏量级 O(n·m)；KMP 构造 O(m) + 匹配 O(n)，即 O(n+m)。
3. 单次查找、模式串短、文本不长时，内置 find（C 实现，常数小）足够；模式含通配、字符类、重复结构时用正则。KMP 的优势在同一模式串反复匹配、流式输入、或需要 O(n+m) 最坏保证时。
