# 分治算法

分治是最通用的算法范式之一：归并排序、二分查找、快速幂都是它。本篇讲思想、适用条件和两道典型题；归并排序的具体实现见 [排序算法实现](计算机基础/算法/排序算法实现.md)，主定理的三情况与速查表见 [复杂度分析基础](计算机基础/算法/复杂度分析基础.md)，两处都不重复。

## 分治三步与适用条件

分治 = 分（拆）→ 治（解）→ 合（并）：

1. 分：把规模 n 的问题拆成 a 个规模 n/b 的同类小问题。
2. 治：递归解决小问题；小到一定规模（通常 n ≤ 1）直接给答案，这就是递归出口。
3. 合：把小问题的答案合并成原问题的答案。

成立需要同时满足三条，缺一条就别硬套分治：

- 可拆：原问题能拆成同类小问题（归并拆数组、快速幂拆指数）。
- 独立：小问题之间互不依赖，可以各自算完再合并；小问题互相纠缠时分治失效。
- 合并可行且划算：合并代价不能吃掉分解省下的收益；合并本身 O(n²) 时，分治可能还不如直接解。

## 递归式与主定理的联系

分治的代价天然写成递归式 `T(n) = a·T(n/b) + f(n)`：a 个规模 n/b 的子问题，f(n) 是拆分加合并的代价。判断量级不用每次都展开递归树，直接套主定理：比较 f(n) 和 n^(log_b a) 谁主导——子问题主导、每层相当、合并主导，分别对应三个结果，归并排序 `T(n) = 2T(n/2) + O(n)` 落在“每层相当”的情况，得 Θ(n log n)，这一步已在复杂度篇算过。

主定理不覆盖时（如 f(n) 和 n^p 之间只差一个 log 因子）别硬套，回递归树展开或代入法手推。

## 典型题 1：逆序对（归并计数）

逆序对是 i < j 但 a[i] > a[j] 的二元组。暴力两两比较是 O(n²)；归并计数的 trick 是：合并两个有序段时，右段元素被取走的那一刻，左段剩余元素全都比它大，各成一个逆序对，顺手就数出来了，不增加量级。

```python
def count_inversions(a):
    def sort_count(arr):
        if len(arr) <= 1:
            return arr, 0
        m = len(arr) // 2
        left, inv_l = sort_count(arr[:m])
        right, inv_r = sort_count(arr[m:])
        merged, inv_m = [], 0
        i = j = 0
        while i < len(left) and j < len(right):
            if left[i] <= right[j]:
                merged.append(left[i]); i += 1
            else:
                merged.append(right[j]); j += 1
                inv_m += len(left) - i
        merged += left[i:] + right[j:]
        return merged, inv_l + inv_r + inv_m
    return sort_count(a)[1]

print(count_inversions([2, 4, 1, 3, 5]))  # 3
```

### worked 例

`[2, 4, 1, 3, 5]` 的逆序对是 (2, 1)、(4, 1)、(4, 3)，共 3 个。归并过程中：左段 [2, 4]、右段 [1, 3, 5] 合并时，取 1 之前左段剩 2 个（2、4）→ 记 2 个；取 3 之前左段剩 1 个（4）→ 记 1 个；合计 3，和暴力数出来的结果一致，代价是归并本身的 O(n log n)。

## 典型题 2：快速幂

求 x^n。朴素连乘要 n 次乘法；分治把指数对半拆：x^n = (x^(n/2))²，n 为奇数时再多乘一个 x。指数每递归一次减半，递归深度 log n。

```python
def fast_pow(x, n):
    if n == 0:
        return 1
    half = fast_pow(x, n // 2)
    res = half * half
    if n % 2 == 1:
        res *= x
    return res

print(fast_pow(2, 10))  # 1024
print(fast_pow(3, 5))   # 243
```

- `fast_pow(2, 10)`：10 → 5 → 2 → 1 → 0，4 层递归，乘法次数 O(log n)。
- 递归版直观，迭代版（按二进制位展开指数）同样 O(log n) 且空间 O(1)，工程里优先迭代版；取模场景下每步取模，结果不变，防溢出。
- 同一思路的亲戚：矩阵快速幂（斐波那契 O(log n)）、二分查找（每次排除一半，见总纲二分模板）。

## 分治 vs 动态规划 vs 贪心

| 范式 | 子问题关系 | 核心动作 | 例子 |
| --- | --- | --- | --- |
| 分治 | 相互独立，不重叠 | 拆 → 治 → 合 | 归并、快排、快速幂、逆序对 |
| 动态规划 | 相互重叠，需缓存 | 定义状态 → 转移 → 填表 | 背包、LIS、LCS，见动态规划篇 |
| 贪心 | 每步只看当前 | 选当前最优，期望拼出全局最优 | 活动选择，见贪心算法篇 |

分不清时先问一句：小问题会不会被反复求解？会，就是 DP 的地盘；不会，且能拆能合，就是分治。贪心最危险：每步最优不一定拼出全局最优，能举出反例就别用贪心。

## 易错点

- 递归出口写错或漏写：分治递归没有出口就是无限递归，先写 `n ≤ 1` 的返回再写拆分。
- 合并代价被忽视：合并本身 O(n²) 时，总代价可能被合并主导，分治白分了；先估 f(n) 再动手。
- 拆分不均衡：快排基准选得差时拆成 1 和 n-1，退化成 O(n²)——分治要求拆得比较均匀，至少别每次都只分出一个元素。
- 子问题不独立时硬套分治：结果要么错，要么反复算重叠部分，等于把 DP 的活干成了指数级。

## 小技巧与冷知识

- 【小技巧】找第 k 大不用排全序，用快速选择（quickselect）只治一半：快排 partition 之后，目标在左半就只递归左半、在右半就只递归右半，另一半直接丢掉。平均复杂度 O(n)，比排完再取快得多；最坏仍是 O(n²)，基准选得差时和快排退化是同一个坑。
- 【小技巧】逆序对计数里 `<=` 不能改成 `<`：`left[i] <= right[j]` 时先取左元素，相等元素不算逆序对；改成 `<` 会把相等元素也当成逆序对记进去，计数直接多算。合并时“取右记 `len(left) - i` 个”这条规则成立的前提，就是相等元素永远算左边的。
- 【小技巧】快速幂先在入口处理负指数：x^(-n) = 1 / x^n，负指数要先取倒数再递归。直接把负数丢进 `n // 2` 的递归里，Python 的向下取整会让 -1 永远停在 -1，递归退不出来；Java/C++ 里负数取模的行为又各不相同，索性在入口统一转正。
- 【小技巧】归并排序有自底向上的迭代版：从宽度 1 的小段开始两两合并，宽度每次翻倍，不用递归。分治递归的深度本来就只有 log n，迭代版的意义不在省栈，而是对不方便递归、或者想把合并分段并行化的场景更友好。
- 【小技巧】分治递归的深度只有 log n，栈溢出不用担心：对半拆时 n = 10 亿也只有约 30 层递归。真正要防的是“拆得不均匀”——快排基准选得差、拆成 1 和 n-1 时，深度才变成 n，那时退化的不只是时间，栈也跟着遭殃。
- 【小技巧】合并是分治并行化的瓶颈：子问题相互独立可以并行算，ForkJoin 框架就是这个思路，但最后的合并往往只能串行做。按 Amdahl 定律，串行合并占比决定了并行加速的上限，合并越重，并行收益越小，拆之前先估合并代价。
- 【小技巧】拆分不一定非得对半：Karatsuba 大整数乘法把 n 位乘拆成 3 个 n/2 位乘法，复杂度 O(n^1.585)，比朴素 O(n²) 快。拆成几份看的是“子问题个数 × 规模缩小”的 trade-off，对半拆只是最常见的一种，不是唯一解。
- 【小技巧】逆序对数能当“有序程度”的度量：0 表示完全有序，最大值 n(n-1)/2 表示完全逆序。拿它比较两个版本的数据、或者评估“这组数据离有序有多远”，比“排没排好”的二值判断细得多。
- 【冷知识】归并排序是冯·诺依曼 1945 年发明的：John von Neumann 在 1945 年提出归并排序，是最早达到 O(n log n) 的排序算法之一。分治作为一种算法范式，就是从归并排序这类具体算法里抽象出来的。
- 【冷知识】“分而治之”出自拉丁语 divide et impera：原是罗马的政治格言，意思是分化、瓦解对手再逐个对付，算法借用了这个名字。英文 divide and conquer 直译过来就是它，范式的名字比计算机科学本身古老得多。
- 【冷知识】Karatsuba 在 1960 年推翻了一个“定理级”猜想：Kolmogorov 曾猜想乘法的时间下界就是 O(n²)，Karatsuba 发现了 O(n^1.585) 的分治乘法，直接证伪了这个猜想。一个被大师认定为下界的复杂度，被分治思想打破了。
- 【冷知识】Strassen 在 1969 年把矩阵乘法降到了 O(n^2.81)：Volker Strassen 用分治把 8 次子矩阵乘法减到 7 次，第一次打破了矩阵乘法 O(n³) 的纪录。代价是数值稳定性稍差、常数较大，小矩阵上反而不如朴素算法快。
- 【冷知识】主定理出自 1980 年的一篇论文：Bentley、Haken 和 Saxe 在《A general method for solving divide-and-conquer recurrences》里给出了解决分治递归式的通用方法。原文里“比较 f(n) 和 n^(log_b a)”的三情况划分，就是这篇论文的结论。
- 【冷知识】逆序对数就是 Kendall tau 距离：统计学里衡量两个排序差异的 Kendall tau 距离，定义就是“不一致的二元组个数”，和逆序对是同一个数。算法题里的逆序对计数，换个名字就是统计学里的排序相关性度量。
- 【冷知识】快速幂有个古代亲戚：古埃及乘法（又叫俄罗斯农民乘法）用“倍增 + 加法”做乘法，与快速幂“平方 + 乘法”的思路同构，都是把 O(n) 次操作降到 O(log n)。二进制思想比二进制计算机早了几千年。
- 【冷知识】最近点对是分治的教科书案例：先按 x 坐标排序拆半，合并时只检查中线两侧条带内的有限个点，整体做到 O(n log n)。它的合并步骤比逆序对更讲究——要先按 y 排序再扫条带，漏掉这一步复杂度就退回 O(n²)。

## 面试与自测

1. 分治成立需要同时满足哪三个条件？各举一个违反时的反例。
2. 逆序对用归并计数为什么是 O(n log n)？合并时 `inv_m += len(left) - i` 的含义是什么？
3. 快速幂为什么是 O(log n)？递归版和迭代版各有什么优缺点？

### 参考答案

1. 可拆成同类小问题、子问题相互独立、合并可行且划算。违反的例子：子问题互相依赖（如斐波那契朴素递归反复算重叠项）该用 DP；合并代价 O(n²) 时分治可能不如直接解。
2. 归并框架本身就是 O(n log n)，计数只在合并时顺带做，不增加量级。右段元素被取走时，左段剩余的 `len(left) - i` 个元素全都比它大，各成一个逆序对，一次记这么多个。
3. 指数每递归一次减半，递归深度 log n，每层一次乘法，所以是 O(log n)。递归版直观易写，空间 O(log n) 递归栈；迭代版按二进制位展开，空间 O(1)，工程里优先迭代版。
