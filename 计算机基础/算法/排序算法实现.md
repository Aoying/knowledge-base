# 排序算法实现

日常开发直接用内置 sort 就够了；手写排序的价值在两处：一是面试和考试，二是理解“分治”和“堆”这两个通用思想。下面三个是最常考的：快排、归并、堆排。

## 快排：分区是全部

快排 = 选一个基准（pivot），把数组分成“小于基准”和“大于基准”两半（分区 partition），再递归排两半。分区是 O(n)，递归深度平均 O(log n)，所以平均 O(n log n)。

Lomuto 分区（取最后一个元素为基准）的逐步演示，数组 `[5, 2, 9, 1, 7, 6]`，基准 6：

```text
i 指向“小于区”的末尾（初始 -1），j 从左扫到右：
j=0: 5 < 6，i -> 0，交换 a[0] 自己，数组 [5, 2, 9, 1, 7, 6]
j=1: 2 < 6，i -> 1，交换 a[1] 自己，数组 [5, 2, 9, 1, 7, 6]
j=2: 9 不小于 6，跳过
j=3: 1 < 6，i -> 2，交换 a[2] 与 a[3]，数组 [5, 2, 1, 9, 7, 6]
j=4: 7 不小于 6，跳过
最后把基准换到 i+1 = 3 处：[5, 2, 1, 6, 7, 9]
左半 [5, 2, 1] 继续排，右半 [7, 9] 继续排。
```

```python
def partition(a, lo, hi):
    pivot = a[hi]
    i = lo - 1
    for j in range(lo, hi):
        if a[j] < pivot:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[hi] = a[hi], a[i + 1]
    return i + 1

def quicksort(a, lo=0, hi=None):
    if hi is None:
        hi = len(a) - 1
    if lo < hi:
        p = partition(a, lo, hi)
        quicksort(a, lo, p - 1)
        quicksort(a, p + 1, hi)
    return a

a = [5, 2, 9, 1, 7, 6]
partition(a, 0, len(a) - 1)
print(a)  # 一次分区后的结果
print(quicksort([5, 2, 9, 1, 7, 6]))
```

### worked 例

```text
一次分区后：[5, 2, 1, 6, 7, 9]（基准 6 落在最终位置 3）
完整快排后：[1, 2, 5, 6, 7, 9]
```

### 基准选择与最坏情况

- 固定取首/尾元素：数组已有序时每次只分出一个元素，递归深度 n，退化成 O(n²)。
- 三数取中（首、中、尾的中位数）：缓解有序输入的最坏情况，工程常用。
- 随机基准：期望 O(n log n)，最坏仍是 O(n²) 但概率极低；很多标准库用这个思路。
- 快排不稳定：分区交换会打乱相等元素的原始顺序；需要稳定时别用它。

## 归并：分治的教科书

归并 = 把数组对半分到只剩一个元素（天然有序），再两两合并。合并两个有序段时用双指针，谁小取谁；左段相等元素先取，保证稳定性。

```python
def merge(left, right):
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:  # <= 而不是 <，相等时取左段 -> 稳定
            out.append(left[i])
            i += 1
        else:
            out.append(right[j])
            j += 1
    return out + left[i:] + right[j:]

def mergesort(a):
    if len(a) <= 1:
        return a
    m = len(a) // 2
    return merge(mergesort(a[:m]), mergesort(a[m:]))

print(merge([1, 4, 7], [2, 5, 6]))
print(mergesort([5, 2, 9, 1, 7, 6]))
```

### worked 例

```text
merge([1, 4, 7], [2, 5, 6]) = [1, 2, 4, 5, 6, 7]
mergesort([5, 2, 9, 1, 7, 6]) = [1, 2, 5, 6, 7, 9]
```

归并时间恒为 O(n log n)（与输入顺序无关），空间 O(n)（合并需要辅助数组），稳定。代价是额外内存和非原地操作，数据量极大时不如快排/堆排。

## 堆排：堆化是关键

堆排 = 先把数组建成最大堆（堆顶即最大值），再反复把堆顶换到末尾、堆规模减一、对新堆顶下沉。建堆是 O(n)（不是 O(n log n)，因为大部分节点在底层，下沉路径短），每次取顶 O(log n)，共 n 次，所以总 O(n log n)，空间 O(1)，不稳定。

堆化过程（自底向上，从最后一个非叶节点开始下沉），数组 `[5, 2, 9, 1, 7, 6]`：

```text
下标：0:5 1:2 2:9 3:1 4:7 5:6，最后一个非叶节点是下标 2
节点 2 (9)：孩子 6，不用换
节点 1 (2)：孩子 1、7，换成 7 -> [5, 7, 9, 1, 2, 6]
节点 0 (5)：孩子 7、9，换成 9 -> [9, 7, 5, 1, 2, 6]，再对节点 2 (5) 下沉：孩子 6，换 -> [9, 7, 6, 1, 2, 5]
建堆完成：[9, 7, 6, 1, 2, 5]
```

```python
def sift_down(a, i, n):
    while True:
        largest, l, r = i, 2 * i + 1, 2 * i + 2
        if l < n and a[l] > a[largest]:
            largest = l
        if r < n and a[r] > a[largest]:
            largest = r
        if largest == i:
            return
        a[i], a[largest] = a[largest], a[i]
        i = largest

def heapsort(a):
    n = len(a)
    for i in range(n // 2 - 1, -1, -1):
        sift_down(a, i, n)
    heapified = list(a)
    for end in range(n - 1, 0, -1):
        a[0], a[end] = a[end], a[0]
        sift_down(a, 0, end)
    return heapified, a

h, s = heapsort([5, 2, 9, 1, 7, 6])
print(h)
print(s)
```

### worked 例

```text
建堆后：[9, 7, 6, 1, 2, 5]
堆排后：[1, 2, 5, 6, 7, 9]
```

## 三者对比

| 维度 | 快排 | 归并 | 堆排 |
| --- | --- | --- | --- |
| 平均时间 | O(n log n) | O(n log n) | O(n log n) |
| 最坏时间 | O(n²)（基准选得差） | O(n log n) | O(n log n) |
| 空间 | O(log n) 递归栈 | O(n) 辅助数组 | O(1) 原地 |
| 稳定性 | 不稳定 | 稳定 | 不稳定 |
| 适用场景 | 通用最快，常数小 | 要求稳定、链表排序、外排序 | 内存受限、求 Top K 变形 |

## 何时直接用内置 sort

- Python 的 `sorted` / `list.sort` 是 Timsort（归并 + 插入的混合），稳定、平均和最坏都是 O(n log n)，日常一律用它。
- 手写排序只出现在三种场合：面试、教学、以及内置 sort 不满足的特殊约束（如不允许额外内存又要最坏保证时选堆排、链表排序时选归并）。
- 不要为“快一点”手写快排：标准库实现经过充分调优，手写版本通常更慢且更容易写出最坏情况。

## 线性时间排序：不比较大小，数数和分桶

上面三种都是比较排序，下界 O(n log n)。数据有额外结构时可以更快：

- 计数排序：数据是非负整数且范围 k 不大时，数每个值出现几次，再按顺序展开。时间 O(n + k)，空间 O(k)，稳定。范围 k 远大于 n 时内存爆炸，不能用。
- 桶排序：把数据分到 m 个桶里，桶内再排序。数据均匀分布时接近 O(n)，分布不均时退化到桶内排序的复杂度。
- 基数排序：按位（个位、十位、百位……）从低位到高位做多轮稳定排序，每轮可用计数排序。时间 O(d × (n + k))，d 是位数。子排序必须稳定，否则高位会冲掉低位的结果。

对照：

| 方法 | 时间 | 额外空间 | 稳定 | 前提 |
| --- | --- | --- | --- | --- |
| 计数排序 | O(n + k) | O(k) | 是 | 非负整数、k 不大 |
| 桶排序 | 平均 O(n) | O(n + m) | 取决于桶内排序 | 数据分布均匀 |
| 基数排序 | O(d × (n + k)) | O(n + k) | 是（子排序稳定时） | 定长 key、可按位拆分 |

易错点：计数排序的 k 是值域大小不是 n；基数排序从低位往高位排，顺序反了结果就错；桶排序的最坏情况和桶内算法有关，不是无条件 O(n)。

## 比较次数与内存定量：快排、归并、堆排算一算

前面只给了大 O，面试常追问一句：“n = 10000 时到底比较多少次？”下面是本地实测 + 理论对照。先把口径说死，否则数字没法比：

- **比较次数**：快排 = 每次“元素与基准比较”；归并 = 合并时每次“左右两段队首元素比较”；堆排 = 下沉时每次“子节点与当前最大值比较”。
- **交换/移动次数**：快排、堆排计元素交换；归并计每次往辅助数组写一个元素。
- **实现**：三个算法都按原文思路手写（快排取首元素作基准的 Lomuto 分区、归并自顶向下、堆排自底向上建堆 + 反复取顶），三种实现都通过了“排序结果等于 Python 内置 sorted”的校验。
- **输入**：每档 n 用同一批随机整数（`random.seed(20261111)`，值域 0～10⁹），三种算法跑同一份输入；另测一组“已排好序 + 首元素基准”的快排最坏情况。

### 实测表：比较次数与交换/移动次数

| n | 算法 | 比较次数（实测） | 交换/移动（实测） | 理论比较次数 | 实测/理论 |
| --- | --- | --- | --- | --- | --- |
| 100 | 快排 | 613 | 292 | 约 923 | 0.66 |
| 100 | 归并 | 541 | 672 | 约 700 | 0.77 |
| 100 | 堆排 | 1011 | 580 | 约 1329 | 0.76 |
| 1000 | 快排 | 11062 | 5561 | 约 13852 | 0.80 |
| 1000 | 归并 | 8711 | 9976 | 约 10000 | 0.87 |
| 1000 | 堆排 | 16862 | 9089 | 约 19932 | 0.85 |
| 10000 | 快排 | 154672 | 73768 | 约 184699 | 0.84 |
| 10000 | 归并 | 120395 | 133616 | 约 140000 | 0.86 |
| 10000 | 堆排 | 235235 | 124032 | 约 265754 | 0.89 |

理论值换算口径（来源见文末）：快排平均约 1.39·n·log₂n；归并约 n·⌈log₂n⌉（偏上界的估算口径）；堆排约 2n·log₂n（偏上界的估算口径）。n = 10000 时 log₂n ≈ 13.29，例如快排理论值 1.39 × 10000 × 13.29 ≈ 184699，与表中数字一致。

读表注意三点：

1. **实测都比理论系数小**（比值 0.66～0.89），因为理论系数是偏保守的上界口径，不是精确期望；n 越大比值越接近 1，是因为常数项的影响被摊薄了。
2. **堆排的比较次数最多**：n = 10000 时堆排 235235 次，约是快排 154672 次的 1.5 倍、归并 120395 次的约 2 倍。堆排每次下沉要比较左右两个子节点，比较次数天然比快排、归并多，这是它“同为 O(n log n) 却常数最大”的直接体现。
3. **归并的移动次数 ≈ n·⌈log₂n⌉**：n = 10000 时移动 133616 次，接近理论 140000——每层归并都要把 n 个元素搬一次，共约 log₂n 层，搬运量是实打实的。

### 快排最坏情况：实测与理论完全吻合

已排好序的输入 + 首元素作基准时，实测比较次数与 n(n-1)/2 分毫不差：

| n | 比较次数（实测） | 理论 n(n-1)/2 | 交换次数 | 最大递归深度 |
| --- | --- | --- | --- | --- |
| 100 | 4950 | 4950 | 0 | 100 |
| 1000 | 499500 | 499500 | 0 | 1000 |

交换次数是 0：已有序时没有元素小于基准，分区一次也不交换，只白白比较。n = 10000 的最坏情况本次未实测（递归深度 10000，Python 默认递归栈扛不住，需改迭代实现；理论值 n(n-1)/2 = 49995000，可直接由公式算出）。

### 内存定量：辅助空间与递归栈

| 算法 | 额外空间 | n = 10 万 | n = 100 万 |
| --- | --- | --- | --- |
| 归并 | O(n) 辅助数组 | 800000 字节 ≈ 0.76 MiB | 8000000 字节 ≈ 7.63 MiB |
| 快排 | O(log n) 递归栈（平均），最坏 O(n) | 栈深约 17 层 | 栈深约 20 层 |
| 堆排 | O(1) 原地 | 只有几个临时变量 | 只有几个临时变量 |

换算口径：辅助数组按“每元素 8 字节指针”估算（64 位系统上一个 Python 对象引用占 8 字节，这是下限口径；真实 Python 列表里每个元素还是对象本身，实际内存只会更大）。n = 100 万时 1000000 × 8 = 8000000 字节，8000000 ÷ 1024 ÷ 1024 ≈ 7.63 MiB；n = 10 万时 100000 × 8 = 800000 字节 ≈ 0.76 MiB。

快排递归深度实测（随机输入）：n = 100 时最深 12 层，n = 1000 时 23 层，n = 10000 时 33 层；都大于 log₂n（6.6 / 10.0 / 13.3），因为分区并不总是对半分，深度是“最不走运的那条递归路径”，不是平均深度。原文小技巧里“只递归小的一半、大的一半改循环”就是把这个深度压回 O(log n) 的办法；不做这一步，最坏输入下深度就是 n（上表最坏情况 n = 1000 时深度 1000），栈先爆掉。

### 边界条件

1. **比较次数与输入分布强相关**：同一算法、同一 n，换一组输入数字就变。表里的数字只对“随机均匀输入”成立；近乎有序、大量重复、逆序输入下三者的比较次数会系统性偏离（快排最坏直接到 n² 量级，归并基本不动）。
2. **理论系数只在随机输入下成立**：1.39·n·log₂n 是快排在随机排列下的期望比较次数（Sedgewick 经典结论）；输入不是随机排列时不能直接套用这个系数。
3. **Timsort 对近乎有序输入有加速**：Python 的 `list.sort` 会检测已有的有序片段（run）直接利用，近乎有序时比较次数远低于 n·log₂n；所以“归并约 n·⌈log₂n⌉”是对纯归并说的，不能套到 Timsort 头上。
4. **计数器实现方式会影响“比较”口径**：比如堆排下沉时“先比左孩子、再比右孩子”是两次比较，换一种写法（一次比较定胜负再比父节点）数字就不同；跨资料对比比较次数时，必须先对齐计数口径，否则数字没有可比性。
5. **辅助空间的 8 字节是下限口径**：归并在 Python 里对 int 对象排序时，每个元素本身是对象（小整数约 28 字节起），辅助数组 7.63 MiB 只是“指针部分”；算真实内存占用要把元素对象本身也算进去（经验口径，未逐项实测）。
6. **n 很小时大 O 会说谎**：n = 100 时堆排比较次数（1011）比快排（613）多 65%，但绝对差距只有约 400 次，现代 CPU 上不到一微秒；小数据上真正决定速度的是常数和缓存，不是比较次数——这也是原文说“小区间切插入排序”的原因。

### 小结

- 同为 O(n log n)，n = 10000 随机输入下比较次数：归并（约 12.0 万）< 快排（约 15.5 万）< 堆排（约 23.5 万）；堆排多花的比较次数换来的是 O(1) 空间和最坏情况保证。
- 快排最坏情况不是理论吓唬人：已有序 + 首元素基准时，n = 1000 就实打实比较 499500 次，是随机输入（11062 次）的 45 倍。
- 内存上归并最贵：n = 100 万要多 7.63 MiB 辅助空间（指针口径下限）；内存受限时选堆排，想省比较次数又接受额外内存时选归并。

来源与核验（2026-11-11）：理论系数出自 CLRS《算法导论》第 7 章（快排期望比较次数约 2n·ln n ≈ 1.39·n·log₂n、最坏 n(n-1)/2）与 Sedgewick《Algorithms》（快排平均比较次数、堆排约 2n·log₂n 的上界分析）；Timsort 行为出自 Python 官方文档（`list.sort` 使用 Timsort，稳定）；表中全部实测数字由本地 python3 跑三份手写实现得出（随机种子 20261111，n = 100/1000/10000），内存字节数由 n × 8 换算得出。快排最坏 n = 10000 未实测，见上文说明。

## 实战案例

### 案例一：海量数据求 Top K——100 万条记录只要最大的 100 条

以下为设计演练示例。

- **场景**：一份 100 万条的分数/热度记录，只需要最大的 100 条，不需要把全部记录排好序。内存紧张，不能为了求 Top K 先把全量排一遍再取前 100 条。
- **选型分析**：先排除全量归并——按原文定量口径，归并在 n = 100 万时要多占约 7.63 MiB 辅助空间（指针口径下限，真实内存只会更大），只为取 100 条不值。再排除“快排排全量再取前 K”——快排平均很快，但最坏是 O(n²)，原文实测已有序 + 首元素基准时 n = 1000 就比较 499500 次，是随机输入 11062 次的 45 倍，输入分布一变就可能踩坑。选堆的变形：维护一个大小为 K 的小顶堆，只留当前最大的 K 条，空间 O(K)，最坏也有保证。这正是原文三者对比表里“堆排适用场景：内存受限、求 Top K 变形”的落点。顺带说清代价：同为 O(n log n) 时堆排的比较次数本来就最多，原文实测 n = 10000 随机输入下堆排 235235 次，约是快排 154672 次的 1.5 倍、归并 120395 次的约 2 倍——Top K 只建 K 大小的堆、每条记录最多比较一次堆顶，比较次数随 K 收敛，不按全量堆排的数字算。
- **实现要点**：先取前 K 条建成小顶堆（堆顶是这 K 条里最小的）；之后每条新记录只与堆顶比一次，比堆顶大就替换堆顶并下沉，比堆顶小直接丢弃；最后把堆里 K 条排好序输出。关键片段（伪代码，只写选型相关的核心逻辑，不重复原文的完整堆排实现）：

```text
heap = 前 K 条建成的小顶堆        # 堆顶 = 当前 Top K 里最小的
for x in 其余记录:
    if x > heap[0]:              # 只与堆顶比较一次
        heap[0] = x
        sift_down(heap, 0, K)   # 下沉恢复堆性质，见原文堆排一节
return sorted(heap, reverse=True)
```

- **复盘**：K 远小于 n 时，这道题的瓶颈不在“排序多快”，而在“别为 K 条结果付出 O(n) 的额外内存和全量排序的代价”。小顶堆把空间压到 O(K)、把每条记录的比较压到一次堆顶比较（进入堆的记录还要下沉调整，另计 O(log K)，但只有进堆的记录才付这笔），是选型上最划算的一处。反模式是先 `sorted(全部记录)` 再切片：结果一样，内存和比较次数都白白放大；K 接近 n 时（比如要前 50%）这招的优势就没了，直接全量排序更省事。

### 案例二：接近有序的数组——日志时间戳基本有序、偶尔乱几条

以下为设计演练示例。

- **场景**：一批按时间戳追加的日志，基本有序，只有少量记录因时钟 skew 或并发写入乱了顺序，需要排好序后按时间回放。
- **选型分析**：别上快排。原文实测写得明白：已有序 + 首元素基准时快排比较次数与 n(n-1)/2 分毫不差，n = 1000 时 499500 次、最大递归深度 1000，栈先爆掉的风险是实打实的；换随机基准或三数取中能缓解，但对“基本有序”这个输入仍不是最对路的打法。原文小技巧一节也点了题：近乎有序的数据用插入排序或 Timsort，Timsort 会检测已有的有序片段（run）直接利用，近乎有序时比较次数远低于 n·log₂n。日常开发直接用 Python 的 `list.sort` / `sorted`（Timsort，稳定），不要手写快排；只有面试或教学场合才需要手写。
- **实现要点**：生产代码只有一行，选型本身就是实现：

```python
logs.sort(key=lambda r: r["ts"])  # Timsort：稳定，复用已有的有序片段
```

如果这段逻辑要落在“手写排序”的面试题里，答法是：先说明输入近乎有序、快排最坏 O(n²) 的风险（引用原文 n = 1000 最坏 499500 次的实测），再写插入排序处理小范围错位——每条记录只往前挪到它该在的位置，有序部分一次比较就过，接近 O(n)；或说明 Timsort 的 run 检测思路。不要反过来先写快排再补一句“输入有序时会退化”。
- **复盘**：选型先看输入分布，再看算法。同一份 n = 10000 的随机输入，快排比较 154672 次、归并 120395 次、堆排 235235 次，三者差距不到 2 倍；但输入一换成已有序，快排直接跳到 n(n-1)/2 量级，差距变成几十倍。面试追问“为什么不用快排”时，答“最坏情况 + 输入分布”比背时间复杂度表更有说服力。

### 案例三：数据放不进内存——外排序，磁盘上的大文件怎么排

以下为设计演练示例。

- **场景**：一个几十 GB 的大文件要按 key 排好序，内存一次只能装下其中一小部分，全量读进内存排序这条路不存在。
- **选型分析**：快排和堆排先出局——原文小技巧一节写得直接，两种算法的随机访问在磁盘上会慢到没法用。归并是主力：它的“顺序读、顺序写”正好贴合磁盘特性。内存定量也支持这个选择：归并每层都要把 n 个元素搬一次，原文实测 n = 10000 时移动 133616 次、接近理论 n·⌈log₂n⌉ ≈ 140000，搬运量是实打实的——所以外排序要把搬运次数压到最少，核心是“分块在内存里排好、落盘成有序 run，再多路归并逐轮合并”，而不是反复随机读写。
- **实现要点**：两步走，不贴完整归并实现，只写外排序特有的骨架（伪代码）：

```text
# 第 1 步：分块排序，内存装得下多少读多少
while 文件还有未读数据:
    chunk = 读入一块（内存能装下的量）
    chunk.sort()              # 块内用内置 sort（Timsort）
    写回磁盘，记为一个有序 run

# 第 2 步：多路归并，逐轮合并
while run 的个数 > 1:
    取一批 run，用小顶堆维护各 run 当前队首
    每次取堆顶最小元素写入输出 run，顺序读、顺序写
    一批 run 合并成一个更大的有序 run
```

关键点有三条：块内排序用内置 sort，别手写；多路归并用堆维护各 run 的队首，每次只比较堆顶，不把所有 run 全读进内存；合并轮数由一次能同时打开的 run 数决定，run 数越少、轮数越少，搬运总量越小。
- **复盘**：外排序的选型逻辑和内存排序是反过来的：内存排序比的是比较次数（n = 10000 时归并约 12.0 万 < 快排约 15.5 万 < 堆排约 23.5 万），外排序比的是磁盘搬运次数和访问模式——归并赢在“顺序读写 + 稳定 + 最坏 O(n log n)”，输在“额外内存和搬运量”，而外排序恰好把“额外内存”换成了磁盘上的 run，把搬运摊到逐轮合并里。面试时先说“数据在哪”再说“选哪个算法”，顺序别反。

## 小技巧与冷知识

【小技巧】Lomuto 分区之外还有 Hoare 分区：Hoare 取首元素做基准，双指针从两头向中间扫，交换次数比 Lomuto 少得多。但它返回的不是基准的最终位置，而是“左半 ≤ 基准、右半 ≥ 基准”的分界点，递归要写成 `quicksort(lo, p)` 和 `quicksort(p + 1, hi)`，照 Lomuto 的 `p - 1 / p + 1` 套会漏元素或死循环。

【小技巧】快排递归只排小的一半、大的一半改循环：先递归处理较小的分区，再用 while 循环继续处理较大的分区，递归栈深度被压到 O(log n)。这叫尾递归优化，是标准库快排防栈溢出的标准写法；不做这一步，有序输入下递归深度就是 n，栈先爆掉。

【小技巧】重复元素多时用三路分区：把数组分成“小于、等于、大于”基准的三段，等于基准的那段不再递归，这就是 Dijkstra 提出的荷兰国旗问题解法。元素只有几种取值时（比如大量 0、1、2），三路分区接近 O(n)，而普通快排会在等于基准的元素上反复分区，退化得很惨。

【小技巧】小区间切插入排序是混合排序的标配：子数组长度小于阈值（常见取 16 左右）时直接用插入排序，别再递归分治。插入排序常数小、缓存友好，小数据上比快排、归并都快；标准库的混合排序（introsort、Timsort、pdqsort）全是这个套路。

【小技巧】多关键字排序用稳定排序排两次：先按次要关键字排，再按主要关键字排，第二次排序不会打乱第一次排好的次要顺序。这招只对稳定排序有效，快排、堆排排两次会把第一次的结果冲掉；需要“先按分数、分数相同按姓名”时，先排姓名、再排分数。

【小技巧】计数排序也能处理负数：先找出最小值 min，所有值减去 min 再计数，展开时再加回来。k 是“值域跨度”（max - min + 1）而不是最大值本身；值域跨度不大就能用，跨度大到几亿时内存照样爆炸。

【小技巧】基数排序分 LSD 和 MSD 两种：LSD 从低位往高位排，每轮子排序必须稳定，否则高位会冲掉低位的结果；MSD 从高位往低位排，可以递归处理每个桶，子排序不用稳定，但要处理大量空桶。原文讲的是 LSD，面试追问 MSD 时别把两者的要求搞反。

【小技巧】链表排序别手写快排：链表没有下标，分区要反复遍历找基准位置，写起来别扭还慢；归并排序的切分和合并在链表上只需要改指针，不需要额外数组。链表题里“排序”两个字出现，第一反应就该是归并。

【小技巧】数据放不进内存时归并是主力：外排序把数据分块读进内存排好、写回磁盘，再做多路归并逐轮合并，归并的“顺序读、顺序写”正好贴合磁盘特性。快排和堆排的随机访问在磁盘上会慢到没法用，选算法前先看数据在哪。

【小技巧】近乎有序的数据别上快排：插入排序在近乎有序的输入上接近 O(n)，Timsort 专门检测已有的有序片段（run）直接利用。日志、时间戳这类“基本有序、偶尔乱几条”的数据，用插入排序或 Timsort 比快排快得多，这也是标准库不直接用纯快排的原因之一。

【冷知识】C++ 的 std::sort 不是纯快排，是 introsort：David Musser 在 1997 年提出，快排递归深度超过 2 倍 log n 就切到堆排兜底，最坏 O(n log n) 有保证，小区间切插入排序。名字里的 intro 是 introspective（自省）的缩写——算法会“盯着”自己的递归深度，失控就换打法。

【冷知识】Timsort 是 Tim Peters 在 2002 年为 Python 写的：它先找数据里天然的有序片段（run），长度不够 32 就用插入排序补成最小 run 长度（minrun 在 32 到 64 之间），再按规则归并这些 run。Java 的对象数组排序后来也采用了 Timsort，名字里的 Tim 就是作者的名字。

【冷知识】Java 的 Arrays.sort 对基本类型和对象用的是两套算法：基本类型用 Vladimir Yaroslavskiy 在 2009 年提出的双基准快排（Dual-Pivot Quicksort，Java 7 引入），对象数组用 Timsort。基本类型不需要稳定、要速度，对象数组要稳定保证，这个分工是刻意的。

【冷知识】Go 和 Rust 近年都换过默认排序：Go 1.19 把 sort 换成 Orson Peters 的 pdqsort（pattern-defeating quicksort），对有序、重复元素多的输入做了专门优化；Rust 在 2024 年把稳定排序换成 driftsort、不稳定排序换成 ipnsort。标准库的排序算法不是一成不变的，隔几年就有人把它换掉。

【冷知识】比较排序的 O(n log n) 下界来自决策树：n 个元素的排列有 n! 种，每次比较只有两种结果，决策树至少要 log2(n!) 层，按斯特林公式约等于 n log2 n − 1.44n。所以“比较排序最快就是 O(n log n)”不是经验，是信息论的硬上限；想更快只能像计数、基数排序那样不比较大小。

【冷知识】第 k 小元素有最坏 O(n) 的选法：Blum、Floyd、Pratt、Rivest、Tarjan 在 1973 年提出中位数的中位数（median of medians）算法，分组找中位数再递归，保证最坏线性时间。它是快排“随机基准”思路的反面——不靠运气、靠构造保证，但常数大，工程上还是随机基准更常见。

## 面试与自测

1. 快排在什么输入下退化成 O(n²)？怎么缓解？
2. 归并为什么稳定，快排为什么不稳定？
3. 堆排建堆为什么是 O(n) 而不是 O(n log n)？
4. 归并排序 n = 100 万时要多占多少内存？为什么工程上大数据排序常不用纯归并？

### 参考答案

1. 已有序（或逆序）且固定取首/尾元素做基准时，每次分区只分出一个元素，递归深度 n，总代价 O(n²)。缓解：三数取中或随机基准。
2. 归并在合并时相等元素取左段先出，原始相对顺序不变，所以稳定；快排分区时的远距离交换会把相等元素换到彼此前面，顺序被打乱，所以不稳定。
3. 建堆从最后一个非叶节点自底向上做下沉，底层节点占一半以上且下沉路径短（叶子层路径为 0），总代价是 n/2·0 + n/4·1 + n/8·2 + … 的级数求和，收敛到 O(n)。
4. 按每元素 8 字节指针估算，辅助数组约 7.63 MiB（1000000×8÷1024÷1024），真实 Python 对象还要更大。工程上大数据常选快排或 Timsort：快排原地、常数小，Timsort 能利用已有有序片段；纯归并的 O(n) 额外内存和搬运量在内存紧张时是硬伤。
