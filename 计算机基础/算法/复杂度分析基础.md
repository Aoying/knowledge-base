# 复杂度分析基础

复杂度分析回答一个问题：输入规模 n 变大时，算法的代价怎么增长？它不关心某台机器跑多快，只关心增长趋势——趋势对了，换机器只是常数倍的差别。

## 大 O、Ω、Θ：上界、下界、紧界

设 f(n) 是算法的真实代价（步数），g(n) 是用来比较的量级：

- f(n) = O(g(n))：存在常数 c 和 n0，使 n ≥ n0 时 f(n) ≤ c·g(n)。读作“不超过 g 的量级”，是上界。
- f(n) = Ω(g(n))：存在常数 c 和 n0，使 n ≥ n0 时 f(n) ≥ c·g(n)。读作“至少 g 的量级”，是下界。
- f(n) = Θ(g(n))：既是 O 又是 Ω，即 f(n) 被 c1·g(n) 和 c2·g(n) 夹住。读作“差不多就是 g 的量级”，是紧界。

例子：`f(n) = 2n² + 3n + 1`。n 充分大时，n² 项主导一切：

```text
f(n) = O(n²)，因为 2n² + 3n + 1 ≤ 3n²（n ≥ 2 时）
f(n) = Ω(n²)，因为 2n² + 3n + 1 ≥ 2n²
所以 f(n) = Θ(n²)
```

直觉：O 回答“最坏能坏到哪”，Ω 回答“最好也得花多少”，Θ 回答“本质就是这个量级”。日常说“这个算法是 O(n log n)”时，通常说的是最坏情况的上界。

## 常见量级对照

| 量级 | 典型场景 | n = 10 | n = 100 | n = 1000 |
| --- | --- | --- | --- | --- |
| O(1) | 哈希查表、数组下标访问 | 1 | 1 | 1 |
| O(log n) | 二分查找、平衡树操作 | ~3 | ~7 | ~10 |
| O(n) | 一次遍历 | 10 | 100 | 1000 |
| O(n log n) | 快排、归并、堆排 | ~33 | ~665 | ~9966 |
| O(n²) | 双重循环、冒泡 | 100 | 10000 | 1000000 |
| O(2ⁿ) | 暴力子集枚举 | 1024 | 天文数字 | 不可算 |
| O(n!) | 暴力全排列 | 3628800 | 不可算 | 不可算 |

看表的关键一列是 n = 1000：O(n²) 已到百万量级，O(2ⁿ) 完全不可算。量级差一级，规模一大就是成百上千倍的差距，常数优化追不回来。

## 主定理：分治递归式速查

分治算法常写成 `T(n) = a·T(n/b) + f(n)`：分出 a 个规模 n/b 的子问题，合并代价 f(n)。记 `p = log_b(a)`：

- 情况 1：f(n) 明显小于 n^p（即 f(n) = O(n^(p-ε))），子问题主导 → T(n) = Θ(n^p)。
- 情况 2：f(n) 与 n^p 同量级（f(n) = Θ(n^p)），每层代价相当 → T(n) = Θ(n^p · log n)。
- 情况 3：f(n) 明显大于 n^p（f(n) = Ω(n^(p+ε))）且满足正则条件（a·f(n/b) ≤ c·f(n)，c < 1），合并主导 → T(n) = Θ(f(n))。
- 扩展情形：f(n) = Θ(n^p · log^k n) 时，T(n) = Θ(n^p · log^(k+1) n)。

例子：

```text
归并排序：T(n) = 2T(n/2) + O(n)，p = log2(2) = 1，f(n) = Θ(n^1) -> 情况 2 -> Θ(n log n)
二分查找：T(n) = T(n/2) + O(1)，p = log2(1) = 0，f(n) = Θ(n^0) -> 情况 2 -> Θ(log n)
```

主定理不是万能的：有些递推式不在上述情形里，例如 `T(n) = 2T(n/2) + n / log n`——f(n) 与 n^p 之间只差一个 log 因子，既不是多项式级更小，也不是 n^p 乘 log 的幂次形式，主定理不覆盖，只能用递归树展开或代入法手推，不要硬套。

## 摊还分析：贵操作被摊薄

摊还分析看的是“一连串操作”的总代价，不是单次最坏。经典例子是动态数组扩容（容量满时翻倍）：

```python
capacity, size, copies = 1, 0, 0
for _ in range(16):  # 连续 push 16 次
    if size == capacity:
        copies += size  # 扩容时把旧元素全拷一遍
        capacity *= 2
    size += 1
print("copies:", copies)
```

### worked 例

```text
16 次 push 的扩容拷贝：1 + 2 + 4 + 8 = 15 次（容量 1->2->4->8->16 时各拷一次）
总代价 = 16 次写入 + 15 次拷贝 < 2n，所以均摊到每次 push 是 O(1)
一般规律：n 次 push 的拷贝总和是 1 + 2 + 4 + ... + n/2 < 2n，永远是 O(n)
```

关键区别：摊还 O(1) 是“最坏序列上的平均保证”，不是概率平均；单次 push 最坏仍是 O(n)（恰好撞上扩容那次），但连续 n 次的总账一定是 O(n)。

## 摊还分析的三方法


### 方法一：聚合分析法（上面例子用的就是它）

直接算 n 次操作的总代价，再除以 n。动态数组：n 次 push 的写入是 n，扩容拷贝是 1 + 2 + 4 + … + n/2 < n，总代价 < 2n，均摊每次 O(1)。优点是直观，缺点是总代价不好算时就卡住了。

### 方法二：记账法（给便宜操作多收费）

给每种操作定一个摊还价（可以高于实际价），多收的部分存为存款，贵操作发生时用存款支付。只要存款余额始终不为负，摊还价就是可信的上界。

动态数组的记账方式：每次 push 收 3 元——1 元付本次写入，2 元存起来。上次扩容后表里有 m/2 个元素，之后每次插入存 2 元，到再次扩容（表满 m 个元素）时恰好存够 m 元，正好支付 m 个元素的拷贝费。于是每次 push 的摊还代价是 3，即 O(1)。

### 方法三：势能法（给数据结构记一笔“欠账”）

定义势函数 Φ(D)，度量当前数据结构离“便宜状态”有多远。摊还代价 = 实际代价 + Φ 的变化量（ΔΦ）。势函数必须满足两条：初态 Φ = 0，且任何状态 Φ ≥ 0——这样摊还代价之和 ≥ 实际代价之和，摊还价才作数。

动态数组取 Φ = 2·元素数 − 容量（从空表起算）：

```text
不扩容的 push：实际代价 1，Φ 增加 2，摊还代价 = 1 + 2 = 3
扩容的 push（容量 m 扩到 2m）：实际代价 m + 1（拷贝 m 个 + 写 1 个）
  扩容前 Φ = 2m − m = m，扩容后 Φ = 2(m+1) − 2m = 2
  摊还代价 = (m + 1) + (2 − m) = 3
两种情况摊还代价都是 3，即 O(1)
```

三种方法怎么选：能直接算总账用聚合；操作种类少、贵操作有明确“攒钱”逻辑用记账；状态复杂、想用一个函数统一度量用势能。日常分析扩容、二进制计数器这类问题，聚合最顺手；势能法是三者里最通用的，难在势函数要自己构造。

## 分析常见误区

- 只看最好情况：快排最好 O(n log n) 但最坏 O(n²)，选型要看最坏和平均，不能只看最好。
- 混淆最坏与平均：哈希表查找平均 O(1)，但冲突退化时最坏 O(n)；说“哈希是 O(1)”时默认说的是平均。
- 忽略常数项的适用范围：n 很小时，O(n²) 的小常数实现可能比 O(n log n) 的大常数实现更快；量级比较只在 n 充分大时成立。
- 只算时间不算空间：归并时间 O(n log n) 但空间 O(n)，内存受限时可能不如堆排的 O(1)；递归深度也要算进空间（如快排递归栈 O(log n)）。
- 把 O 记号当成精确运行时间：O(n) 的两个算法实际耗时可能差几十倍（常数、缓存、分支预测都不在记号里），记号只管增长趋势。

## 面试与自测

1. `f(n) = 3n² + 100n + 50` 是 O(n²)、Ω(n²)、Θ(n²) 中的哪几个？为什么？
2. 动态数组扩容的均摊 O(1) 和“平均 O(1)”有什么区别？
3. 主定理情况 2 里为什么会多出一个 log n 因子？

### 参考答案

1. 三个都是。n 充分大时 n² 项主导：上界 `3n² + 100n + 50 ≤ 4n²`（n 充分大时成立）所以是 O(n²)；下界 `≥ 3n²` 所以是 Ω(n²)；两者都有即 Θ(n²)。
2. 均摊是确定性保证：任意连续 n 次 push 的总代价都是 O(n)，与输入无关；“平均”通常指概率意义下的期望，需要假设输入分布。扩容的 O(1) 是均摊，不是期望。
3. 因为情况 2 里每一层的合并代价都是 Θ(n^p)，而递归树恰好有 log_b(n) 层，每层同量级的代价加起来就是 n^p × 层数，即 Θ(n^p · log n)。
