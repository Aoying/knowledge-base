# 回溯算法

回溯是“试探着走，撞墙就退回上一步换条路”的穷举。解空间是一棵树：每个节点是一个部分解，叶子是完整解；从根往下试探，某条路走不通（违反约束）就回退到父节点换分支。回溯的精髓不在“递归”本身，而在剪枝——提前砍掉整棵不可能的子树，穷举才跑得动。

## 回溯模板三件套

写回溯先定三样东西，再套模板：

1. 路径：当前已经选了什么（列表）。
2. 选择列表：当前这一步还能选什么。
3. 结束条件：路径什么时候算一个完整解。

```python
def backtrack(路径, 选择列表):
    if 满足结束条件:
        记录结果
        return
    for 选择 in 选择列表:
        做选择            # 路径.append(选择)
        backtrack(路径, 新的选择列表)
        撤销选择          # 路径.pop()，这一步叫回溯
```

“撤销选择”是回溯和普通 DFS 最大的区别：同一条路径列表在不同分支间复用，走完一个分支必须把状态恢复干净，否则下一个分支会带上上个分支的残留。

## 经典题 1：全排列

给 `[1, 2, 3]`，输出全部 6 种排列。解空间是排列树：第一层 3 个选择，第二层各剩 2 个，第三层各剩 1 个，叶子 3×2×1 = 6 个。

```python
def permute(nums):
    res, path, used = [], [], [False] * len(nums)

    def dfs():
        if len(path) == len(nums):
            res.append(path.copy())
            return
        for i, x in enumerate(nums):
            if used[i]:
                continue
            used[i] = True
            path.append(x)
            dfs()
            path.pop()          # 回溯：撤销选择
            used[i] = False

    dfs()
    return res

perms = permute([1, 2, 3])
print(len(perms))   # 6
print(perms[0], perms[-1])   # [1, 2, 3] [3, 2, 1]
```

## 经典题 2：子集

给 `[1, 2, 3]`，输出全部 8 个子集。解空间是子集树：每个元素只有“选 / 不选”两条分支，叶子 2³ = 8 个。这里每个节点（不只是叶子）都是一个解，所以每进一个节点就记录一次。

```python
def subsets(nums):
    res, path = [], []

    def dfs(start):
        res.append(path.copy())   # 每个节点都是一个解
        for i in range(start, len(nums)):
            path.append(nums[i])
            dfs(i + 1)
            path.pop()            # 回溯：撤销选择

    dfs(0)
    return res

subs = subsets([1, 2, 3])
print(len(subs))   # 8
print(subs)        # [[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]
```

注意 `dfs(i + 1)` 里传的是 `i + 1` 不是 `start + 1`：这保证每个元素只在它之后的元素里继续选，不会重复选同一个元素，也不会出现 `[2, 1]` 这种与 `[1, 2]` 重复的顺序。

## 经典题 3：N 皇后

n×n 棋盘放 n 个皇后，互不攻击（不同行、不同列、不同对角线）。按行往下放，每行选一列；剪枝条件是新皇后与已放皇后不同列、不同对角线（同一行天然不冲突，因为一行只放一个）。

```python
def solve_n_queens(n):
    res, cols, diag1, diag2, path = [], set(), set(), set(), []

    def dfs(row):
        if row == n:
            res.append(path.copy())
            return
        for col in range(n):
            if col in cols or (row - col) in diag1 or (row + col) in diag2:
                continue          # 剪枝：这格会冲突，整棵子树砍掉
            cols.add(col); diag1.add(row - col); diag2.add(row + col)
            path.append(col)
            dfs(row + 1)
            path.pop()            # 回溯：撤销选择
            cols.remove(col); diag1.remove(row - col); diag2.remove(row + col)

    dfs(0)
    return res

solutions = solve_n_queens(4)
print(len(solutions))   # 2
print(solutions[0])     # [1, 3, 0, 2]：第 0 行放 1 列，第 1 行放 3 列……
```

n = 4 只有 2 解；n = 8 是 92 解。N 皇后的剪枝效果很直观：不剪枝要试 4⁴ = 256 种放法（每行 4 列），剪枝后实际搜索节点远少于这个数。

## 剪枝技巧

- 约束剪枝：还没走到底就发现违反约束，立刻回退（N 皇后的列/对角线检查就是）。
- 排序 + 跳过重复：输入有重复元素时（如子集 II、组合总和 II），先排序，同一层遇到与上一个相同的元素直接跳过，避免重复解。
- 限界剪枝：带最优目标时（如背包求最大值），用乐观上界判断当前分支有没有可能超过已知最优解，没可能就砍掉。
- 对称性剪枝：N 皇后里镜像对称的解只算一次时可减半（竞赛题常用，工程题一般不做）。

## 回溯、DFS、动态规划的关系

| 关系 | 说明 |
| --- | --- |
| 回溯 vs DFS | 回溯就是带剪枝和“撤销选择”的 DFS；DFS 只管遍历，回溯多了一层“这条路不用再走了”的判断 |
| 回溯 vs DP | 回溯是穷举所有可能解（指数级），DP 是把重叠子问题的答案记下来避免重复算（多项式级）；同一道题两种都可能写，但适用条件不同 |
| 什么时候用回溯 | 题目要求“列出所有解”（全排列、子集、N 皇后、组合总和），而不是“求最优值” |
| 复杂度直觉 | 最坏是分支数 ^ 深度（如全排列 O(n!)、子集 O(2ⁿ)）；剪枝决定实际跑多快，剪枝写不好就退化成纯暴力 |

## 实战案例

### 案例一：全排列——漏掉一行撤销，6 种变 1 种

现象：输入 `[1, 2, 3]`，原文 §2 的 `permute` 应输出全部 6 种排列，首个 `[1, 2, 3]`、末个 `[3, 2, 1]`。某次改动后程序不报错，却只输出 1 种 `[1, 2, 3]`，少了 5 种（`6 - 1 = 5`）。

排查：复用原文 §2 的代码，只删掉撤销处的 `used[i] = False` 这一行（`path.pop()` 仍在），其余写法不变，本地运行：

```python
def permute_no_undo_used(nums):
    res, path, used = [], [], [False] * len(nums)

    def dfs():
        if len(path) == len(nums):
            res.append(path.copy())
            return
        for i, x in enumerate(nums):
            if used[i]:
                continue
            used[i] = True
            path.append(x)
            dfs()
            path.pop()
            # 漏掉了 used[i] = False

    dfs()
    return res

print(permute_no_undo_used([1, 2, 3]))   # 本地运行输出：[[1, 2, 3]]，共 1 个
```

第一条分支走完 `[1, 2, 3]` 后回退：`path` 被 `pop` 空了，但 `used` 三项全是 `True`、没恢复，之后任何分支都在 `if used[i]: continue` 处被跳过，搜索树在第一片叶子之后就再也长不出新分支。原文 §1 已说明“走完一个分支必须把状态恢复干净，否则下一个分支会带上上个分支的残留”，本例就是这句话的实测。

结论：做选择与撤销选择必须成对、顺序相反（原文小技巧节同样要求“做选择处有几处状态修改，撤销处就该有几处恢复”）；漏一行撤销不报错，只会静默丢解，本例丢 5 种（`6 - 1 = 5`）。原文未展开：只漏掉 `path.pop()`、保留 `used[i] = False` 时的结果，原文未展开，不作定论。

### 案例二：N 皇后——n = 4 只有 2 解，不剪枝要试 256 种

现象：4×4 棋盘放 4 个皇后，直觉上放法很多，原文 §4 说只有 2 解；不剪枝每行 4 列，要试 `4⁴ = 256` 种放法。

排查：本地运行原文 §4 的代码，`solve_n_queens(4)` 返回 2 解，第一解 `[1, 3, 0, 2]` 与原文一致，第二解 `[2, 0, 3, 1]` 是本地运行得出（原文只给出第一解）。第一解验算：第 0 行 1 列、第 1 行 3 列、第 2 行 0 列、第 3 行 2 列，列号 1、3、0、2 互不相同；`row - col` 为 -1、-2、2、1，互不相同；`row + col` 为 1、4、2、5，互不相同，三组检查都通过。第二解验算：列号 2、0、3、1 互不相同；`row - col` 为 -2、1、-1、2，互不相同；`row + col` 为 2、1、5、4，互不相同，同样通过。另本地运行 `solve_n_queens(8)` 返回 92，与原文“n = 8 是 92 解”一致。

剪枝起作用的位置在“放之前”：每放一个皇后先检查列与两条对角线（原文 §4 代码 `if col in cols or (row - col) in diag1 or (row + col) in diag2: continue`），冲突分支整棵砍掉，256 种放法里绝大部分根本没走到叶子。剪枝后实际搜索节点数原文只说“远少于”256，未给具体数字，原文未展开，不作定论。

结论：2 解与 256 种放法之间差的，就是剪枝砍掉的冲突分支；剪枝写在“放之前”（先检查再递归）而不是“放完再验”，是回溯跑得动的关键，与原文 §5“约束剪枝：还没走到底就发现违反约束，立刻回退”的说法一致。原文未展开：n = 12、n = 13 的解数原文冷知识节给出 14200、73712（位掩码程序验证），但本文 set 版代码跑 n = 12、n = 13 的耗时与解数原文未展开，此处不作复核定论。

## 小技巧与冷知识

【小技巧】回溯写崩了先别盯着代码看，拿 n = 3、n = 4 的小输入手推搜索树：每进一层打印带缩进的当前 path，退回时也打印，搜索树的形状一目了然。大多数回溯 bug（多记、漏记、重复解）都在小输入上就能复现，没必要等 n = 8 才发现。

【小技巧】记录结果时一定要 `res.append(path.copy())`，不能直接 append path：path 是全部分支共用的同一条列表，之后还会继续 append/pop，直接 append 存进去的是引用，最终结果里所有条目都会变成最后一次回溯完的空列表。原文三道经典题的代码都用了 copy，抄模板时这行最容易被顺手省掉。

【小技巧】“做选择”和“撤销选择”必须严格成对、顺序相反：append 对应 pop、used 置 True 对应置 False、集合 add 对应 remove，漏掉其中任何一个，残留状态就会污染下一个分支。写完先数一遍：做选择处有几处状态修改，撤销处就该有几处恢复，数量对不上就是 bug。

【小技巧】有重复元素的去重条件要写全：同层跳过重复元素是 `i > start and nums[i] == nums[i-1]`，`i > start` 这一半不能省。只写 `nums[i] == nums[i-1]` 会把“同一分支内第二次用这个值”也剪掉，合法解就丢了；`i > start` 的作用正是只跳过同层重复、不碰同分支的重复使用。

【小技巧】组合类题目的 start 参数语义决定元素能不能重用：元素可重复使用时递归传 i（下一层还能从自己开始选），不可重复时传 i + 1。原文子集题讲的是后一种；组合总和（元素可重复）用的就是前一种，传错一个参数，答案要么重复要么缺失。

【小技巧】题目只要求“找一个解”时，找到就立刻短路返回，别搜完全部：让 dfs 返回 bool，找到解返回 True，父层收到 True 后直接返回、不再试下一个分支。N 皇后只求一组解时，这样能省掉绝大部分搜索量；求全部解时才需要跑满整棵树。

【小技巧】剪枝条件按“便宜的先查”排序：列冲突、对角线冲突这种 O(1) 判断放前面，限界剪枝里算乐观上界这种贵操作放后面。剪枝本身也有成本，先被便宜检查砍掉的分支，就不用再付贵检查的代价；顺序反了，剪枝省的时间可能还不够付检查的账。

【小技巧】n 比较大时留意 Python 的递归深度：默认递归上限约 1000 层，回溯深度等于 n，n 上千就会触发 RecursionError。深搜索要么改显式栈版，要么调 `sys.setrecursionlimit`——但调上限只是延后问题，层数再深会受 C 栈限制，显式栈才是稳妥解法。

【小技巧】计数类回溯遇到重叠子问题可以加记忆化：同样的“剩余状态”被反复搜到时，用 `functools.lru_cache` 把结果记下来，下次直接返回。这一步本质上就是往动态规划靠——回溯负责枚举，记忆化负责去重，组合总和计数这类题用上后复杂度能从指数级降下来。

【小技巧】N 皇后 n 较大时把三个 set 换成位掩码：列、两条对角线各用一个整数的位表示占用情况，冲突检查变成几次位运算，速度比集合版快一个量级。原文的 set 版 n = 8 够用，但 n = 12、13 时位掩码版仍能快速跑完，集合版会明显变慢。

【冷知识】八皇后问题是 1848 年国际象棋棋手 Max Bezzel 提出的，高斯、Nauck 等数学家都研究过它；92 个解去掉旋转、镜像等对称重复后，本质上不同的解只有 12 个。原文说的“n = 8 是 92 解”只是计数，去掉对称才是“真正不同的摆法”。

【冷知识】"backtrack"（回溯）这个词是数学家 D. H. Lehmer 在 1950 年代造出来的：他用它描述“试探失败就退回上一步”的搜索方式，之后才成了算法领域的通用术语。回溯作为思想比这个名字古老得多，名字却是计算机时代的产物。

【冷知识】N 皇后的解数长得比直觉快：n = 8 是 92 解，n = 12 是 14200 解，n = 13 是 73712 解（已用位掩码程序验证）。解数爆炸的速度，就是回溯“穷举所有解”这个定位的代价——n 稍大一点，求全部解就不再现实，只能转而求一个解或用启发式方法。

【冷知识】全排列的爆炸速度可以用阶乘直接感受：10 个元素的全排列是 10! = 3628800 种，12 个元素是约 4.79 亿种；子集数 2^n 同理，n = 30 时子集约 10.7 亿个。看到 n!、2^n 这种复杂度，先算一算 n = 20、30 时的数量级，再决定要不要穷举。

【冷知识】逻辑编程语言 Prolog 的执行机制就是带回溯的深度优先搜索：程序按子句顺序试探，失败就自动回溯换下一条子句。写回溯算法时那种“试一条路、不行就退回换一条”的感觉，在 Prolog 里是语言内置的，不用自己写递归和撤销。

【冷知识】1972 年，Edsger Dijkstra 用八皇后问题讲结构化程序设计，写了一份非常详细的深度优先回溯算法描述。这道题能成为回溯的代名词，很大程度上是因为 Dijkstra 把它当作“结构化编程威力”的示范——回溯的每一步都有清晰的不变式可讲。

## 面试与自测

1. 回溯模板里的“撤销选择”为什么不能省？省了会出什么问题？
2. 子集问题里 `dfs(i + 1)` 为什么传 `i + 1` 而不是 `start + 1`？
3. 同一道题，回溯和动态规划分别在什么情况下更合适？

### 参考答案

1. 不能省。同一条路径列表在不同分支间复用，走完一个分支不撤销，下一个分支会带上上个分支的残留选择，得到错误解或重复解；`used` 标记同理，不恢复会把后续分支的可选元素错误地锁死。
2. 传 `i + 1` 保证每个元素只在它之后的元素里继续选：既不会重复选同一个元素，也不会出现 `[2, 1]` 这种与 `[1, 2]` 顺序不同但内容相同的重复解。传 `start + 1` 会让每一层都从固定位置重选，产生重复和遗漏。
3. 题目要求“列出所有解”时用回溯（全排列、子集、N 皇后）；题目要求“最优值/计数”且有重叠子问题和最优子结构时用 DP；回溯最坏指数级，DP 是多项式级，能用 DP 就别用回溯穷举。
