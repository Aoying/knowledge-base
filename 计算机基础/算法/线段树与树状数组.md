# 线段树与树状数组

前缀和与差分只解决静态问题：一旦数组会变，前缀和每次修改都要 O(n) 重算。线段树和树状数组解决的正是“边改边查”的动态区间问题：单点修改、区间查询都是 O(log n)。

## 线段树：把区间二分到底

思想：每个节点存一段区间的聚合值（这里以区间和为例），根节点是整个数组，左右孩子各管一半，一直分到叶子（单个元素）。查询区间和时，把区间拆成 O(log n) 个已算好的节点相加；单点修改时，从叶子一路向上更新 O(log n) 个节点。

- 建树：O(n)，每个元素恰好进一个叶子，内部节点由孩子相加。
- 区间查询：O(log n)，最坏拆成约 2·log n 个节点。
- 单点修改：O(log n)，叶子到根一条链。
- 区间修改：朴素做法会退化成 O(n)，要靠懒标记。

实现上常用两种写法：递归版直观（节点编号、区间 [l, r]），迭代版（把原数组垫到 2 的幂长度放进一棵满二叉树）更短更快。下面是迭代版区间和：

```python
class SegTree:
    def __init__(self, nums):
        n = 1
        while n < len(nums):
            n *= 2
        self.n = n
        self.t = [0] * (2 * n)
        for i, x in enumerate(nums):
            self.t[n + i] = x
        for i in range(n - 1, 0, -1):
            self.t[i] = self.t[2 * i] + self.t[2 * i + 1]

    def point_update(self, idx, value):
        i = self.n + idx
        self.t[i] = value
        i //= 2
        while i:
            self.t[i] = self.t[2 * i] + self.t[2 * i + 1]
            i //= 2

    def range_sum(self, l, r):  # 闭区间 [l, r]
        l += self.n
        r += self.n
        s = 0
        while l <= r:
            if l % 2 == 1:
                s += self.t[l]
                l += 1
            if r % 2 == 0:
                s += self.t[r]
                r -= 1
            l //= 2
            r //= 2
        return s

st = SegTree([1, 3, 5, 7, 9, 11])
print(st.range_sum(1, 4))  # 3+5+7+9
st.point_update(2, 6)      # 数组变为 [1, 3, 6, 7, 9, 11]
print(st.range_sum(1, 4))  # 3+6+7+9
```

### worked 例

`nums = [1, 3, 5, 7, 9, 11]`：

```text
range_sum(1, 4) = 3 + 5 + 7 + 9 = 24
point_update(2, 6) 后 range_sum(1, 4) = 3 + 6 + 7 + 9 = 25
```

## 懒标记：区间修改的直觉

区间修改（如 [l, r] 全部 +10）如果一路改到叶子就是 O(n)。懒标记的直觉是“先记账、后下放”：当修改区间恰好覆盖某个节点时，不再往下走，只把“这个节点代表的区间都要 +10”记在该节点上，同时把节点存的和直接加上 `10 × 区间长度`。以后查询经过该节点时，再把账“下推”给两个孩子（孩子的和同样加上，孩子的懒标记累加）。

关键点只有两个：

- 记账时必须同步更新节点存的聚合值，否则查询会读到旧值。
- 下推时是“累加”不是“覆盖”，因为同一节点可能被多次区间修改命中。

```python
class LazySegTree:
    def __init__(self, nums):
        self.n = len(nums)
        self.sum = [0] * (4 * self.n)
        self.lazy = [0] * (4 * self.n)
        self._build(1, 0, self.n - 1, nums)

    def _build(self, node, l, r, nums):
        if l == r:
            self.sum[node] = nums[l]
            return
        m = (l + r) // 2
        self._build(node * 2, l, m, nums)
        self._build(node * 2 + 1, m + 1, r, nums)
        self.sum[node] = self.sum[node * 2] + self.sum[node * 2 + 1]

    def _push(self, node, l, r):
        if self.lazy[node] and l != r:
            m = (l + r) // 2
            for child, cl, cr in ((node * 2, l, m), (node * 2 + 1, m + 1, r)):
                self.lazy[child] += self.lazy[node]
                self.sum[child] += self.lazy[node] * (cr - cl + 1)
            self.lazy[node] = 0

    def range_add(self, node, l, r, ql, qr, v):
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr:
            self.lazy[node] += v
            self.sum[node] += v * (r - l + 1)
            return
        self._push(node, l, r)
        m = (l + r) // 2
        self.range_add(node * 2, l, m, ql, qr, v)
        self.range_add(node * 2 + 1, m + 1, r, ql, qr, v)
        self.sum[node] = self.sum[node * 2] + self.sum[node * 2 + 1]

    def query(self, node, l, r, ql, qr):
        if qr < l or r < ql:
            return 0
        if ql <= l and r <= qr:
            return self.sum[node]
        self._push(node, l, r)
        m = (l + r) // 2
        return (self.query(node * 2, l, m, ql, qr)
                + self.query(node * 2 + 1, m + 1, r, ql, qr))

lst = LazySegTree([1, 3, 5, 7, 9, 11])
lst.range_add(1, 0, 5, 1, 3, 10)  # [1, 3, 5, 7, 9, 11] -> [1, 13, 15, 17, 9, 11]
print(lst.query(1, 0, 5, 0, 5))
print(lst.query(1, 0, 5, 1, 3))
```

### worked 例

`[1, 3, 5, 7, 9, 11]`，区间 `[1, 3] += 10` 后数组为 `[1, 13, 15, 17, 9, 11]`：

```text
query(0, 5) = 1 + 13 + 15 + 17 + 9 + 11 = 66
query(1, 3) = 13 + 15 + 17 = 45
```

## 树状数组：只做前缀和，但极简

树状数组（Fenwick 树）只解决前缀和问题，但代码只有十几行、常数极小。核心是 `lowbit`：

```text
lowbit(x) = x & (-x)   # 取 x 的最低位 1 代表的值，如 lowbit(12) = 4
```

下标从 1 开始。`c[i]` 存的是一段区间和：从 `i - lowbit(i) + 1` 到 `i`。于是：

- 单点修改 `add(i, delta)`：`c[i]` 加上 delta，然后 `i += lowbit(i)` 往上爬，直到越界。
- 前缀和 `prefix(i)`：`i` 处取值，然后 `i -= lowbit(i)` 往下降，累加。
- 区间和 `sum(l, r) = prefix(r) - prefix(l - 1)`。

两者都是 O(log n)，因为每次 lowbit 跳变至少去掉一个二进制位。

```python
class Fenwick:
    def __init__(self, nums):
        self.n = len(nums)
        self.c = [0] * (self.n + 1)
        for i, x in enumerate(nums, start=1):
            self.add(i, x)

    def add(self, i, delta):
        while i <= self.n:
            self.c[i] += delta
            i += i & (-i)

    def prefix(self, i):
        s = 0
        while i > 0:
            s += self.c[i]
            i -= i & (-i)
        return s

fw = Fenwick([1, 3, 5, 7, 9, 11])
print(fw.prefix(4))   # 1+3+5+7
fw.add(3, 2)          # a[3] 由 5 变 7
print(fw.prefix(4))   # 1+3+7+7
```

### worked 例

`a = [1, 3, 5, 7, 9, 11]`（1-based），树状数组内部：

```text
c[1] = 1, c[2] = 1+3 = 4, c[3] = 5, c[4] = 1+3+5+7 = 16, c[5] = 9, c[6] = 9+11 = 20
prefix(4) = c[4] = 16
add(3, 2) 后：c[3] = 7，c[4] = 18，prefix(4) = 18
```

### 区间修改、点查询：差分技巧

树状数组本身只支持单点修改，但套一层差分就能做“区间修改、点查询”：区间 `[l, r] += v` 等价于差分数组上 `d[l] += v`、`d[r+1] -= v`，点查询 `a[i]` 就是差分数组的前缀和。代价仍是 O(log n)。

```python
class Fenwick:
    def __init__(self, n):
        self.n = n
        self.c = [0] * (n + 1)

    def add(self, i, delta):
        while i <= self.n:
            self.c[i] += delta
            i += i & (-i)

    def prefix(self, i):
        s = 0
        while i > 0:
            s += self.c[i]
            i -= i & (-i)
        return s

orig = [1, 3, 5, 7, 9, 11]
bit = Fenwick(len(orig))
bit.add(2, 10)   # 区间 [2, 4] += 10 的差分起点
bit.add(5, -10)  # 差分终点（r+1 = 5）
print(orig[2] + bit.prefix(3))  # a[3] 原值 5 + 10
```

## 两者对比

| 维度 | 线段树 | 树状数组 |
| --- | --- | --- |
| 区间查询 + 单点修改 | O(log n) | O(log n) |
| 区间修改 + 区间查询 | O(log n)（懒标记） | 需两个树状数组的公式推导，复杂 |
| 区间修改 + 点查询 | O(log n) | O(log n)（差分技巧） |
| 非求和聚合（最值、gcd） | 天然支持 | 只适用于可逆运算（和、异或），最值不行 |
| 实现难度 / 内存 | 较高，递归版约 4n 空间 | 极低，n + 1 空间，常数小 |
| 适用场景 | 通用动态区间问题 | 只需前缀和、追求简洁快速时首选 |

## 常见误区

- 树状数组下标必须从 1 开始：0 的 lowbit 是 0，会死循环。
- 线段树递归版数组开 4n 不是 2n：最坏情况下节点数接近 4n，开小了会越界。
- 懒标记下推时是累加不是覆盖；查询前忘了下推会读到未更新的孩子值。
- 区间修改区间查询用树状数组要推两个数组的公式，推不出来时直接用线段树，别硬套。

## 小技巧与冷知识

【小技巧】树状数组也可以 O(n) 建树，不用逐个 add：先把原数组抄进 c（c[i] = a[i]），再从 i = 1 到 n 把 c[i] 累加进 c[i + lowbit(i)]，越界跳过。逐个 add 建树是 O(n log n)，这招一遍就建好；不过只在“初始数组已知”时有用，之后动态插入仍要走 add。

【小技巧】树状数组找“前缀和首次 ≥ k 的下标”不用二分套 prefix：从最高位的 2 的幂开始往下试（倍增/二进制提升），一次 O(log n) 直接定位。求第 k 小、按权重随机采样都用这招；注意它只适用于非负数的前缀和，前缀和单调、倍增才有意义。

【小技巧】区间修改 + 区间查询用树状数组要两棵树：只套一层差分只能做区间改、点查；想同时区间查和，得再加一棵树维护系数，增量部分的前缀和公式是 prefix(x) = x·sum(B1, x) − sum(B2, x)，再叠加原数组的前缀和。推不出来、记不住公式时直接上带懒标记的线段树，原文对比表也是这个结论。

【小技巧】线段树也可以不递归：迭代版把原数组垫到 2 的幂放进一棵满二叉树，叶子从下标 n 开始，区间查询用“左奇加、右偶加、双双除以 2”的循环。写熟了比递归版短、还省函数调用开销；但它做不了懒标记——区间修改还是要递归版。

【小技巧】线段树上可以直接“二分”找位置：想找“第一个 ≥ x 的位置”或“第一个满足条件的前缀”，从根往下走，比较左孩子的聚合值后决定去左还是去右，O(log n) 一次定位。别先把整段查出来再线性扫，树本身就是一棵可二分的索引。

【小技巧】懒标记“赋值”和“加法”混用时要分两套 tag：加法 tag 是累加，赋值 tag 是覆盖；下推赋值时要先清掉孩子已有的加法 tag，否则旧的加法会在赋值后又被算一次。只处理“区间加”的题一个 tag 够用，题目一旦出现“区间赋值为 v”，就要先想清两套 tag 的下推顺序。

【小技巧】树状数组的下标从 1 开始不是习惯，是 lowbit(0) = 0 会死循环：add 里的 `i += i & -i` 在 i = 0 时原地不动。下标 0 的数据要整体平移一位再建树；想用 0 下标版树状数组，lowbit 的定义和循环条件都要改，别只改下标。

【小技巧】求逆序对数时树状数组比归并排序好写：数值离散化后从右往左扫，每个数查询“比它小的数已出现几个”就是它贡献的逆序对数，累加即答案。比如 [3, 1, 2] 从右往左：2 贡献 0，1 贡献 0，3 贡献 2，总共 2 个。需要“动态插入 + 实时查逆序对”时归并排序做不了，树状数组可以。

【小技巧】线段树节点存什么决定它能回答什么：求和存 sum、求最值存 max、求最大子段和要同时存“区间和、前缀最大、后缀最大、子段最大”四项。聚合信息设计是线段树题的核心——合并规则写得出，树就搭得起来；写不出合并规则，先别急着建树。

【小技巧】递归版线段树开 4n 是“够用”不是“恰好”：满二叉树最坏节点数不到 4n，开 4n 是留了余量的保险写法；迭代版垫到 2 的幂后只需要 2n。n = 10^5 时递归版约 4×10^5 个节点，迭代版垫到 2^17 后约 2.6×10^5，两者都远小于“每层都开满”的直觉，别在空间上纠结。

【冷知识】树状数组是 1994 年 Peter M. Fenwick 发表的：论文《A New Data Structure for Cumulative Frequency Tables》，最初是为“累计频数表”设计的——统计每个值出现几次、查排名、找中位数这类问题。名字里的 Fenwick 就是作者的姓，BIT（Binary Indexed Tree）是后来更常用的叫法。

【冷知识】线段树比树状数组早近二十年：Jon Bentley 在 1977 年的论文《Solutions to Klee's rectangle problems》里首次描述了它，原本是用来解决矩形面积并这类几何问题的。区间求和只是它最常见的用法，出生时它是几何工具。

【冷知识】树状数组能做的不只是求和：任何满足“可逆”的运算都能套同一套 lowbit 跳法，比如区间异或（异或是自己的逆运算）。最值、GCD 不行——GCD 虽然能合并，但区间 GCD 不能从两个前缀 GCD 相减得到，所以原文说“只适用于可逆运算”。

【冷知识】区间取 min/max 也有线段树打法，叫“线段树 Beats”：它在每个节点多维护区间最大值、次大值和最大值的个数，只对最大值那批元素下推取 min 操作，均摊下来每次操作接近 O(log n)。这是 2014 年左右才在竞赛圈成熟的技巧，比懒标记晚了几十年，复杂度证明也比懒标记难得多。

【冷知识】二维树状数组做矩形求和是 O(log²n)：外层按行跳 lowbit，内层每行再挂一棵一维树状数组。矩形和 = 四个前缀和容斥，和二维前缀和的公式长得一样，只是前缀和的查询本身变成 O(log²n)。数据会变时二维前缀和每次修改要 O(n²) 重算，二维树状数组改一个点只要 O(log²n)。

【冷知识】lowbit 的名字直译是“最低位”：lowbit(x) = x & (-x) 依赖补码表示下 -x 的低位结构，这个技巧在 C 语言里写成 `x & -x`、在 Python 里同样成立。树状数组整棵树的跳跃、建树、查询全靠这一个位运算撑着——数据结构的名字里没有它，但实现里处处是它。

## 面试与自测

1. 只有单点修改和区间求和查询时，选线段树还是树状数组？为什么？
2. 懒标记下推时为什么是累加而不是覆盖？
3. 树状数组能求区间最大值吗？为什么？

### 参考答案

1. 选树状数组。两者复杂度同为 O(log n)，但树状数组代码只有十几行、常数和内存都更小；线段树的优势（通用聚合、懒标记区间修改）在这里用不上。
2. 因为同一节点可能被多次区间修改命中，每次修改都要叠加到已有的懒标记上；覆盖会丢掉之前未下推的修改，导致孩子值算错。
3. 不能。树状数组的区间查询依赖 `prefix(r) - prefix(l-1)` 这种可逆运算，最值没有逆运算（知道 [1, r] 的最大值推不出 [l, r] 的最大值），所以最值查询必须用线段树。
