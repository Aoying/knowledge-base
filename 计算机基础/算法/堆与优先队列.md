# 堆与优先队列

堆是“总能最快拿到最大/最小元素”的结构，优先队列是它的接口名。本篇讲 heapq、TopK、合并 K 路、数据流中位数；堆排的建堆与下沉见 [排序算法实现](计算机基础/算法/排序算法实现.md)，堆优化 Dijkstra 见 [图算法深篇](计算机基础/算法/图算法深篇.md)，两处都不重复。

## 堆结构一句话

堆是完全二叉树，用数组存：下标从 0 开始，父节点 `(i-1) / 2`，左孩子 `2i + 1`，右孩子 `2i + 2`（总纲里已给）。大顶堆是每个节点都不小于孩子，堆顶即最大值；小顶堆反之。插入放末尾再上浮，删堆顶把末尾元素挪到顶再下沉，各 O(log n)。

Python 的 heapq 是小顶堆，只提供 heappush / heappop / heapreplace，没有 decrease-key（改 key 要重新入堆，旧项靠过期判断跳过——图篇 Dijkstra 里 `d != dist[u]` 那行就是这个套路）。

## TopK：大小为 k 的小顶堆

求前 k 大：维护一个大小 k 的小顶堆，堆顶就是当前第 k 大；来一个新元素，比堆顶大就换掉堆顶，比堆顶小就扔掉。结束时堆里 k 个就是答案。

```python
import heapq

def topk(nums, k):
    h = []
    for x in nums:
        if len(h) < k:
            heapq.heappush(h, x)
        elif x > h[0]:
            heapq.heapreplace(h, x)
    return sorted(h, reverse=True)

print(topk([5, 2, 9, 1, 7, 6], 3))              # [9, 7, 6]
print(heapq.nlargest(3, [5, 2, 9, 1, 7, 6]))   # [9, 7, 6]
```

### worked 例

`[5, 2, 9, 1, 7, 6]` 取前 3 大：堆先装 5、2、9（堆顶 2）；来 1，比堆顶小，扔；来 7，比堆顶大，换掉 2，堆顶变 5；来 6，比堆顶大，换掉 5，堆里是 6、7、9；排序输出 `[9, 7, 6]`。

复杂度 O(n log k)：每个元素最多一次堆操作；k 远小于 n 时比全排序 O(n log n) 省得多。k 接近 n 时别折腾，直接排序。日常直接用 `heapq.nlargest / nsmallest`，它内部就是这个思路（k 小时用堆，k 大时切回排序）。

## 合并 K 个有序链表

K 路已排序，归并成一路：堆里始终放每路当前的第一个元素，每次弹出最小的追加到结果，再把该路的下一个元素推进堆。堆大小恒为 K，取元素 O(log K)。

```python
import heapq

def merge_k_sorted(lists):
    h = []
    for i, lst in enumerate(lists):
        if lst:
            heapq.heappush(h, (lst[0], i, 0))
    out = []
    while h:
        v, i, j = heapq.heappop(h)
        out.append(v)
        if j + 1 < len(lists[i]):
            heapq.heappush(h, (lists[i][j + 1], i, j + 1))
    return out

print(merge_k_sorted([[1, 4, 7], [2, 5, 6], [0, 8]]))
# [0, 1, 2, 4, 5, 6, 7, 8]
```

### worked 例

三路 `[1, 4, 7]`、`[2, 5, 6]`、`[0, 8]`：堆初始 (0, 2路)、(1, 0路)、(2, 1路)；弹 0 → 2路推进 8；弹 1 → 0路推进 4；弹 2 → 1路推进 5；弹 4 → 0路推进 7；弹 5 → 1路推进 6；弹 6、7、8 依次出堆。结果 `[0, 1, 2, 4, 5, 6, 7, 8]`，总代价 O(N log K)，N 是元素总数。

注意元组写法 `(值, 路编号, 下标)`：值相等时比较路编号，不会去比较链表节点对象本身——直接往堆里放节点对象、值又相等时，Python 会尝试比较节点而报错。

## 数据流中位数：两堆对顶

数据流源源不断地来，任何时刻都要报中位数：维护两个堆，low 是大顶堆（取负模拟）存较小的一半，high 是小顶堆存较大的一半；不变量是 low 的最大值 ≤ high 的最小值，且 len(low) == len(high) 或多一个。

```python
import heapq

class MedianFinder:
    def __init__(self):
        self.low = []   # 大顶堆（取负），存较小的一半
        self.high = []  # 小顶堆，存较大的一半
    def add(self, x):
        heapq.heappush(self.low, -x)
        heapq.heappush(self.high, -heapq.heappop(self.low))
        if len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))
    def median(self):
        if len(self.low) > len(self.high):
            return -self.low[0]
        return (-self.low[0] + self.high[0]) / 2

mf = MedianFinder()
for x in [5, 2, 9, 1, 7]:
    mf.add(x)
    print(mf.median(), end=" ")
# 5 3.5 5 3.5 5
```

### worked 例

流 `[5, 2, 9, 1, 7]`：

| 加入 | low（较小半） | high（较大半） | 中位数 |
| --- | --- | --- | --- |
| 5 | [5] | [] | 5 |
| 2 | [2] | [5] | (2+5)/2 = 3.5 |
| 9 | [5, 2] | [9] | 5 |
| 1 | [2, 1] | [5, 9] | (2+5)/2 = 3.5 |
| 7 | [5, 2, 1] | [7, 9] | 5 |

新元素先过 low 再过 high 的用意：保证 low 的最大值永远 ≤ high 的最小值，顺序不被打破；再按长度调平衡，多的那个放 low。每次 add 是 O(log n)，取中位数是 O(1)。

## 易错点

- heapq 是最小堆：要最大堆就存相反数；取出来记得再取负，别把负数当答案返回。
- 堆里放元组时，值相等会顺位比较下一项：放 (值, 编号) 而不是 (值, 对象)，否则值相等时 Python 会去比较对象而报错。
- heapq 没有 decrease-key：Dijkstra 里距离变小是重新入堆，旧项靠 `d != dist[u]` 跳过，不要试图在堆里原地改 key。
- TopK 堆大小是 k 不是 n：堆里始终只留 k 个，写成 n 就是全排序的代价，省不下。
- 中位数两堆的长度关系写反时，中位数取的就不是中间值：先定不变量（low 多一个或相等），再写 add 的调整顺序。

## 小技巧与冷知识

【小技巧】建堆别一个个 push，用 `heapq.heapify`：把整个列表原地转成堆是 O(n)，逐个 heappush 是 O(n log n)。数据已经全在手里时先 heapify 再 pop，比“空堆一个个 push”快一个量级；只有流式逐个到达的数据才需要 push。

【小技巧】`heappushpop` 和 `heapreplace` 别混用：`heapreplace` 是先弹堆顶再压新元素，堆为空会报 IndexError；`heappushpop` 是先压后弹，空堆也能用，而且新元素比堆顶还小时会直接把新元素弹出来、堆原样不动。TopK 里“比堆顶大才换”用 heapreplace 更贴切，写错成 heappushpop 也能跑，但语义是“先压后弹”而不是“换掉堆顶”。

【小技巧】合并多路已排序的可迭代对象直接用 `heapq.merge`：它返回一个惰性迭代器，边取边归并，不用先把所有元素拼成一个大列表。K 路归并手写堆循环的场景，能用 merge 就用 merge；Python 3.5 起它还支持 `key` 参数，可以按自定义键归并。

【小技巧】堆里放自定义对象时，用 `(优先级, 计数器, 对象)` 三元组：优先级相等时比较计数器，永远轮不到比较对象本身。计数器用 `itertools.count()` 自增生成，比手写路编号更省事；别给业务对象加 `__lt__` 来迁就堆，排序语义一旦和业务语义绑在一起，后面改排序就得改对象。

【小技巧】需要“改优先级”时用懒删除的标准套路：维护一个 `entry_finder` 字典记每个任务的最新堆项，旧项打上 `REMOVED` 标记留在堆里，弹出时跳过已标记的项。这就是 Python 官方 heapq 文档里优先队列示例的做法，Dijkstra 的 `d != dist[u]` 是它的简化版；堆里多留几个过期项的代价，远小于“在堆里原地改 key 再重新调整”的实现成本。

【小技巧】别在热循环里写 `x in heap`：堆是数组，不是集合，成员检查是 O(n) 扫描。需要频繁判断“在不在堆里”时，另外维护一个 set 或 entry_finder 字典做 O(1) 查询；只在调试时用 `in` 看一眼。

【小技巧】heapq 不是线程安全的：多个线程同时 push/pop 同一个堆会破坏堆结构。并发场景要自己加锁，或者每个线程用自己的堆、最后再归并；别把 heapq 当成 `queue.PriorityQueue` 用，后者内部带锁、但每次操作都有锁开销。

【小技巧】TopK 的 k 很小（比如 1、2）时别急着上堆：k=1 就是 `max()`，k=2 扫两遍也够，堆的常数开销反而更大。堆的优势区间是“k 不大不小”——n 很大、k 中等时 O(n log k) 才划算，k 接近 n 时原文已经说了直接排序。

【小技巧】堆顶元素被弹出后堆大小会缩水，循环里用 `while h:` 而不是按初始长度 `for _ in range(n)`：边弹边压的场景（比如 K 路归并）长度在变，按初始长度循环要么提前停、要么多弹一次报空堆错误；以堆是否为空为循环条件最稳。

【小技巧】Dijkstra 里堆的大小上限是边数不是点数：每条边松弛成功就 push 一次，堆里最多攒 E 个项（含过期项）。估算内存和 pop 次数时按 E 算，别按 V 算；稠密图上这就是堆版 Dijkstra 比朴素版慢的根源之一。

【小技巧】需要“第 k 小”但 k 会变时，别每次都重建堆：维护一个大小固定的堆加一个已排序的缓存，k 变大时从堆里多弹几个补进缓存，k 变小时直接从缓存取。频繁改 k 的查询场景（如交互式 TopK），重建堆的 O(n log k) 每次都付不起。

【冷知识】堆排序是 1964 年 J. W. J. Williams 发明的，发表在《Communications of the ACM》上，论文题为 "Algorithm 232: Heapsort"。同一年 Robert W. Floyd 提出了 O(n) 的线性建堆方法，也就是今天 `heapify` 背后的算法——先建堆再逐个弹出排序，整个堆排序因此是 O(n log n)。

【冷知识】Python 的 `heapq` 模块是 Python 2.3（2003 年）引入的，名字取自 heap + queue（堆实现的队列）。它一开始就是纯 Python 实现，后来 CPython 用 C 重写了核心操作（`_heapq`），所以今天的 heappush/heappop 走的是 C 代码，比纯 Python 循环快得多。

【冷知识】斐波那契堆是 1984 年 Michael Fredman 和 Robert Tarjan 提出的，插入和 decrease-key 均摊 O(1)，删最小值均摊 O(log n)，理论上比二叉堆更优。但它常数大、实现复杂，实际工程里几乎没人用，Dijkstra 的堆优化至今仍以二叉堆为主——理论最优不等于工程最优。

【冷知识】堆排序是不稳定的：相等元素在建堆和下沉过程中会被交换，相对顺序保不住。需要稳定排序时别用堆排，用归并排序；TopK 场景里“值相等时谁先出”要靠元组里的第二项（编号/计数器）显式定序，堆本身不保证。

【冷知识】d 叉堆是二叉堆的推广：每个节点有 d 个孩子，下沉时要在 d 个孩子里挑最小的，树更矮、比较次数更多。d 取 3 或 4 时，某些 Dijkstra 实现上比二叉堆快，因为缓存局部性更好——堆的“形状”本身就是个可调参数，不只有二叉一种。

【冷知识】优先队列这个名字比堆更老：它最早是操作系统调度里“按优先级取任务”的抽象，堆只是实现它的一种结构。除了堆，优先队列还能用有序数组、平衡树、跳表实现，选哪种取决于“插入多还是取最小多”——插入远多于取用时，懒一点的结构反而更快。

## 面试与自测

1. heapq 是最小堆还是最大堆？要最大堆怎么办？为什么 heapq 没有 decrease-key？
2. TopK 为什么用大小 k 的小顶堆而不是把全部排序？复杂度差在哪？
3. 数据流中位数两堆的不变量是什么？新元素为什么先过 low 再过 high？

### 参考答案

1. heapq 是最小堆；存相反数模拟最大堆，取出时再取负。heapq 只提供 push / pop，改 key 要重新入堆，旧项靠版本号或过期判断跳过——图篇 Dijkstra 的 `d != dist[u]` 就是这个套路。
2. 小顶堆只留 k 个，堆顶即当前第 k 大，来一个比堆顶大的才换，复杂度 O(n log k)；全排序是 O(n log n)，n 远大于 k 时堆省得多；k 接近 n 时直接排序更简单。
3. 不变量：low（大顶堆）存较小一半，high（小顶堆）存较大一半，low 的最大值 ≤ high 的最小值，且 len(low) == len(high) 或多一个。新元素先入 low 再把 low 顶倒入 high，保证顺序不被打破，再按长度调平衡。
