# 堆与优先队列

堆是“总能最快拿到最大/最小元素”的结构，优先队列是它的接口名。本篇讲 heapq、TopK、合并 K 路、数据流中位数；堆排的建堆与下沉见 [排序算法实现](计算机基础/算法/排序算法实现.md)，堆优化 Dijkstra 见 [图算法深篇](计算机基础/算法/图算法深篇.md)，两处都不重复。

## 堆结构一句话

堆是完全二叉树，用数组存：下标从 0 开始，父节点 `(i-1) / 2`，左孩子 `2i + 1`，右孩子 `2i + 2`（总纲里已给）。大顶堆是每个节点都不小于孩子，堆顶即最大值；小顶堆反之。插入放末尾再上浮，删堆顶把末尾元素挪到顶再下沉，各 O(log n)。

Python 的 heapq 是小顶堆，只提供 heappush / heappop / heapreplace，没有 decrease-key（改 key 要重新入堆，旧项靠过期判断跳过——图篇 Dijkstra 里 `d != dist[u]` 那行就是这个套路）。

## TopK：大小为 k 的小顶堆

求前 k 大：维护一个大小 k 的小顶堆，堆顶就是当前第 k 大；来一个新元素，比堆顶大就换掉堆顶，比堆顶小就扔掉。结束时堆里 k 个就是答案。

```python
import heapq

def topk(nums, k):
    h = []
    for x in nums:
        if len(h) < k:
            heapq.heappush(h, x)
        elif x > h[0]:
            heapq.heapreplace(h, x)
    return sorted(h, reverse=True)

print(topk([5, 2, 9, 1, 7, 6], 3))              # [9, 7, 6]
print(heapq.nlargest(3, [5, 2, 9, 1, 7, 6]))   # [9, 7, 6]
```

### worked 例

`[5, 2, 9, 1, 7, 6]` 取前 3 大：堆先装 5、2、9（堆顶 2）；来 1，比堆顶小，扔；来 7，比堆顶大，换掉 2，堆顶变 5；来 6，比堆顶大，换掉 5，堆里是 6、7、9；排序输出 `[9, 7, 6]`。

复杂度 O(n log k)：每个元素最多一次堆操作；k 远小于 n 时比全排序 O(n log n) 省得多。k 接近 n 时别折腾，直接排序。日常直接用 `heapq.nlargest / nsmallest`，它内部就是这个思路（k 小时用堆，k 大时切回排序）。

## 合并 K 个有序链表

K 路已排序，归并成一路：堆里始终放每路当前的第一个元素，每次弹出最小的追加到结果，再把该路的下一个元素推进堆。堆大小恒为 K，取元素 O(log K)。

```python
import heapq

def merge_k_sorted(lists):
    h = []
    for i, lst in enumerate(lists):
        if lst:
            heapq.heappush(h, (lst[0], i, 0))
    out = []
    while h:
        v, i, j = heapq.heappop(h)
        out.append(v)
        if j + 1 < len(lists[i]):
            heapq.heappush(h, (lists[i][j + 1], i, j + 1))
    return out

print(merge_k_sorted([[1, 4, 7], [2, 5, 6], [0, 8]]))
# [0, 1, 2, 4, 5, 6, 7, 8]
```

### worked 例

三路 `[1, 4, 7]`、`[2, 5, 6]`、`[0, 8]`：堆初始 (0, 2路)、(1, 0路)、(2, 1路)；弹 0 → 2路推进 8；弹 1 → 0路推进 4；弹 2 → 1路推进 5；弹 4 → 0路推进 7；弹 5 → 1路推进 6；弹 6、7、8 依次出堆。结果 `[0, 1, 2, 4, 5, 6, 7, 8]`，总代价 O(N log K)，N 是元素总数。

注意元组写法 `(值, 路编号, 下标)`：值相等时比较路编号，不会去比较链表节点对象本身——直接往堆里放节点对象、值又相等时，Python 会尝试比较节点而报错。

## 数据流中位数：两堆对顶

数据流源源不断地来，任何时刻都要报中位数：维护两个堆，low 是大顶堆（取负模拟）存较小的一半，high 是小顶堆存较大的一半；不变量是 low 的最大值 ≤ high 的最小值，且 len(low) == len(high) 或多一个。

```python
import heapq

class MedianFinder:
    def __init__(self):
        self.low = []   # 大顶堆（取负），存较小的一半
        self.high = []  # 小顶堆，存较大的一半
    def add(self, x):
        heapq.heappush(self.low, -x)
        heapq.heappush(self.high, -heapq.heappop(self.low))
        if len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))
    def median(self):
        if len(self.low) > len(self.high):
            return -self.low[0]
        return (-self.low[0] + self.high[0]) / 2

mf = MedianFinder()
for x in [5, 2, 9, 1, 7]:
    mf.add(x)
    print(mf.median(), end=" ")
# 5 3.5 5 3.5 5
```

### worked 例

流 `[5, 2, 9, 1, 7]`：

| 加入 | low（较小半） | high（较大半） | 中位数 |
| --- | --- | --- | --- |
| 5 | [5] | [] | 5 |
| 2 | [2] | [5] | (2+5)/2 = 3.5 |
| 9 | [5, 2] | [9] | 5 |
| 1 | [2, 1] | [5, 9] | (2+5)/2 = 3.5 |
| 7 | [5, 2, 1] | [7, 9] | 5 |

新元素先过 low 再过 high 的用意：保证 low 的最大值永远 ≤ high 的最小值，顺序不被打破；再按长度调平衡，多的那个放 low。每次 add 是 O(log n)，取中位数是 O(1)。

## 易错点

- heapq 是最小堆：要最大堆就存相反数；取出来记得再取负，别把负数当答案返回。
- 堆里放元组时，值相等会顺位比较下一项：放 (值, 编号) 而不是 (值, 对象)，否则值相等时 Python 会去比较对象而报错。
- heapq 没有 decrease-key：Dijkstra 里距离变小是重新入堆，旧项靠 `d != dist[u]` 跳过，不要试图在堆里原地改 key。
- TopK 堆大小是 k 不是 n：堆里始终只留 k 个，写成 n 就是全排序的代价，省不下。
- 中位数两堆的长度关系写反时，中位数取的就不是中间值：先定不变量（low 多一个或相等），再写 add 的调整顺序。

## 面试与自测

1. heapq 是最小堆还是最大堆？要最大堆怎么办？为什么 heapq 没有 decrease-key？
2. TopK 为什么用大小 k 的小顶堆而不是把全部排序？复杂度差在哪？
3. 数据流中位数两堆的不变量是什么？新元素为什么先过 low 再过 high？

### 参考答案

1. heapq 是最小堆；存相反数模拟最大堆，取出时再取负。heapq 只提供 push / pop，改 key 要重新入堆，旧项靠版本号或过期判断跳过——图篇 Dijkstra 的 `d != dist[u]` 就是这个套路。
2. 小顶堆只留 k 个，堆顶即当前第 k 大，来一个比堆顶大的才换，复杂度 O(n log k)；全排序是 O(n log n)，n 远大于 k 时堆省得多；k 接近 n 时直接排序更简单。
3. 不变量：low（大顶堆）存较小一半，high（小顶堆）存较大一半，low 的最大值 ≤ high 的最小值，且 len(low) == len(high) 或多一个。新元素先入 low 再把 low 顶倒入 high，保证顺序不被打破，再按长度调平衡。
