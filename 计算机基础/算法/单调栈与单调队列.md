# 单调栈与单调队列

单调栈和单调队列共享一个思想：维护一个单调的结构，把“不需要再比较的元素”提前扔掉，让每个元素最多入出一次，从而把 O(n²) 的暴力比较降到 O(n)。

## 单调栈：下一个更大元素

模板（栈内存下标，栈内从栈底到栈顶单调递减）：

```python
def next_greater(nums):
    res = [-1] * len(nums)
    st = []  # 存下标，nums[st] 从栈底到栈顶单调递减
    for i, x in enumerate(nums):
        while st and nums[st[-1]] < x:
            res[st.pop()] = x  # 当前元素就是被弹出元素的下一个更大元素
        st.append(i)
    return res
```

注意比较符：`while nums[st[-1]] < x` 弹出，相等的不弹，所以求的是“严格更大”；把 `<` 换成 `>`，栈内就变成单调递增，求的是下一个更小元素。

### worked 例

`nums = [2, 1, 2, 4, 3]`，逐步走：

- 2 入栈，栈 `[2]`；1 入栈，栈 `[2, 1]`。
- 2 到来：弹出 1（1 的下一个更大是 2），栈 `[2, 2]`。
- 4 到来：弹出两个 2（它们的下一个更大都是 4），栈 `[4]`。
- 3 入栈，栈 `[4, 3]`；结束时栈里剩的 4、3 没有下一个更大元素，填 -1。

结果 `[4, 2, 4, -1, -1]`。

### 应用：柱状图最大矩形

同样是单调栈：弹出高度 `h` 时，`h` 能向左右扩展到的边界就是当前栈顶和当前下标，宽 = `i - left - 1`。

```python
def largest_rectangle(heights):
    hs = heights + [0]  # 末尾哨兵，把栈里剩的元素全部弹出来算一遍
    st, best = [], 0
    for i, h in enumerate(hs):
        while st and hs[st[-1]] > h:
            height = hs[st.pop()]
            left = st[-1] if st else -1
            best = max(best, height * (i - left - 1))
        st.append(i)
    return best
```

worked 例：`heights = [2, 1, 5, 6, 2, 3]`，最大矩形是 `10`。关键一步：处理到下标 4（值为 2）时弹出高度 5，左边界是下标 1，宽 `4 - 1 - 1 = 2`，面积 `5 * 2 = 10`；弹出高度 6 时宽 1，面积 6；最终最大值就是 10。

## 单调队列：滑动窗口最大值

模板（双端队列存下标，队内元素对应的值单调递减）：

```python
from collections import deque

def sliding_max(nums, k):
    dq, res = deque(), []
    for i, x in enumerate(nums):
        while dq and dq[0] <= i - k:  # 队首已滑出窗口，扔掉
            dq.popleft()
        while dq and nums[dq[-1]] < x:  # 队尾比当前值小的，永远当不了窗口最大值
            dq.pop()
        dq.append(i)
        if i >= k - 1:
            res.append(nums[dq[0]])  # 队首就是当前窗口最大值
    return res
```

### worked 例

`nums = [1, 3, -1, -3, 5, 3, 6, 7]`，`k = 3`，结果 `[3, 3, 5, 5, 6, 7]`。走前两步看机制：下标 0（值 1）入队；下标 1（值 3）到来，队尾 1 比 3 小被弹出，队首是 3，第一个窗口 `[1, 3, -1]` 的最大值就是 3；下标 2（值 -1）入队排在 3 后面，因为它可能在 3 滑出窗口后成为最大值——这就是“比当前值小的元素还要留着”的原因：它们是未来的候选。

## 为什么是 O(n)

单调栈和单调队列都是：每个元素最多入栈/入队一次、出栈/出队一次，总操作不超过 `2n` 次，所以是 O(n)。不是“内层 while 看起来像嵌套循环就是 O(n²)”——while 每弹一个元素，那个元素就再也不会进来了，均摊下来每个元素只被处理常数次。

## 适用场景对比

| 工具 | 解决的问题 | 典型题 |
|---|---|---|
| 单调栈 | 找每个元素的“下一个更大/更小” | 下一个更大元素、柱状图最大矩形、接雨水 |
| 单调队列 | 维护滑动窗口内的最值 | 滑动窗口最大值、滑动窗口最小值 |

## 常见误区

- 术语混淆：有人把“从栈底到栈顶单调递减的栈”叫单调递减栈，有人按弹出顺序叫它单调递增栈；做题时不要背名字，按“栈内单调性 + 比较符”对号入座：求下一个更大 → 栈内递减、`<` 弹出；求下一个更小 → 栈内递增、`>` 弹出。
- 滑动窗口最大值用堆：堆顶可能是已滑出窗口的元素，要反复判断过期，写法比单调队列啰嗦且常数更大；窗口最值优先用单调队列。
- 相等元素的处理要先定好：求“严格更大”时相等不弹，求“更大或相等”时相等也弹，两者结果不同，写代码前先确认题意。

## 小技巧与冷知识

【小技巧】单调栈里存下标不存值：下标能换算出距离（左右边界、宽度）和位置（是否过期），值本身做不到。柱状图最大矩形里弹出高度时，宽 `i - left - 1` 用的就是栈顶下标；只存高度的话，左边边界在哪根本算不出来。

【小技巧】“弹出时算答案”是单调栈的通用模式：一个元素被弹出的那一刻，当前元素就是它的“下一个更大”，此时的新栈顶就是它的“上一个更大”，左右边界一次齐全。接雨水、柱状图最大矩形、下一个更大元素都是这个模式的不同填法，认出模式后不用每题重想。

【小技巧】正反各扫一遍能一次拿到左右边界：从左往右扫得到每个元素的“上一个更大/更小”，从右往左扫得到“下一个更大/更小”，两个结果拼起来就是左右边界。最大矩形、接雨水里“左边第一个更矮、右边第一个更矮”都是这样来的，比在一次遍历里同时维护两边更不容易错。

【小技巧】哨兵能省掉“扫完再清栈”的收尾：柱状图最大矩形末尾加一个 0，栈里剩的元素会被全部弹出来算一遍；下一个更大元素同理，末尾加一个正无穷哨兵也能把栈清空。哨兵值要选“一定会触发弹出”的极端值，写完记得它不对应真实下标、结果里别把它算进去。

【小技巧】单调队列里也只存下标不存值：队首是否滑出窗口只能靠下标判断（`dq[0] <= i - k`），只存值根本不知道队首是第几个元素。窗口最大值模板里“队首过期先扔、队尾更小再弹、读答案前两步都要做完”，顺序反了会读到过期值。

【小技巧】滑动窗口最小值就是把比较符反过来：单调队列队内从单调递减改成单调递增，队首就变成窗口最小值，其余逻辑（过期判断、入队时机）一行都不用改。最大值和最小值是同一套模板的两种填法，别当成两个算法背。

【小技巧】循环数组的下一个更大元素不用复制数组：下标遍历 `2n` 次、取模访问，栈里只存第一遍的下标，`[1, 2, 1]` 的结果是 `[2, -1, 2]`。注意第二遍只负责弹出、不再入栈，否则同一元素会进栈两次；这个“只弹不压”的细节是循环版最容易写错的地方。

【小技巧】窗口大小取极端值时先想退化情况：`k = 1` 时每个窗口就是单个元素，答案等于原数组；`k = n` 时只有一个窗口，答案就是全局最大值。写完模板先拿这两个极端值测一遍，过期判断 `dq[0] <= i - k` 写错时 k=1 那个用例最先露馅。

【小技巧】接雨水用单调栈时，弹出的是“凹槽底部”：当前柱子比栈顶高，栈顶被弹出，左右边界是新栈顶和当前下标，雨水高度是左右较低者减去底部高度，宽度是 `i - left - 1`。`[0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]` 的答案是 6，算完可拿这个例子对一遍。

【小技巧】单调栈的 O(n) 要用“均摊”讲才站得住：每个元素最多入栈一次、出栈一次，总操作不超过 `2n` 次，while 嵌套在 for 里也不改变这个上界。面试里只说“每个元素只处理一次”不够，要补一句“弹出的元素永不再进栈”，这才是均摊分析的关键。

【冷知识】滑动窗口最大值是 LeetCode 239 题（困难），它是单调队列最出名的标志题：暴力是 O(nk)，堆是 O(n log k) 还要处理过期堆顶，单调队列是 O(n)。很多面试官点名这道题，就是在考“你知不知道单调队列这个结构”，而不是考“你会不会写堆”。

【冷知识】柱状图最大矩形是 LeetCode 84 题，接雨水是 42 题，下一个更大元素是 496 题：这三道题用的都是同一套单调栈思想，只是“弹出时算什么”不同——84 算面积、42 算水量、496 填答案。刷题时把这三道放一起做，比分散在不同章节做更容易看出共性。

【冷知识】单调栈和单调队列的英文是 monotonic stack / monotonic queue（deque）：英文资料里单调队列常直接叫 monotonic deque，因为它本质上就是维护单调性的双端队列。查英文题解时搜 monotonic stack 比搜“单调栈”能找到更多讨论，包括不少可视化演示。

【冷知识】单调栈不是“为做题发明的技巧”，它在编译器里也有身影：表达式求值、括号匹配、语法分析里维护运算符优先级时，用的都是“栈内保持单调、遇到更大的就弹出处理”的同一思路。做题时觉得它像个 trick，放到编译原理里看就是常规操作。

【冷知识】“每个元素最多进出一次”这个结论有个正式名字：均摊分析（amortized analysis）。它不只用于单调栈，动态数组扩容、并查集路径压缩的复杂度分析用的也是它——单次操作可能很贵，但分摊到一连串操作上是常数。理解均摊分析后，单调栈的 O(n) 就不再是“看起来像 O(n²) 但其实是 O(n)”的玄学。

## 面试与自测

1. 单调栈里有个 while 嵌套在 for 里，为什么整体还是 O(n) 而不是 O(n²)？
2. 滑动窗口最大值为什么不直接用一个普通队列（或堆）来维护？
3. 求下一个更大元素时，栈内应该维护递增还是递减？比较符用 `<` 还是 `>`？

### 参考答案

1. 因为每个元素最多入栈一次、出栈一次：while 每弹出一个元素，那个元素就永久离开栈了；整个过程入栈 n 次、出栈至多 n 次，总操作 O(n)，均摊到每个元素是常数。
2. 普通队列只能做到先进先出，取最大值要扫一遍窗口是 O(k)；堆虽然能取最大值，但堆顶可能是已滑出窗口的过期元素，要反复清理。单调队列让队首恒为窗口最大值，过期判断和最值获取都是 O(1)。
3. 维护从栈底到栈顶单调递减的栈，比较符用 `<` 弹出：当前元素大于栈顶时，栈顶元素的下一个更大元素就是当前元素；相等的不弹，求的是严格更大。若比较符换成 `>`，栈内变成单调递增，求的是下一个更小元素。
