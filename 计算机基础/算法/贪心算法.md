# 贪心算法

贪心只有一句话：每一步都选当前看起来最好的，选完不回头。能这么干的前提是这道题有贪心选择性质——局部最优能拼出全局最优，外加最优子结构。两个条件缺一个，贪心就可能错，错的例子见后文反例。

## 经典题 1：活动选择

一堆活动各有开始和结束时间，同一时间只能参加一个，问最多参加几个。贪心策略：按结束时间从早到晚排，每次选和已选活动不冲突、结束最早的那个。直觉是结束越早，留给后面的时间越多。

```python
def activity_selection(activities):
    # activities: (start, end)，按结束时间排序
    acts = sorted(activities, key=lambda x: x[1])
    selected, last_end = [], 0
    for s, e in acts:
        if s >= last_end:
            selected.append((s, e))
            last_end = e
    return selected

acts = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9),
        (6, 10), (8, 11), (8, 12), (2, 14), (12, 16)]
print(activity_selection(acts))
# 输出：[(1, 4), (5, 7), (8, 11), (12, 16)]，共 4 个
```

为什么按结束时间排、而不是按开始时间或持续时间排：按开始时间排会先选中 `(0, 6)` 这种横跨很久的活动，堵住后面好几个；按持续时间排也有类似问题。只有“结束最早”能保证每次选完剩余时间最多，这是能证明的（交换论证：把最优解的第一个活动换成结束最早的活动，解不会变差）。

## 经典题 2：分发饼干

每个孩子有胃口值 `g[i]`，每块饼干有尺寸 `s[j]`，尺寸大于等于胃口才算满足，问最多满足几个孩子。贪心策略：孩子和饼干都从小到大排，用最小的能满足当前孩子的饼干去满足他，不浪费大饼干。

```python
def find_content_children(g, s):
    g, s = sorted(g), sorted(s)
    child = cookie = satisfied = 0
    while child < len(g) and cookie < len(s):
        if s[cookie] >= g[child]:
            satisfied += 1
            child += 1
        cookie += 1
    return satisfied

print(find_content_children([1, 2, 3], [1, 1]))       # 1：只有胃口 1 的孩子能满足
print(find_content_children([1, 2], [1, 2, 3]))       # 2：两个孩子都满足
```

## 经典题 3：跳跃游戏

数组 `nums`，`nums[i]` 表示从位置 `i` 最远能跳几格，问能否到达最后一个下标。贪心策略：维护“目前能到达的最远位置”，一路向右扫，能到达的位置不断往外扩；如果最远位置卡在某个下标之前，说明到不了。

```python
def can_jump(nums):
    farthest = 0
    for i, jump in enumerate(nums):
        if i > farthest:      # 当前位置已经够不着了
            return False
        farthest = max(farthest, i + jump)
    return True

print(can_jump([2, 3, 1, 1, 4]))   # True：0→1→4
print(can_jump([3, 2, 1, 0, 4]))   # False：最远到下标 3，够不着下标 4
```

## 贪心失效的反例

### 反例 1：0-1 背包不能按性价比贪心

背包容量 50，三件物品（重量，价值）：A(10, 60)、B(20, 100)、C(30, 120)，性价比分别是 6、5、4。

- 按性价比贪心：先拿 A，再拿 B，重量 30、价值 160，剩下 20 装不下 C，结果 160。
- 最优解：拿 B + C，重量 50、价值 220。

贪心错的原因：0-1 背包没有贪心选择性质，局部最优（先拿性价比最高的）堵住了全局最优。注意区分：分数背包（物品可拆）按性价比贪心是对的，因为拆开拿不会堵住空间。

### 反例 2：找零不总是贪心最优

面额 `[1, 3, 4]`，要凑 6 元。贪心先拿最大的 4，再拿两个 1，共 3 枚；最优是两个 3，共 2 枚。人民币、美元这种“规范面额”贪心是对的，但换一组面额就不一定，写找零代码前要先确认面额体系，或者直接用 DP 求最优。

## 贪心 vs 动态规划

| 维度 | 贪心 | 动态规划 |
| --- | --- | --- |
| 每步决策 | 只看当前最优，选完不回头 | 比较所有子问题的结果再选 |
| 适用条件 | 贪心选择性质 + 最优子结构 | 最优子结构 + 重叠子问题 |
| 典型复杂度 | 排序后 O(n log n) 或 O(n) | O(n²)、O(n×容量) 等 |
| 风险 | 条件不满足时静默出错 | 状态定义错了答案也错，但不会“以为对了” |
| 典型题 | 活动选择、分发饼干、跳跃游戏 | 背包、LIS、LCS、打家劫舍 |

判断流程：先想这道题能不能用贪心（找反例试着证伪），证伪失败再去证明贪心选择性质；证不出来就老老实实写 DP，DP 是更通用的兜底。

## 小技巧与冷知识

【小技巧】怀疑贪心对不对时，先写暴力对拍再写证明：小规模随机输入上，把贪心结果和暴力枚举（或 DP 求出的最优解）逐组对比，跑几千组都没分歧再去想证明。原文反例 1 的背包、反例 2 的找零，用对拍都能在小输入上立刻抓到；先对拍、后证明，比空想反例快得多。

【小技巧】跳跃游戏只问"能不能到"，改问"最少跳几步"还是贪心：按"当前这一跳能到达的边界"分层推进，每到边界就跳数加一、边界扩到这一层内能到达的最远处。`[2, 3, 1, 1, 4]` 只需 2 跳（0→1→4），和原文的"能不能到"是同一套 farthest 思路，只是多记了一个边界。

【小技巧】活动一旦带权重，按结束时间贪心立刻失效：活动 (1, 2, 权重 100) 和 (1, 3, 权重 101)，按结束最早选先拿 100 的，总收益 100；最优是只拿 101 的那个。权重一出现就要换成加权区间调度 DP（按结束时间排序 + 二分找上一个不冲突的活动），别在贪心上硬修。

【小技巧】区间类贪心有个通用口诀：按右端点排序。活动选择、最少箭射气球、区间覆盖都是同一个套路——先排右端点，再按"不冲突就选"往下走。比如区间 `[1,6],[2,8],[7,12],[10,16]`，箭落在右端点 6 和 12，只需 2 支箭；认出"按右端点排"这个模式，等于同时认出好几道题。

【小技巧】分发饼干也可以反过来配：从胃口最大的孩子开始，用最大的饼干去满足他，同样最优；正向"最小够用饼干"和反向"最大饼干配最大胃口"都是不浪费的配法。关键不在方向，而在"不拿大的去满足小的"——两种方向都成立，说明这道题的贪心选择不唯一。

【小技巧】跳跃游戏里可以提前剪枝：扫到某个位置时一旦 `farthest >= n - 1`，直接返回 True，不用把数组扫完。原文代码是扫完全程才返回 True，提前返回在"前面就能跳到终点"的输入上能省掉后面的循环，逻辑不变、只是少做无用功。

【小技巧】贪心经常和堆搭档：比如"最多做 k 个项目"（先按启动资金排序，够本的项目进最大堆、每次取利润最大的做），排序定顺序、堆定选择，两者分工不同。看到"每步在已满足条件的集合里挑最好的"，先想想是不是"排序 + 堆"的组合，而不是纯排序。

【小技巧】加油站问题是贪心的换角度范例：总油量大于等于总消耗时一定有解，起点就是"累计盈亏最低点"的下一站——因为从最低点之后出发，累计油量全程不为负。这道题的贪心不在"每步选最大"，而在"先算总账、再找起点"，贪心策略的形式比"每步最优"更宽。

【小技巧】写贪心代码时把"排序键"单独抽出来：活动选择按结束时间、分发饼干按胃口、找零按面额，排序键换了等于策略换了。抽出来之后，同一份代码换个排序键就能对拍"按开始时间排""按持续时间排"这些错误策略，原文"为什么按结束时间排"的论证，用对拍跑一遍比背结论更直观。

【小技巧】贪心题的调试顺序是"先找反例、再调代码"：贪心写错时代码本身往往没有 bug，错的是策略。先拿小输入暴力对拍定位"贪心在哪一步开始偏离最优"，再决定是换策略还是改用 DP；盯着代码逐行看，大概率看不出问题，因为每一步单独看都是"当前最优"。

【冷知识】霍夫曼编码是贪心最优的经典例子：David Huffman 在 1952 年的论文《A Method for the Construction of Minimum-Redundancy Codes》里提出，每次合并两个频率最小的节点，最终得到最优前缀码。他当时还是 MIT 的研究生，这篇论文本是课程作业的替代方案——贪心在编码理论里一出手就是最优解。

【冷知识】最小生成树的 Kruskal、Prim 和最短路的 Dijkstra，本质上都是贪心：Kruskal 每步选全局最轻且不成环的边，Prim 每步选连接已选集合的最轻边，Dijkstra 每步锁定当前最近的未确定节点。原文的三道经典题之外，图论里最出名的三个算法全是贪心，只是它们的"当前最优"需要堆和并查集来维护。

【冷知识】贪心能保证最优的结构有个正式名字：拟阵（matroid）。Edmonds 在 1971 年证明，贪心算法在拟阵的独立集上取最大权一定最优，Kruskal 背后就是图的拟阵（无环边集）。反过来也可以理解原文的反例：0-1 背包的"可装集合"不是拟阵，所以性价比贪心不保证最优——贪心成立与否，取决于问题背后的结构是不是拟阵。

【冷知识】找零的面额体系合不合贪心，是可以判定的："规范面额"（canonical coin system）指贪心永远最优的面额组。David Pearson 在 2005 年的论文《A Polynomial-time Algorithm for the Change-Making Problem》里给出了 O(n³) 的判定算法（n 为面额个数），所以原文"写找零代码前先确认面额体系"这句话，是有算法支撑的，不只是经验之谈。

【冷知识】贪心算法的英文 greedy algorithm 里，"贪心"这个词本身就是算法思想的直译：每一步都"贪"当前最好的，不考虑以后。它的反面不是动态规划，而是"回溯"——贪心选了不回头，回溯选错了退回来重选；原文判断流程里"证伪失败再证明"，本质上就是在问"这道题能不能不回头"。

## 面试与自测

1. 活动选择为什么按结束时间排序，而不是按开始时间或持续时间排序？
2. 0-1 背包为什么不能按性价比贪心，分数背包为什么可以？
3. 跳跃游戏的贪心解法里，`farthest` 卡住时为什么能直接返回 False，不用回头试别的跳法？

### 参考答案

1. 按开始时间排会先选中横跨很久的活动（如 `(0, 6)`），堵住后面多个活动；按持续时间排也有同样问题。只有“结束最早”能保证每次选完剩余时间最多，且可用交换论证证明：把最优解的第一个活动换成结束最早的活动，解不会变差。
2. 0-1 背包的物品不可拆，拿性价比最高的可能堵住空间（如容量 50 时贪心 160、最优 220）；分数背包的物品可拆，拿一部分不会堵住剩余空间，性价比优先始终成立。
3. `farthest` 是从已扫过的所有位置能到达的最远下标；如果当前下标 `i` 已经大于 `farthest`，说明前面所有位置都跳不过来，后面的位置更够不着，不存在别的跳法能绕过去，所以直接返回 False。
