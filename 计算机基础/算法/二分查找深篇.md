# 二分查找深篇

总纲 [数据结构与算法](计算机基础/算法/数据结构与算法.md) 已给左闭右闭模板与左边界思路，本篇只写它之外的增量：区间不变式、右边界、旋转数组、答案二分、实数二分。

## 区间不变式：左闭右闭 vs 左闭右开

二分不出错的关键是全程维持一句话：目标（如果存在）一定在当前区间里。两种写法只是区间定义不同，循环条件和更新方式必须配套，混用就死循环或丢答案。

| 写法 | 区间定义 | 循环条件 | 中点小于目标 | 中点大于等于目标 | 退出时 l 的含义 |
| --- | --- | --- | --- | --- | --- |
| 左闭右闭 | [l, r]，r 是合法下标 | l <= r | l = m + 1 | r = m - 1 | 插入位置（第一个大于目标的位置） |
| 左闭右开 | [l, r)，r 是哨兵下标 | l < r | l = m + 1 | r = m | 第一个大于等于目标的位置（lower_bound） |

左闭右开模板（求 lower_bound，找不到时返回插入位置）：

```python
def lower_bound(a, target):
    l, r = 0, len(a)
    while l < r:
        m = (l + r) // 2
        if a[m] < target:
            l = m + 1
        else:
            r = m
    return l

a = [1, 2, 2, 4, 5]
print(lower_bound(a, 2))  # 1：第一个 2 的下标
print(lower_bound(a, 3))  # 3：3 不存在，插入位置在 4 之前
print(lower_bound(a, 6))  # 5：比全部都大，插入位置是末尾
```

右边界（upper_bound，第一个大于目标的位置）只改一个比较符：

```python
def upper_bound(a, target):
    l, r = 0, len(a)
    while l < r:
        m = (l + r) // 2
        if a[m] <= target:
            l = m + 1
        else:
            r = m
    return l

def lower_bound(a, target):
    l, r = 0, len(a)
    while l < r:
        m = (l + r) // 2
        if a[m] < target:
            l = m + 1
        else:
            r = m
    return l

a = [1, 2, 2, 4, 5]
print(upper_bound(a, 2))  # 3：第一个大于 2 的位置
print(upper_bound(a, 2) - lower_bound(a, 2))  # 2：目标 2 出现 2 次
```

## 边界条件易错点

- 空数组：左闭右开写法 l = r = 0，循环一次不进，直接返回 0，不用特判。
- 目标比全部都小：lower_bound 返回 0；比全部都大：返回 len(a)。用返回值当下标前先校验范围，否则越界。
- 左闭右闭写法里 `while l <= r` 配 `l = m + 1 / r = m - 1`；左闭右开写法里 `while l < r` 配 `l = m + 1 / r = m`。把右闭的更新搬到右开写法里，`r = m - 1` 会把合法区间切掉一个元素；反过来把右开的更新搬到右闭写法里，`r = m` 在 l == r 时原地不动，死循环。
- 中点取法：`(l + r) // 2` 在 Python 里没有溢出问题；Java/C++ 里写 `l + (r - l) / 2`，总纲已提过。

## 旋转数组：先判哪半有序

旋转后的数组不再整体有序，但以中点为界，左右至少有一半是有序的。判断中点落在有序的那半，再决定目标可能在哪半。

```python
def search_rotated(nums, target):
    l, r = 0, len(nums) - 1
    while l <= r:
        m = (l + r) // 2
        if nums[m] == target:
            return m
        if nums[l] <= nums[m]:  # 左半有序
            if nums[l] <= target < nums[m]:
                r = m - 1
            else:
                l = m + 1
        else:  # 右半有序
            if nums[m] < target <= nums[r]:
                l = m + 1
            else:
                r = m - 1
    return -1

rot = [4, 5, 6, 7, 0, 1, 2]
print(search_rotated(rot, 0))  # 4
print(search_rotated(rot, 3))  # -1：不存在
```

worked 走一遍找 0：l = 0，r = 6，m = 3（值 7），左半 [4, 5, 6, 7] 有序，0 不在 [4, 7) 内，去右半，l = 4；m = 5（值 1），左半 [0, 1] 有序，0 在 [0, 1) 内，r = 4；m = 4（值 0），命中。

有重复元素时退化：`nums[l] == nums[m] == nums[r]` 时无法判断哪半有序，只能 `l += 1, r -= 1` 缩小范围，最坏退化到 O(n)。面试先写无重复版，再补这一句，说明知道边界。

## 答案二分：对答案做二分，不是对下标

当问题是“求最小的可行值 / 最大的可行值”，且可行性随答案单调变化（某个值可行，比它更宽松的值一定也可行），就可以对答案区间二分。模板是左闭右开求“最小可行值”：

```python
def min_max_split(nums, k):
    def feasible(limit):
        segs, cur = 1, 0
        for x in nums:
            if cur + x > limit:
                segs += 1
                cur = x
            else:
                cur += x
        return segs <= k

    lo, hi = max(nums), sum(nums)  # 答案一定在这个区间里
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

print(min_max_split([7, 2, 5, 10, 8], 2))  # 18：分成 [7, 2, 5] 与 [10, 8]
```

worked 核对：答案区间 [10, 32]。mid = 21 可行（[7, 2, 5] 与 [10, 8]），hi = 21；mid = 15 不可行（要 3 段），lo = 16；mid = 18 可行，hi = 18；mid = 17 不可行，lo = 18；lo == hi = 18，结束。判定函数是 O(n)，二分约 log(sum) 轮，总复杂度 O(n log sum)。

适用信号：题面出现“最小的最大值”“最大的最小值”“最少天数/次数”，且“某个值行不行”比“最优值是多少”好判断得多。

## 实数二分：固定迭代次数，别用整数退出条件

实数域没有“下一个整数”，`while l < r` 永远等不到相等。标准做法是固定迭代 100 次（每次区间减半，100 次后精度远超 double 的有效位数），或用 `while r - l > eps` 配一个明确的 eps。

```python
def sqrt2():
    lo, hi = 1.0, 2.0
    for _ in range(100):
        mid = (lo + hi) / 2
        if mid * mid < 2:
            lo = mid
        else:
            hi = mid
    return lo

print(sqrt2())  # 1.414213562373095
```

## 常见误区

- 二分的前提是单调性，不是“数组”：无序数组上二分结果纯属碰运气，总纲已强调过。
- 左闭右开返回的是位置，不是“是否找到”：找存在性要补一句 `l < len(a) and a[l] == target`。
- 旋转数组里 `nums[l] <= nums[m]` 用 `<=` 不用 `<`：左半只有一个元素时，l == m，`<` 会误判为右半有序。
- 答案二分的 lo、hi 初始值要取到“一定不可行”和“一定可行”的边界：lo 取 max(nums)（任何一段都不能小于单个元素），hi 取 sum(nums)（一段装下全部一定可行），区间外无答案。

## 小技巧与冷知识

【小技巧】只背一种写法，别两种混着背：全程用左闭右开 `while l < r` 配 `l = m + 1 / r = m`，lower_bound 与 upper_bound 只差一个比较符（`<` 改 `<=`）。一种写法练熟后，旋转数组、答案二分都能套同一个框架；两种写法来回切换是最常见的死循环来源。

【小技巧】二分写完先在 `[1, 2, 2, 4, 5]` 上手算三遍：找 2、找 3、找 6，分别覆盖“命中重复元素”“不存在插中间”“比全部都大”三种情况。死循环时在循环里打印 `l, m, r`，重点看 `l == r` 那一刻更新有没有原地不动——原地不动就是死循环的根。

【小技巧】把所有二分都想成“找第一个满足条件的下标”：先写一个返回布尔值的谓词 `ok(mid)`，再套 lower_bound 框架。找左边界时谓词是 `a[m] >= target`，答案二分时谓词是 `feasible(mid)`，旋转数组找最小值时谓词是“mid 在右半无序区”。谓词写对了，循环体几乎不用改。

【小技巧】答案二分的判定函数先单独测再套框架：拿原文的例子验证 `feasible(17)` 为假、`feasible(18)` 为真，确认单调性没反（可行值越大越容易可行），再套二分。判定函数里混进一个方向写反的判断，二分会安静地返回一个错答案，不报错、不死循环，最难查。

【小技巧】实数二分固定 100 次迭代就够了，不用再纠结 eps：100 次后区间宽度是初始宽度的 2^-100，远小于 double 约 2^-52 的有效精度，再多迭代也不会让结果更准。用 `while r - l > eps` 时 eps 选得太大提前停、选得太小可能因浮点舍入永远停不下来。

【小技巧】直接用标准库，别手写：Python 的 `bisect_left(a, x)` / `bisect_right(a, x)` 就是 lower_bound / upper_bound，而且是 C 实现的，比手写循环快；C++ 用 `std::lower_bound` / `std::upper_bound`，Java 用 `Arrays.binarySearch`。手写只留在面试和理解原理时，生产代码优先用库函数。

【小技巧】Java 里写 `l + (r - l) / 2` 防溢出，另一种写法是 `(l + r) >>> 1`：无符号右移一位等于除以 2，即使 `l + r` 溢出成负数，右移后仍是正确的中点（两个非负 int 之和溢出后最高位为 1，无符号右移把它当正数处理）。两种写法都对，团队里统一一种即可。

【小技巧】旋转数组找最小值不用先判哪半有序，换个比较对象：比较 `nums[m]` 与 `nums[r]`，`nums[m] > nums[r]` 说明最小值在右半，`l = m + 1`，否则 `r = m`。这个版本只有一条分支，比原文“先判哪半有序”的两分支写法短，出错面更小。

【小技巧】答案二分的 hi 上界在 Java/C++ 里要用 long：`sum(nums)` 超过 int 范围时先溢出再二分，答案从一开始就是错的。Python 没有这个问题，但跨语言复述同一道题时要记得补上类型提醒，面试官常在这里追问。

【冷知识】二分查找 1946 年就发表了，但第一个没有 bug 的实现直到 1962 年才出现：Jon Bentley 在《编程珠玑》里写过这段历史，他还做过调查，大多数专业程序员第一次写二分查找都会写错。二分查找的坑不在思路，在边界——这也是原文花整节讲区间不变式的原因。

【冷知识】Java 的 `Arrays.binarySearch` 也中过招：`(low + high) / 2` 在数组很大时 `low + high` 会溢出成负数，导致中点算错，这个 bug 从 JDK 1.2 一直存在，直到 2006 年 Joshua Bloch 写文章《Nearly All Binary Searches and Mergesorts are Broken》指出后才修复。修法正是 `low + (high - low) / 2`。

【冷知识】二分查找的最少比较次数有个下界：n 个元素的有序表，每次比较只有“小/大”两种出路，要区分 n+1 种可能结果（n 个位置加一种“不存在”），决策树至少要 ceil(log2(n+1)) 层。所以 O(log n) 不是“写得巧”，是信息论意义上的最优，换任何写法都突破不了。

【冷知识】数据均匀分布时插值查找比二分更快：它按目标值在取值范围里的比例猜中点位置，平均只要 O(log log n) 次比较。但代价是最坏退化到 O(n)，且只对数值均匀分布的数据有效，分布稍一倾斜就不如二分稳，标准库至今没把它当默认实现。

【冷知识】数组长度未知时先用指数查找探边界：从下标 1、2、4、8……指数级扩大，直到越界或超过目标，再在最后一个区间里二分。这就是处理“无界数组/流式数据”的标准套路，探边界花 O(log n)，二分花 O(log n)，总复杂度仍是 O(log n)。

【冷知识】三分查找不是二分的升级版：它每次把区间分成三份，只适用于单峰函数（先增后减）求极值，不适用于单调函数找目标。单调函数上用三分查找，每轮排除的区间比例更小、比较次数更多，一般比二分慢，别把它当成“分得越多越快”。

## 面试与自测

1. 左闭右开写法退出时 l 一定是第一个大于等于目标的位置吗？目标比全部元素都大时返回什么？
2. 旋转数组找目标时，为什么先判断 `nums[l] <= nums[m]`？有重复元素时会发生什么？
3. 答案二分和普通二分的区别是什么？lo、hi 的初始值应该怎么取？

### 参考答案

1. 是。循环维持的不变式是“第一个大于等于目标的位置一直在 [l, r) 内”：`a[m] < target` 时它一定在 m 右边，`l = m + 1`；否则它在 m 或 m 左边，`r = m`。退出时 l == r，就是那个位置。目标比全部都大时，所有元素都小于目标，l 一路走到 len(a)，返回 len(a)（插入位置），用它当下标前要先校验。
2. 因为旋转数组以中点为界，左右至少一半有序；`nums[l] <= nums[m]` 成立说明左半有序，就能在左半内用区间判断目标是否在内，否则目标一定在右半。`<=` 而非 `<` 是为了左半只剩一个元素（l == m）时仍判为左半有序。有重复元素且 `nums[l] == nums[m] == nums[r]` 时无法判断哪半有序，只能两边各缩一步，最坏退化到 O(n)。
3. 普通二分在下标区间里找一个已知存在（或判断存在）的值；答案二分在答案区间里找“最小可行值”，依赖可行性随答案单调变化。lo 取“一定不可行”的下界（如单个元素的最大值），hi 取“一定可行”的上界（如全部元素之和），保证最优答案落在 [lo, hi] 内；循环用左闭右开求最小可行值，退出时 lo 就是答案。
