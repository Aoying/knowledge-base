## 1. 分流原理：随机是因果的前提

- 一句话理解：A/B 测试不是“新版上线看看涨没涨”，而是“随机分流后比较两组”，随机是能谈因果的前提。
- 生活案例：外卖 App 把下单按钮从蓝色改成绿色。用户打开 App 时按随机数分流：一半看到蓝色（对照组），一半看到绿色（实验组）。因为分流是随机的，两组用户的年龄、地域、消费习惯分布基本一致，后面转化率的差距才能算到按钮颜色头上。
- 如果分流不随机会怎样：比如新用户全进实验组、老用户全进对照组，转化率一差，你根本不知道是按钮颜色的作用，还是新老用户本身行为不同。这叫混杂——分流不随机，因果就谈不下去。
- 分流单位：按用户分，不要按请求分。按用户 ID 哈希分流，同一用户在整个实验期内始终在同一组；按请求分流，同一用户今天进对照组、明天进实验组，两边的数据就互相污染了。
- AA 测试：正式实验前，先跑一次两组都是旧版的测试。两组转化率应该没有显著差异；如果 AA 就显著，说明分流系统本身有问题（比如分流比偏了、某类用户被过滤了），先修分流再跑实验。
- 实验期内冻结：分组逻辑、指标口径、分流比例中途不要改。改了任何一个，前后数据就不再可比，等于重做实验。

## 2. 样本量与功效：跑多少人才够

- 功效先说清：功效 = 1 − β，即“真实有效果时，你能成功发现它的概率”（[计算机基础/统计/统计推断与应用.md](计算机基础/统计/统计推断与应用.md) §4.8 已讲）。功效 80% 是惯例：真实有效果时，10 次实验里约 8 次能测出来。
- 公式拆解（两组比例检验，每组样本量 n）：

  n = [z_{α/2}·√(2p̄(1 − p̄)) + z_β·√(p1(1 − p1) + p2(1 − p2))]² / (p2 − p1)²

  - p1：对照组转化率（基线）；p2：实验组转化率（期望值）；p̄ = (p1 + p2) / 2，两组平均。
  - z_{α/2}：显著性门槛，α = 0.05 双侧时取 1.96。
  - z_β：功效门槛，功效 80% 时取 0.84，功效 90% 时取 1.28。
  - 分母 (p2 − p1)²：效应差的平方。效应越小，分母越小，样本量越大——而且是平方关系。

- 逐步代入（基线 10%，想测出 12%，α = 0.05 双侧，功效 80%）：
  - p̄ = (0.10 + 0.12) / 2 = 0.11。
  - 第一项：1.96 × √(2 × 0.11 × 0.89) = 1.96 × √0.1958 ≈ 1.96 × 0.4425 ≈ 0.867。
  - 第二项：0.84 × √(0.10 × 0.90 + 0.12 × 0.88) = 0.84 × √0.1956 ≈ 0.84 × 0.4423 ≈ 0.372。
  - 合计 0.867 + 0.372 = 1.239，平方 ≈ 1.535，除以 0.02² = 0.0004，得 3836.5，向上取整每组 3837 人。
  - 结果理解：2 个百分点的效应在 80% 功效下要每组约 3800 人，两组共约 7700 人。小效应本来就不便宜。

- 对照组（只改一个条件，看样本量怎么变）：
  - 效应放大到 5 个点（10% → 15%），其余不变：每组约 685 人。效应从 2 个点变 5 个点（2.5 倍），样本量缩小到约 1/5.6——平方关系就是这么陡。
  - 功效提到 90%（z_β = 1.28），效应仍是 2 个点：每组约 5137 人。功效从 80% 提 10 个点，样本量多约 1/3。
  - Python 复现（下面代码实跑结果与正文一致）：

```python
import math
def n_per_group(p1, p2, za=1.96, zb=0.84):
    pb = (p1 + p2) / 2
    return ((za * math.sqrt(2 * pb * (1 - pb)) + zb * math.sqrt(p1 * (1 - p1) + p2 * (1 - p2))) ** 2) / ((p2 - p1) ** 2)
print(math.ceil(n_per_group(0.10, 0.12)))  # 3837
print(math.ceil(n_per_group(0.10, 0.15)))  # 685
```

- 与抽样篇公式的区别：[计算机基础/统计/抽样方法与样本量.md](计算机基础/统计/抽样方法与样本量.md)的 n = z²p(1 − p)/E² 回答的是“估计一个比例要多准”，本节公式回答的是“检验两个比例的差要多大把握”。一个讲估计精度，一个讲检验功效，目的不同不要混用。
- 最小可测效应（MDE）：样本量固定时，只能测出大于某个值的效应；小于它的真实效应大概率测不出来。实验前先算 MDE：如果 MDE 是 5 个点，而业务上 2 个点的提升就值得做，那这个实验设计本身就是测不出来的——要么加样本，要么接受测不出来。

## 3. 显著性判定：差值、置信区间、p 值三件套

- 判定只看 p 值不够（[计算机基础/统计/统计推断与应用.md](计算机基础/统计/统计推断与应用.md) §5.5 已讲）：要同时看差值多大、置信区间多宽、p 值多少。差值讲业务意义，区间讲不确定性，p 值讲反常程度。
- 逐步代入（跑够样本后的判定）：对照组 4000 人转化 400 人（10%），实验组 4000 人转化 480 人（12%），差值 2 个百分点。
  - 差值的标准误 SE = √(0.10 × 0.90 / 4000 + 0.12 × 0.88 / 4000) = √0.0000489 ≈ 0.006993（约 0.70 个百分点）。
  - z = 0.02 / 0.006993 ≈ 2.86，双侧 p 值约 0.0042 < 0.05，显著。
  - 95% 置信区间：0.02 ± 1.96 × 0.006993 = 0.02 ± 0.01371，即 [0.0063, 0.0337]，也就是 0.63 个百分点到 3.37 个百分点。
  - 结果怎么理解：区间不含 0，与 p < 0.05 的结论一致；更重要的是区间下限 0.63 个百分点——即使按最保守估计，提升也至少有 0.63 个点。接下来是业务判断：0.63 个点值不值得上线？这一步统计给不了答案，要业务拍板。
  - Python 复现（实跑结果与正文一致）：

```python
import math
se = math.sqrt(0.10 * 0.90 / 4000 + 0.12 * 0.88 / 4000)
z = 0.02 / se
p = math.erfc(abs(z) / math.sqrt(2))
print(round(se, 6), round(z, 2), round(p, 4))  # 0.006993 2.86 0.0042
print(round(0.02 - 1.96 * se, 4), round(0.02 + 1.96 * se, 4))  # 0.0063 0.0337
```

- 显著不等于重要：样本量极大时，0.1 个点的差距也能显著，但业务上毫无意义；反过来，不显著也不等于没效果，可能是样本量不够（见第 2 节）。显著性回答“是不是抖动”，重要性回答“值不值得”，两个问题分开答。

## 4. peeking 偷看：中途天天看 p 值的危害

- 一句话理解：peeking 是“实验没跑完就天天看 p 值，看到小于 0.05 就提前停”。它破坏了显著性水平的含义。
- 为什么错：显著性水平 α = 0.05 的意思是“只检验一次时，假阳性概率是 5%”。中途看了 5 次、每次都按 0.05 判，等于做了 5 次检验，假阳性概率不再是 5%。
- 算术示意（独立情形的上界）：如果 5 次检验相互独立，至少错一次的概率 = 1 − 0.95⁵ ≈ 22.6%。实际偷看是累积数据、检验之间相关，膨胀幅度小于这个上界，但依然显著高于 5%——方向是确定的：看得越勤，假阳性越高。
- 提前停的第二个危害：效应高估。刚好在早期“显著”的那次停下来，看到的差值往往是被随机波动放大的那次——真实效应通常比这次看到的小。这叫赢家诅咒直觉：只挑显著的结果报，报出来的数系统性偏大。
- 正确做法二选一：事先定好样本量和唯一的检验时机，跑够再看；或者用序贯检验方法（如 alpha spending，把 α 预算分配到各次检验），而不是每次都按 0.05 判。两种做法都要求“规则事先定”，看完数据再定规则等于没定。

## 5. 常见坑

### 5.1 辛普森悖论：整体与分组结论打架

- 推断篇 §5.2 已讲“整体与分组结论打架时找混杂变量”，这里给一个 A/B 专属版本：流量配比变了。
- 完整数字：按新老用户分组。

|  | 对照组 | 实验组 |
|---|---|---|
| 新用户 | 900 人，转化 10%（90 人） | 100 人，转化 9%（9 人） |
| 老用户 | 100 人，转化 30%（30 人） | 900 人，转化 29%（261 人） |
| 总体 | 120 / 1000 = 12% | 270 / 1000 = 27% |

- 读法：分组看，实验组新用户 9% < 对照组 10%，老用户 29% < 对照组 30%，两组都更低；总体看，实验组 27% 远高于对照组 12%。结论完全相反。
- 原因：流量配比变了。实验组老用户占 90%，对照组老用户只占 10%，而老用户转化天然高（30% 左右），总体就被老用户占比抬高了。不是新版更好，是两组根本不是同一类人。
- 对策：实验结束先核对分流比（见 5.4 的 SRM 检查），再按关键分层（新老用户、渠道、地域）各看一遍分组结论；整体与分组打架时信分组，先找配比变化的原因。

### 5.2 新奇效应：新版蜜月期

- 一句话理解：新版上线初期，用户因为新鲜多点几下，转化虚高；新鲜感一过，效应就回落。
- 对策：跑够完整周期（至少 1–2 周，覆盖工作日与周末），并看效应是否随时间稳定；不要只看前 3 天的数据就下结论。如果效应逐日衰减，先怀疑新奇效应，再谈真实提升。

### 5.3 样本污染：同一用户进了两组

- 表现：按请求分流、多设备登录、清 cookie、内部测试号混入正式流量，都会让同一用户出现在两组里。
- 后果：两组数据互相掺水，真实效应被稀释——本来 2 个点的提升，污染后可能只剩 1 个点，检验就更难显著。
- 对策：按用户 ID 哈希分流；排除内部测试流量；实验期内不改分组逻辑；上线前跑 AA 测试验证分流干净。

### 5.4 SRM：分流比失衡

- 一句话理解：SRM（样本比失衡）是“实际分流比偏离设计比”，说明分流系统或过滤逻辑出了问题。
- 逐步代入：设计 50/50 分流，跑了 10000 人，实验组实际 5200 人（52%）。在设计比下，比例的标准误 = √(0.5 × 0.5 / 10000) = 0.005，z = (0.52 − 0.50) / 0.005 = 4.0，显著偏离。结论：不是抽样抖动，分流有问题，先查分流代码和过滤逻辑，不要直接读实验结论。
- 注意：SRM 本身不告诉你哪边错了，只告诉你“分流不可信”。查出来之前，实验结论一律挂起。

### 5.5 换指标与多指标：p-hacking

- 表现：主指标不显著，就换个指标再测；或者同时看 10 个指标，挑显著的那个报。每次换指标、加指标，都是一次新的检验，假阳性跟着涨。
- 对策：实验前定好一个主指标和它的判定标准；多指标同时看时用 Bonferroni 校正一句话：m 个指标，门槛从 α 收紧到 α/m（比如 10 个指标、α = 0.05 时每个按 0.005 判）。校正不是万能，事先定指标才是根本。


## 公式精讲与练习：比例差样本量与显著性三件套

原篇 §2 给了两组比例检验的样本量公式、§3 给了显著性判定三件套，本节把两个公式拆开讲透：每个符号是什么意思、数字怎么一步步代入、结果往哪个方向拉动，再配 4 道练习题。生活案例即每小节的计算例题本身，不另堆案例（原篇已有分流、辛普森等案例）。

### 样本量公式：两项分别对应 α 门槛与功效门槛

公式（两组比例检验，每组样本量 n）：

n = [z_{α/2}·√(2p̄(1 − p̄)) + z_β·√(p1(1 − p1) + p2(1 − p2))]² / (p2 − p1)²

| 符号 | 含义 | 手算时注意 |
|---|---|---|
| p1 | 对照组转化率（基线） | 实验前就要有的估计值，不是跑完才回填的数 |
| p2 | 实验组转化率（期望值） | p2 − p1 是你想测出的效应，不是跑完观测到的差值 |
| p̄ = (p1 + p2) / 2 | 两组平均转化率 | 只用在第一项里 |
| z_{α/2} | 显著性门槛，α = 0.05 双侧时取 1.96 | 第一项对应“原假设下不冤枉好人”的门槛 |
| z_β | 功效门槛，功效 80% 时取 0.84，90% 时取 1.28 | 第二项对应“真实有效果时能测出来”的门槛 |
| 分母 (p2 − p1)² | 效应差的平方 | 效应减半，样本量变 4 倍；算完向上取整，不能四舍五入往下抹 |

与抽样篇公式的区别（原篇 §2 已定，这里只钉一句）：抽样篇 n = z²p(1 − p)/E² 回答“估计一个比例要多准”，本节公式回答“检验两个比例的差要多大把握”。一个讲估计精度，一个讲检验功效，目的不同不要混用。

生活案例（全新数字，不重复原篇）：某电商 App 把商品详情页的“加入购物车”按钮文案从“加入购物车”改成“立即抢购”。基线转化率 p1 = 20%，期望测出 p2 = 24%（差 4 个点），α = 0.05 双侧，功效 80%。逐步算：

1. p̄ = (0.20 + 0.24) / 2 = 0.22。
2. 第一项：1.96 × √(2 × 0.22 × 0.78) = 1.96 × √0.3432 ≈ 1.96 × 0.5858 ≈ 1.148。
3. 第二项：0.84 × √(0.20 × 0.80 + 0.24 × 0.76) = 0.84 × √0.3424 ≈ 0.84 × 0.5851 ≈ 0.492。
4. 合计 1.148 + 0.492 = 1.640，平方后除以 0.04² = 0.0016，得约 1680.5，向上取整每组 1681 人，两组共约 3362 人。
5. 读法：4 个点的效应在 80% 功效下每组约 1680 人。注意 n 是“精度下限”：算出 1680.5 只能取 1681，取 1680 会使实际能测出的最小效应略大于 4 个点——取整永远向上进位。

图示：样本量往哪个方向拉动（实验设计前先对一下方向，数字错了方向能兜底发现）。

| 变动 | 样本量变化 | 原因 |
|---|---|---|
| 效应差减半（如 4 个点 → 2 个点） | 变约 4 倍（平方关系） | 分母是差值的平方 |
| 功效 80% → 90% | 变大约 1.3 倍 | z_β 从 0.84 升到 1.28 |
| 基线靠近 50%（如 20% → 45%） | 变大 | p(1 − p) 在 50% 处最大，方差最大 |
| 基线远离 50%（如 20% → 5%） | 变小 | p(1 − p) 变小，方差变小 |

### 显著性三件套：差值、置信区间、p 值各回答一个问题

接上例：实验跑够样本后，对照组 3000 人转化 600 人（20%），实验组 3000 人转化 690 人（23%），差值 3 个百分点。逐步算：

1. 差值的标准误 SE = √(0.20 × 0.80 / 3000 + 0.23 × 0.77 / 3000) = √0.0001124 ≈ 0.0106（约 1.06 个百分点）。
2. z = 0.03 / 0.0106 ≈ 2.83，双侧 p 值约 0.0047 < 0.05，显著。
3. 95% 置信区间：0.03 ± 1.96 × 0.0106 = 0.03 ± 0.0208，即 [0.0092, 0.0508]，也就是 0.92 个百分点到 5.08 个百分点。
4. 三件套各回答什么：

| 一件 | 本例数值 | 回答的问题 |
|---|---|---|
| 差值 3 个点 | 0.03 | 效应有多大（业务意义的起点） |
| 95% 置信区间 [0.92, 5.08] 个点 | 不含 0 | 不确定性有多大；下限 0.92 个点是“最保守估计也有”的提升 |
| p 值约 0.0047 | < 0.05 | 在“两组其实没差别”的前提下，看到当前或更大差距的概率——即反常程度 |

5. p 值的红线表述（只用这一种）：p 值 = 在原假设成立的前提下，观察到当前或更极端数据的概率。它不是原假设为真的概率，不是结论正确的概率，也不是效应大小的度量。p = 0.0047 不能读成“原假设为真的概率是 0.47%”。
6. 最后一步是业务判断：区间下限 0.92 个点——即使按最保守估计，提升也至少有 0.92 个点。0.92 个点值不值得上线？统计给不了答案，要业务拍板。显著回答“是不是抖动”，重要回答“值不值得”，两个问题分开答。

### 练习题

1. 样本量：某邮件标题实验，基线打开率 5%，想测出 7%（差 2 个点），α = 0.05 双侧、功效 80%，每组需要多少人？（向上取整）
2. peeking：实验中途看了 3 次，每次都按 0.05 判。独立情形下至少错一次的概率上界是多少？除此之外，提前停还有什么危害？正确做法是什么？
3. 显著性判定：对照组 2000 人转化 240 人（12%），实验组 2000 人转化 280 人（14%），差值 2 个点。算 SE、z、双侧 p 值约数、95% 置信区间，结论是拒绝还是不拒绝？并判断：下列说法哪个错？A. p ≈ 0.06 说明原假设为真的概率是 6%。B. p ≈ 0.06 说明在原假设成立的前提下，看到当前或更大差距的概率约 6%。
4. 显著 ≠ 重要：某实验差值 0.3 个点，95% 置信区间 [0.05, 0.55] 个点，p = 0.02。统计上显著吗？能不能据此直接上线？为什么？

### 参考答案

1. p̄ = (0.05 + 0.07) / 2 = 0.06。第一项：1.96 × √(2 × 0.06 × 0.94) = 1.96 × √0.1128 ≈ 1.96 × 0.3359 ≈ 0.658。第二项：0.84 × √(0.05 × 0.95 + 0.07 × 0.93) = 0.84 × √0.1126 ≈ 0.84 × 0.3356 ≈ 0.282。合计约 0.940，平方后除以 0.02² = 0.0004，得约 2209.7，向上取整每组 2210 人。对照：同样 2 个点、基线 20%（20%→22%）时每组约需 6503 人——低基线反而更便宜，因为方差 p(1 − p) 在 5% 时远小于 20% 时。不要被相对提升误导：5%→7% 是相对 +40%，20%→22% 仅相对 +10%，但公式只认绝对差，相对值好看不等于实验便宜。
2. 上界 = 1 − 0.95³ ≈ 14.3%，远高于单次检验的 5%（实际偷看是累积数据、检验相关，膨胀幅度小于这个上界，但方向确定：看得越勤，假阳性越高）。提前停的第二个危害是效应高估：刚好在早期“显著”的那次停下来，看到的差值往往是被随机波动放大的那次，真实效应通常更小（赢家诅咒）。正确做法二选一：事先定好样本量和唯一的检验时机，跑够再看；或者用序贯检验方法（如 alpha spending，把 α 预算分配到各次检验）。两种做法都要求“规则事先定”。
3. SE = √(0.12 × 0.88 / 2000 + 0.14 × 0.86 / 2000) = √0.000113 ≈ 0.01063。z = 0.02 / 0.01063 ≈ 1.88，双侧 p 值约 0.060 > 0.05。95% 置信区间：0.02 ± 1.96 × 0.01063 = 0.02 ± 0.0208，即 [−0.0008, 0.0408]，含 0。结论：不拒绝原假设——不显著不等于没效果，可能是样本量不够（2 个点的效应在每组 2000 人时本来就难测出来）。A 错：p 值不是原假设为真的概率；B 对：p 值是在原假设成立前提下看到当前或更大差距的概率。
4. 统计上显著：区间不含 0 且 p = 0.02 < 0.05。但不能据此直接上线：区间下限只有 0.05 个点，业务价值极小——显著只回答“不是抖动”，值不值得要看下限够不够业务上“值得做”的最小值。下限 0.05 个点即使显著也不值得，显著与重要是两个问题。

## 易混淆对比表

| 容易混淆的一对 | 区别 | 一句话记忆 |
|---|---|---|
| 显著 vs 重要 | 显著回答“是不是抖动”；重要回答“值不值得做” | 显著是统计判断，重要是业务判断 |
| 相对提升 vs 绝对差值 | 相对提升是差值除以基线（10%→12% 是相对提升 20%）；绝对差值是 2 个百分点 | 相对值好看，绝对值实在 |
| 偷看 vs 序贯检验 | 偷看是每次都按 0.05 判；序贯检验是事先把 α 预算分配到各次 | 一个无规则，一个有预算 |
| 估计样本量 vs 功效样本量 | 估计公式回答“比例估计要多准”；功效公式回答“检验差值要多大把握” | 一个估一个数，一个比两组 |
| 新奇效应 vs 真实效应 | 新奇效应随时间衰减；真实效应跑完整周期后稳定 | 看时间趋势，不看头三天 |
| SRM 偏离 vs 抽样抖动 | SRM 是系统性偏离（z 值很大）；抽样抖动在标准误范围内 | 偏离几个标准误就不是抖动 |

## 常见误区

- p < 0.05 就上线：错。还要看置信区间下限是否达到业务上“值得做”的最小值；下限 0.1 个点即使显著也不值得。
- 实验中途看到显著就停：错。见第 4 节，偷看放大假阳性，还会高估效应。
- 只报相对提升：错。10%→12% 是相对提升 20%，但绝对只差 2 个点，样本量不大时根本站不住；相对值和绝对值、样本量一起报。
- 整体显著就不看分组：错。辛普森悖论下整体结论可能完全反转，分组结论才是可信的。
- 样本量越大越好：错。精度收益递减（见抽样篇），成本却上升；而且跑太久会撞上新奇效应窗口、节假日、版本迭代，数据反而不干净。

## 小技巧与冷知识

【小技巧】分流哈希要给每个实验加盐：直接拿用户 ID 哈希取模，同一用户在所有实验里会被分到“同一侧”，实验之间不再独立。正确做法是把实验名（或实验 ID）当盐值拼进哈希输入再取模，同一个用户在不同实验里的分组才近似独立；多个实验并行跑时，这一步不做，实验结果会互相污染。

【小技巧】样本量按“分析单位”算，不按“曝光”算：分流单位是用户，分析时若按曝光或会话一条条算，同一个用户的多次行为是相关的，标准误会被低估、p 值虚小。正确做法是先按用户聚合出“每人一个指标值”再检验，或者用聚类稳健标准误；分流单位和分析单位不一致，是线上实验里最容易被忽略的方差坑。

【小技巧】想缩短实验时间，先上 CUPED 而不是加流量：CUPED 用实验前同一指标做协变量回归调整，把用户“本来就有的差异”从结果里扣掉，方差乘上 (1 − ρ²)，ρ 是实验前后指标的相关系数。ρ = 0.5 时样本量省约 25%，ρ = 0.7 时省约 49%（已复算）。它对人均消费这类连续指标最划算，对二值转化率效果弱；新用户没有实验前数据，这招对他们无效。

【小技巧】比率指标别直接套比例公式：人均 GMV、人均点击这类“总量除以人数”的指标，分子分母都随机，方差不能用 p(1 − p) 那套算。要么用 delta 方法推方差，要么直接做置换检验；把比率指标当成普通比例塞进样本量公式，算出来的 n 根本不准。

【小技巧】单侧检验能省样本，但只能看一个方向：单侧 α = 0.05 的门槛比双侧低，同样效应要的样本更少。可一旦新版可能变差（比如改动涉及核心流程），单侧检验发现不了伤害。上线决策要“防变差”时坚持双侧；只有“变差也不可能、只关心有没有变好”的场景才考虑单侧。

【小技巧】实验要跑满完整周数，不只跑够人数：工作日和周末的用户行为不一样，跑 5 天和跑 7 天的样本构成不同，效应也可能不同。至少跑满 1 个整周、最好 2 周，让工作日与周末的配比在两组里自然对齐；只看“人数够了就停”，等于把星期几这个混杂变量留在了实验里。

【小技巧】主指标之外事先定护栏指标：比如留存、崩溃率、客服投诉量，主指标涨但护栏跌，就不能上线。护栏指标只做“有没有变差”的单侧判定，不参与“挑显著”的游戏；实验前就要写清护栏的判定线，跑完再补护栏等于给自己留了改口的后门。

【小技巧】实验前先分层随机化，别只靠事后分组：按新老用户、渠道等关键维度先分层、层内再随机，能保证每层两组人数接近，从源头上防住配比漂移。事后分组只能“看出来”辛普森式的问题，分层随机能让它根本不发生；分层维度不要贪多，2–3 个最关键的就够了。

【小技巧】只分析真正“触发”了改动的用户：改动只在某个页面生效时，没进过那个页面的用户根本没接触到实验，全量分析会把他们也算进来稀释效应。正确做法是只分析触发用户，但要先确认两组的触发率一致——如果实验本身改变了触发率（比如新版让更多人进到该页面），触发分析就又引入了新的选择偏差。

【小技巧】基线转化率要用最近 2–4 周的真实数据，别拍脑袋：样本量对基线很敏感。同样测 2 个点效应、功效 80%，基线 10% 时每组要 3837 人，基线实际是 11% 时要 4139 人，基线 9% 时只要 3527 人（已复算）。基线估错 1 个点，样本量就差约 300 人——跑之前先去数数，别凭感觉填。

【小技巧】主指标显著后，留一小撮用户长期不放量：短期显著可能是新奇效应，留 1%–5% 的用户长期留在对照组做 holdout，几周后再对比，能看到效应是稳定住了还是衰减回去了。全量上线就等于把长期对照组毁了，之后再想验证“当时那个提升还在不在”就没数据了。

【冷知识】Google 的第一次 A/B 测试在 2000 年：测的是搜索结果每页显示多少条。这个实验一度被误读为“多显示结果是负面的”，后来发现只是因为结果多了、页面加载变慢——延迟本身就是一个变量。从第一天起，A/B 测试的教训就是“你以为在测 A，其实在测 A + 副作用”。

【冷知识】功效 80% 不是算出来的最优值，是 Cohen 在 1992 年《A Power Primer》里提议的惯例：α = 0.05、功效 0.80 时，两类错误的风险比正好是 4:1。换句话说，“80% 功效”是统计学界约定俗成的折中，不是大自然规定的常数；功效提到 90% 完全合理，只是样本量要多约三分之一。

【冷知识】辛普森悖论的名字比现象晚了二十年：Pearson 在 1899 年、Yule 在 1903 年就提到过类似的关联反转，Simpson 在 1951 年的论文《The Interpretation of Interaction in Contingency Tables》里系统讨论了它，而“辛普森悖论”这个名字是 Blyth 在 1972 年才起的。原文 §5.1 的新老用户例子，本质上是同一类问题在流量配比上的翻版。

【冷知识】随机对照实验的理论源头是农田：Ronald Fisher 在 1920 年代为农业田间试验建立了随机化、重复和区组设计的理论，A/B 测试就是这套理论搬到线上的版本。分流、AA 测试、SRM 检查这些流程，都是“田间试验”在互联网上的对应物——随机化不是互联网发明的，是从农田里长出来的。

【冷知识】微软的统计是：大约三分之二的想法在对照实验里没有正向效果，Bing 上这个比例接近 80%–90%。这不是说想法大多很差，而是说“凭直觉判断哪个改动有效”本身就很不可靠——实验的价值不只是验证好想法，更是快速杀掉那些看起来很好、实际没用的想法。

【冷知识】多臂老虎机（multi-armed bandit）和 A/B 测试不是一回事：老虎机边测边把流量导向当前表现好的版本，收敛快、浪费的流量少，但拿不到两组严格可比的干净估计。想快速“选个不差的版本上线”用老虎机，想严谨回答“新版比旧版好多少”还是要用固定分流的 A/B 测试；省流量和可比性，只能二选一。

## 面试与自测

1. 基线转化率 10%，想测出 12%（差 2 个点），α = 0.05 双侧、功效 80%，每组需要多少人？如果只想测 5 个点的效应呢？
2. 实验中途每天看 p 值，第五天 p = 0.04 就停了，为什么不对？至少说出两个理由。
3. 下表是某实验按新老用户的分组结果，整体结论与分组结论哪个可信？为什么？

|  | 对照组 | 实验组 |
|---|---|---|
| 新用户 | 900 人，转化 10% | 100 人，转化 9% |
| 老用户 | 100 人，转化 30% | 900 人，转化 29% |

### 参考答案

1. 每组约 3837 人（公式见第 2 节，3836.5 向上取整）。只测 5 个点（10%→15%）时每组约 685 人。效应从 2 个点变 5 个点，样本量缩小到约 1/5.6，平方关系。
2. 理由一：多次检验放大假阳性，5 次独立检验至少错一次的概率上界约 22.6%，远高于 5%。理由二：样本量没跑够就停，看到的效应往往是被随机波动放大的，真实效应通常更小。正确做法是事先定好样本量和检验时机，或用序贯检验方法。
3. 分组结论可信。分组看实验组两组都更低（新用户 9% < 10%，老用户 29% < 30%），总体反超是因为流量配比变了（实验组老用户占 90%，对照组只占 10%），老用户转化天然高抬高了总体。应先查 SRM 与分流原因，再信分组结论。
