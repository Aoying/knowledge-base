# 数据结构与算法

> 程序 = 数据结构 + 算法。面试要考，工程里天天用（缓存淘汰、排行榜、任务调度）。

## 复杂度

- 时间/空间复杂度：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)。
- 算平均情况别只算最坏：HashMap 查找平均 O(1)，最坏 O(n)（全哈希冲突）。
- 空间换时间是工程常态：缓存、索引、预计算都是这个思想。

## 线性结构

| 结构 | 特点 | 场景 |
|---|---|---|
| 数组 | 连续内存，随机访问 O(1) | 二分查找 |
| 链表 | 插入删除 O(1) | LRU 底层、频繁头插删 |
| 栈 | LIFO | 函数调用、括号匹配、DFS |
| 队列 | FIFO | BFS、任务队列、削峰 |
| 双端队列 | 两头进出 | 滑动窗口最大值 |

## 哈希表

- 冲突解决：拉链法（Java HashMap）/ 开放寻址（Python dict）。
- 负载因子 0.75 扩容是工程折中：空间 vs 冲突概率。
- 别用可变对象当 key：Java 里改了影响 hashCode 的字段就找不回来了。

## 树

- 二叉搜索树：左<根<右；退化成链表时 O(n)，AVL/红黑树自平衡保 O(log n)。
- B+ 树：MySQL 索引的底层，多路 + 叶子链表，范围查询友好，见 [数据库/MySQL/MySQL-数据库.md](数据库/MySQL/MySQL-数据库.md)。
- 堆（优先队列）：TopK、定时任务（DelayQueue 就是堆）。
- Trie：前缀搜索、敏感词过滤。

## 图

- 存法：邻接表（稀疏图）/ 邻接矩阵（稠密图）。
- 遍历：BFS（最短路径）/ DFS（连通性、拓扑排序）。
- 工程映射：依赖关系（Maven 构建顺序就是拓扑排序）、流程图。

## 排序

| 算法 | 平均 | 稳定 | 场景 |
|---|---|---|---|
| 快排 | O(n log n) | 否 | 通用最快 |
| 归并 | O(n log n) | 是 | 外排序、链表排序 |
| 堆排 | O(n log n) | 否 | TopK |
| 计数/基数 | O(n) | 是 | 范围有限的整数 |

## 高频模式

1. 双指针：有序数组两数之和、链表判环。
2. 滑动窗口：最长无重复子串；限流本质上也是窗口。
3. 二分：有序查找；`while (l <= r)` 模板背下来。
4. DFS/BFS：岛屿数量、层序遍历。
5. 动态规划：爬楼梯、背包；先暴力递归再加备忘录。
6. 回溯：全排列；做选择→递归→撤销选择。

## 工程里的算法

- LRU：HashMap + 双向链表，LinkedHashMap 现成的；Redis 也有近似 LRU。
- 一致性哈希：分布式缓存扩容不抖动。
- 布隆过滤器：缓存穿透防护，Guava / RedisBloom 都有。


## 二分模板（背下来）

```java
// 左闭右闭，找不到返回 -1
int binarySearch(int[] a, int target) {
    int l = 0, r = a.length - 1;
    while (l <= r) {
        int m = l + (r - l) / 2;  // 防溢出，不写 (l+r)/2
        if (a[m] == target) return m;
        if (a[m] < target) l = m + 1; else r = m - 1;
    }
    return -1;
}
// 找左边界：相等时 r = m - 1，最后 l 就是左边界（需校验 a[l] == target）
```

- 二分不只查数组：单调答案都能二分（"最小的最大值"类问题）。
- `l + (r - l) / 2` 是面试加分项，int 溢出在生产代码里真实发生过。

## LRU 手写（HashMap + 双向链表）

```java
class LRUCache {
    static class Node { int k, v; Node prev, next; Node(int k, int v){this.k=k;this.v=v;} }
    private final int cap; private final Map<Integer, Node> map = new HashMap<>();
    private final Node head = new Node(-1,-1), tail = new Node(-1,-1); // 哨兵
    { head.next = tail; tail.prev = head; }
    public int get(int k) {
        Node n = map.get(k); if (n == null) return -1;
        moveToHead(n); return n.v;
    }
    public void put(int k, int v) {
        Node n = map.get(k);
        if (n != null) { n.v = v; moveToHead(n); return; }
        n = new Node(k, v); map.put(k, n); addHead(n);
        if (map.size() > cap) { Node last = tail.prev; remove(last); map.remove(last.k); }
    }
    private void moveToHead(Node n){ remove(n); addHead(n); }
    private void remove(Node n){ n.prev.next = n.next; n.next.prev = n.prev; }
    private void addHead(Node n){ n.next = head.next; n.prev = head; head.next.prev = n; head.next = n; }
}
```

- 三个操作缺一不可：get/put 时把节点搬到头，超容量时从尾淘汰。
- 生产直接用 `LinkedHashMap(cap, 0.75f, true)` 的 `removeEldestEntry`；但面试要求手写上面这个。

## 限流算法（三种必会）

| 算法 | 原理 | 特点 |
|---|---|---|
| 固定窗口 | 计数器，窗口重置清零 | 简单，边界有 2 倍突发 |
| 滑动窗口 | 小窗口滚动 | 平滑，Redis 里最常用 |
| 令牌桶 | 定速放令牌，请求拿令牌 | 允许突发，Guava RateLimiter |
| 漏桶 | 定速出水 | 强制匀速，队列满了就丢 |

- Java 后端实战：Guava `RateLimiter`（令牌桶，单机）、Sentinel（滑动窗口，集群）、网关层 Redis + Lua 做滑动窗口限流。
- 滑动窗口 Redis 实现思路：ZSET 存时间戳，`ZREMRANGEBYSCORE` 删过期 + `ZCARD` 计数 + `ZADD`，三步放 Lua 里保证原子。
- 见 [开发语言/Java/Java.md](开发语言/Java/Java.md) 并发相关章节（如有 Sentinel 笔记可互链）。

## 并查集（Union-Find）

- 解决"连通性"：用户好友圈、账号合并、Kruskal 最小生成树。
- 路径压缩 + 按秩合并，近乎 O(1)：
```java
int find(int x){ return p[x]==x ? x : (p[x]=find(p[x])); } // 路径压缩一行
void union(int a,int b){ a=find(a); b=find(b); if(a!=b) p[a]=b; }
```

## 快排分区要点

- 递归出口别忘；基准取中位数/随机防最坏 O(n²)（近乎有序数组是快排杀手）。
- 工程里直接用 `Arrays.sort`（双轴快排）和 `Collections.sort`（TimSort，稳定）。

## 复杂度速判清单

- 两层循环 n²、双指针/滑动窗口 n、堆 n log n、二分 log n、递归树画出来看节点数。
- 递归空间 = 递归深度；DP 空间常可压缩到一维（背包、爬楼梯）。

## 基础知识补强

### 核心概念与术语

- 数据结构：数据在内存中的组织方式，决定了增删改查各自要付出多少代价。
- 算法：解决问题的有限步骤序列；同一问题可有多种算法，差别在效率和空间。
- 抽象数据类型（ADT）：只定义"能做什么操作"，不定义怎么实现。栈、队列都是 ADT。
- 逻辑结构 vs 物理结构：逻辑上是线性表，物理上可以用数组（顺序存储）或链表（链式存储）实现。
- 大 O 表示法：描述输入规模 n 增大时，耗时/空间的增长量级；忽略常数系数和低阶项。
- O(1) 不等于"只做一步"，而是步数不随 n 增长；O(n) 里也可以藏着很大的常数。
- 最好/平均/最坏：同一算法在不同输入下表现不同，评估时先说清讨论的是哪一种。
- 均摊分析：单次操作偶尔很贵（如数组扩容复制），但平均到每次仍是 O(1)。
- 原地算法：只用 O(1) 额外空间；稳定排序：相等元素的相对顺序排序后不变。
- 递归深度就是隐形的空间成本：递归调用占调用栈，深度过大直接栈溢出。

### 基础知识与用法

数组下标为什么能 O(1) 随机访问，先记住地址公式：

```text
元素地址 = 首地址 + 下标 × 元素大小
下标从 0 开始，就是为了让首元素偏移为 0，公式最简。
```

动态数组（ArrayList 一类）扩容的心智模型：

```text
容量满 → 申请约 1.5~2 倍新数组 → 整体拷贝 → 释放旧数组
单次扩容 O(n)，但容量翻倍使拷贝次数被摊薄，尾插均摊 O(1)。
扩容因子太小：频繁拷贝；太大：浪费内存，1.5~2 是折中。
```

链表节点与遍历的基本形态（伪代码）：

```text
Node { value, next }
head -> [1] -> [2] -> [3] -> null
遍历：p = head; while p != null: 处理 p.value; p = p.next
链表没有下标：找第 k 个元素只能从头走 k 步，O(n)。
双向链表多一个 prev 指针，换来可反向遍历、已知节点时 O(1) 删除。
```

二叉树遍历是树一切操作的基础，四种顺序只差"访问根的时机"：

```text
前序：根 → 左 → 右    （复制树、表达式前缀式）
中序：左 → 根 → 右    （二叉搜索树中序输出即有序序列）
后序：左 → 右 → 根    （删树、算目录大小，先处理子再处理父）
层序：按层从左到右    （用队列实现，就是 BFS）
```

堆在数组里的下标关系（完全二叉树不存指针，全靠算）：

```text
下标从 0 开始：父 = (i - 1) / 2，左孩子 = 2i + 1，右孩子 = 2i + 2
大顶堆：每个节点都不小于它的孩子，堆顶就是最大值。
插入：放末尾再上浮；删堆顶：末尾元素挪到顶再下沉，各 O(log n)。
```

三个最朴素的排序先理解，再谈快排（以升序为例）：

```text
冒泡：相邻比较交换，每轮把最大值冒到末尾，O(n²)，稳定
选择：每轮从未排序区选最小值放到前面，O(n²)，不稳定，交换次数最少
插入：把新元素插进已排序区的合适位置，O(n²)，稳定
     近乎有序的数据插入排序接近 O(n)，小数据量时常数比快排还小
```

动态规划的四个要素（缺一个就写不出转移）：

```text
1. 状态定义：dp[i] 到底表示什么，先用一句话说清
2. 转移方程：dp[i] 能由哪些更小的 dp 值推出
3. 边界条件：最小规模的答案直接给定
4. 计算顺序：保证算 dp[i] 时它依赖的值已经算好
成立前提：最优子结构（大问题的最优解含小问题的最优解）
        + 重叠子问题（同一小问题被反复求解，值得缓存）
例：爬楼梯 dp[i] = dp[i-1] + dp[i-2]，dp[1]=1，dp[2]=2
```

分治与贪心两个基本范式：

- 分治：拆成同类小问题 → 分别解决 → 合并答案；归并排序、二分查找都是分治。
- 贪心：每一步只选当前最优，期望拼出全局最优；不保证对，成立需要证明。
- 拿不准用贪心还是 DP 时：能举出反例否定贪心，就老老实实 DP。

### 关键机制速览

- 复杂度怎么数：看循环层数和每层次数；嵌套相乘、并列相加取大者。
- 递归复杂度：画递归树，节点总数 × 单节点代价；主定理是这棵树的速算公式。
- 哈希函数好坏只看两点：分布均匀（少冲突）、计算快；取模法是最常见的均匀手段。
- 哈希表查找快的前提是负载因子可控；冲突再少，退化成长链表也会变 O(n)。
- 二叉搜索树一切操作都是沿一条根到叶的路径走，成本由树高决定，平衡就是保树高。
- 图的最短路径分两种：无权图用 BFS，有权图（非负权）用 Dijkstra，本质是优先队列版 BFS。
- 字符串朴素匹配 O(nm)：主串每个位置都尝试对齐模式串；KMP 的改进是不回退主串指针。
- 空间复杂度包括输入之外的辅助空间；递归栈、缓存表都要算进去，别只数变量。
- 数据规模决定选型直觉：n 小于几十随便写，n 到十万必须 O(n log n) 以内，n 到千万要 O(n) 或 O(log n)。

### 新手易错点

- 把 O(n) 两层写法的常数忽略掉：同样 O(n)，哈希查找和全表扫描在大数据下差几个数量级体验。
- 看到递归就以为空间是 O(1)：递归深度 n 时栈空间就是 O(n)。
- 二分用在无序数据上：二分的前提是单调性，数据无序时结果纯属碰运气。
- 以为排序稳定性无所谓：多键排序（先按 A 排再按 B 排）时，不稳定排序会打乱前一轮成果。
- 用浮点数做相等判断和当哈希 key：浮点有表示误差，相等判断要用误差范围。
- 整数溢出不设防：计数、金额、时间戳超 int 范围会静默变负数，该用 long 就用 long。
- 数组越界与空指针式错误：空链表、空树、单元素是所有边界 bug 的高发输入，先拿它们自测。
- 只背算法模板不记前提：快排怕近乎有序、贪心怕反例、二分怕不单调，前提错了模板全对也白搭。
