# 排序算法实现

日常开发直接用内置 sort 就够了；手写排序的价值在两处：一是面试和考试，二是理解“分治”和“堆”这两个通用思想。下面三个是最常考的：快排、归并、堆排。

## 快排：分区是全部

快排 = 选一个基准（pivot），把数组分成“小于基准”和“大于基准”两半（分区 partition），再递归排两半。分区是 O(n)，递归深度平均 O(log n)，所以平均 O(n log n)。

Lomuto 分区（取最后一个元素为基准）的逐步演示，数组 `[5, 2, 9, 1, 7, 6]`，基准 6：

```text
i 指向“小于区”的末尾（初始 -1），j 从左扫到右：
j=0: 5 < 6，i -> 0，交换 a[0] 自己，数组 [5, 2, 9, 1, 7, 6]
j=1: 2 < 6，i -> 1，交换 a[1] 自己，数组 [5, 2, 9, 1, 7, 6]
j=2: 9 不小于 6，跳过
j=3: 1 < 6，i -> 2，交换 a[2] 与 a[3]，数组 [5, 2, 1, 9, 7, 6]
j=4: 7 不小于 6，跳过
最后把基准换到 i+1 = 3 处：[5, 2, 1, 6, 7, 9]
左半 [5, 2, 1] 继续排，右半 [7, 9] 继续排。
```

```python
def partition(a, lo, hi):
    pivot = a[hi]
    i = lo - 1
    for j in range(lo, hi):
        if a[j] < pivot:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[hi] = a[hi], a[i + 1]
    return i + 1

def quicksort(a, lo=0, hi=None):
    if hi is None:
        hi = len(a) - 1
    if lo < hi:
        p = partition(a, lo, hi)
        quicksort(a, lo, p - 1)
        quicksort(a, p + 1, hi)
    return a

a = [5, 2, 9, 1, 7, 6]
partition(a, 0, len(a) - 1)
print(a)  # 一次分区后的结果
print(quicksort([5, 2, 9, 1, 7, 6]))
```

### worked 例

```text
一次分区后：[5, 2, 1, 6, 7, 9]（基准 6 落在最终位置 3）
完整快排后：[1, 2, 5, 6, 7, 9]
```

### 基准选择与最坏情况

- 固定取首/尾元素：数组已有序时每次只分出一个元素，递归深度 n，退化成 O(n²)。
- 三数取中（首、中、尾的中位数）：缓解有序输入的最坏情况，工程常用。
- 随机基准：期望 O(n log n)，最坏仍是 O(n²) 但概率极低；很多标准库用这个思路。
- 快排不稳定：分区交换会打乱相等元素的原始顺序；需要稳定时别用它。

## 归并：分治的教科书

归并 = 把数组对半分到只剩一个元素（天然有序），再两两合并。合并两个有序段时用双指针，谁小取谁；左段相等元素先取，保证稳定性。

```python
def merge(left, right):
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:  # <= 而不是 <，相等时取左段 -> 稳定
            out.append(left[i])
            i += 1
        else:
            out.append(right[j])
            j += 1
    return out + left[i:] + right[j:]

def mergesort(a):
    if len(a) <= 1:
        return a
    m = len(a) // 2
    return merge(mergesort(a[:m]), mergesort(a[m:]))

print(merge([1, 4, 7], [2, 5, 6]))
print(mergesort([5, 2, 9, 1, 7, 6]))
```

### worked 例

```text
merge([1, 4, 7], [2, 5, 6]) = [1, 2, 4, 5, 6, 7]
mergesort([5, 2, 9, 1, 7, 6]) = [1, 2, 5, 6, 7, 9]
```

归并时间恒为 O(n log n)（与输入顺序无关），空间 O(n)（合并需要辅助数组），稳定。代价是额外内存和非原地操作，数据量极大时不如快排/堆排。

## 堆排：堆化是关键

堆排 = 先把数组建成最大堆（堆顶即最大值），再反复把堆顶换到末尾、堆规模减一、对新堆顶下沉。建堆是 O(n)（不是 O(n log n)，因为大部分节点在底层，下沉路径短），每次取顶 O(log n)，共 n 次，所以总 O(n log n)，空间 O(1)，不稳定。

堆化过程（自底向上，从最后一个非叶节点开始下沉），数组 `[5, 2, 9, 1, 7, 6]`：

```text
下标：0:5 1:2 2:9 3:1 4:7 5:6，最后一个非叶节点是下标 2
节点 2 (9)：孩子 6，不用换
节点 1 (2)：孩子 1、7，换成 7 -> [5, 7, 9, 1, 2, 6]
节点 0 (5)：孩子 7、9，换成 9 -> [9, 7, 5, 1, 2, 6]，再对节点 2 (5) 下沉：孩子 6，换 -> [9, 7, 6, 1, 2, 5]
建堆完成：[9, 7, 6, 1, 2, 5]
```

```python
def sift_down(a, i, n):
    while True:
        largest, l, r = i, 2 * i + 1, 2 * i + 2
        if l < n and a[l] > a[largest]:
            largest = l
        if r < n and a[r] > a[largest]:
            largest = r
        if largest == i:
            return
        a[i], a[largest] = a[largest], a[i]
        i = largest

def heapsort(a):
    n = len(a)
    for i in range(n // 2 - 1, -1, -1):
        sift_down(a, i, n)
    heapified = list(a)
    for end in range(n - 1, 0, -1):
        a[0], a[end] = a[end], a[0]
        sift_down(a, 0, end)
    return heapified, a

h, s = heapsort([5, 2, 9, 1, 7, 6])
print(h)
print(s)
```

### worked 例

```text
建堆后：[9, 7, 6, 1, 2, 5]
堆排后：[1, 2, 5, 6, 7, 9]
```

## 三者对比

| 维度 | 快排 | 归并 | 堆排 |
| --- | --- | --- | --- |
| 平均时间 | O(n log n) | O(n log n) | O(n log n) |
| 最坏时间 | O(n²)（基准选得差） | O(n log n) | O(n log n) |
| 空间 | O(log n) 递归栈 | O(n) 辅助数组 | O(1) 原地 |
| 稳定性 | 不稳定 | 稳定 | 不稳定 |
| 适用场景 | 通用最快，常数小 | 要求稳定、链表排序、外排序 | 内存受限、求 Top K 变形 |

## 何时直接用内置 sort

- Python 的 `sorted` / `list.sort` 是 Timsort（归并 + 插入的混合），稳定、平均和最坏都是 O(n log n)，日常一律用它。
- 手写排序只出现在三种场合：面试、教学、以及内置 sort 不满足的特殊约束（如不允许额外内存又要最坏保证时选堆排、链表排序时选归并）。
- 不要为“快一点”手写快排：标准库实现经过充分调优，手写版本通常更慢且更容易写出最坏情况。

## 面试与自测

1. 快排在什么输入下退化成 O(n²)？怎么缓解？
2. 归并为什么稳定，快排为什么不稳定？
3. 堆排建堆为什么是 O(n) 而不是 O(n log n)？

### 参考答案

1. 已有序（或逆序）且固定取首/尾元素做基准时，每次分区只分出一个元素，递归深度 n，总代价 O(n²)。缓解：三数取中或随机基准。
2. 归并在合并时相等元素取左段先出，原始相对顺序不变，所以稳定；快排分区时的远距离交换会把相等元素换到彼此前面，顺序被打乱，所以不稳定。
3. 建堆从最后一个非叶节点自底向上做下沉，底层节点占一半以上且下沉路径短（叶子层路径为 0），总代价是 n/2·0 + n/4·1 + n/8·2 + … 的级数求和，收敛到 O(n)。
