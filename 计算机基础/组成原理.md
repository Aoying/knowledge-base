# 组成原理

> 骨架篇：抓住存储层次与 CPU 执行模型，其余细节按需展开。

## 1. 核心概念

冯·诺依曼结构：程序与数据都以二进制存放在同一存储器里，CPU 按"取指 → 译码 → 执行"循环工作，五大部件是运算器、控制器、存储器、输入、输出。现代计算机在它之上加了缓存层次、流水线、多核与向量指令，但主干未变。

一条指令的生命周期：PC（程序计数器）指向的地址取指 → 译码得到操作码与操作数 → 执行 → PC 自增或按跳转改写。理解这条线，就能理解分支预测、流水线气泡、上下文切换为什么有成本。

## 2. 存储层次：性能优化的根

| 层级 | 容量量级 | 访问延迟量级 | 备注 |
|---|---|---|---|
| 寄存器 | KB | <1 ns | 编译器/JIT 分配 |
| L1 缓存 | 32–64 KB/核 | ~1 ns | 指令与数据分开 |
| L2 缓存 | 256 KB–数 MB/核 | ~3–5 ns | |
| L3 缓存 | 数 MB–数百 MB | ~10–20 ns | 多核共享 |
| 内存（DRAM） | GB–TB | ~100 ns | |
| SSD | TB | ~100 μs | 比内存慢约千倍 |
| 机械盘/网络 | — | ms 级 | |

每往下一层慢一个数量级左右。"数据在哪一层"几乎直接决定代码性能，这也是缓存友好的数据结构（连续数组优于链表）跑得快的原因：缓存以 64 字节的缓存行（cache line）为单位搬运，顺序访问能整批命中，随机指针跳转则次次 miss。

## 3. CPU 执行的几个关键机制

- **流水线**：取指/译码/执行/访存/写回并行重叠，像工厂流水线提升吞吐；分支跳转猜错要冲刷流水线，所以有了**分支预测**——对代码的启示：可预测的分支（已排序数据、稳定条件）明显更快。
- **缓存一致性（MESI 等协议）**：多核各有缓存，靠协议同步状态；两个线程频繁写同一缓存行的不同变量会互相使对方缓存失效，叫**伪共享**（false sharing），Java 里用 `@Contended` 填充解决，计数器拆分（LongAdder）同理。
- **虚拟内存**：每个进程看到独立地址空间，MMU 按页（4 KB）经 TLB 翻译到物理内存；页表与 TLB miss 也是真实开销，JVM 的大页、堆大小设置都与之有关。
- **中断与 DMA**：外设不用 CPU 轮询，中断通知 + DMA 直接搬数据到内存——这是高并发网络/磁盘 IO 能成立的硬件基础，NIO、零拷贝最终都落在这里。

## 4. 数据的表示

- 补码：负数用补码表示，减法变加法；溢出是静默的（Java int 溢出不报错），金额等计算不能用浮点近似。
- 浮点 IEEE 754：符号 + 阶码 + 尾数，精度与范围的取舍决定了 `0.1 + 0.2 != 0.3`；钱用 BigDecimal 本质是避开二进制浮点。
- 字节序：大端/小端影响网络协议与文件格式解析，跨语言传二进制时必须约定。

## 5. 与开发工作的关联

- **Java 性能**：对象头、内存对齐决定对象实际占用往往比字段之和大；数组是连续内存所以遍历远快于链表，与"链表插入 O(1)"的纸面结论常相反——数据结构选型要把缓存效应算进去。
- **数据库**：B+ 树索引的设计（扇出大、树矮、节点对齐页大小）就是为"内存页/磁盘页"层次量身定做；Buffer Pool 命中率就是数据库版的缓存命中率。
- **本地大模型推理**：权重从内存/显存搬运是瓶颈，所以量化（减少搬运字节数）直接提速——显存带宽、内存带宽就是这一层的参数。
- **排查工具**：`perf`、火焰图看的是 CPU 周期花在哪条指令上；上下文切换贵，是因为要保存/恢复寄存器与刷新 TLB。

## 6. 数字速记（排查时随手估算用）

- L1 ~1 ns，内存 ~100 ns，SSD 随机读 ~100 μs，磁盘寻道 ~10 ms，跨机房往返几十 ms。
- 顺序读 1 MB：内存约几十微秒，SSD 约 0.3 ms，机械盘约 10 ms 以上。
- 一次上下文切换 ~1–10 μs（直接成本）+ 缓存/TLB 失效的间接成本，往往后者更大。
- 经验法则：优化先问"数据在哪一层、搬运多少字节"，再谈算法常数。

## 7. 常见误区

- 只看时间复杂度不看数据布局：同为 O(n)，顺序扫数组与跳着追指针可差几倍到几十倍。
- 认为多核等于线性提速：缓存一致性、内存带宽、伪共享都会让加速比提前见顶（阿姆达尔定律之外还有硬件上限）。
- 把 SSD 延迟当内存考虑：一次缓存 miss 去内存是百纳秒，去磁盘是百微秒，差三个数量级，系统设计对"是否落盘"必须敏感。
