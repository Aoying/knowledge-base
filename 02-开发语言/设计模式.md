# 设计模式

> 模式是"前人踩坑的命名"。别背 23 种，先掌握这 8 个，剩下查表。

## 创建型

- **单例**：DruidDataSource、Spring Bean 默认；双重检查 + volatile。
- **工厂**：`ChannelFactory.create("email")`，多渠道消息就靠它。
- **建造者**：`Lombok @Builder`，参数多的对象告别 telescoping 构造器。

## 结构型

- **代理**：Spring AOP、MyBatis Mapper 接口（JDK 动态代理）；静态代理写起来累，动态代理是正道。
- **装饰器**：`BufferedInputStream` 包 `FileInputStream`，功能叠加不改原类。
- **适配器**：把不兼容的接口包一层；老系统对接新规范时用。

## 行为型

- **策略**：`if-else` 超过 3 个分支就换策略模式 + Map 注册；支付/渠道选择是典型。
- **观察者**：Spring Event、MQ 解耦，本质都是"发布-订阅"。
- **模板方法**：定骨架，子类填细节；和策略模式常一起用。

## Spring 里的模式（面试常问）

工厂（BeanFactory）、单例（Bean 作用域）、代理（AOP）、观察者（事件）、模板方法（JdbcTemplate）。

## 反模式提醒

- 别为了用模式而用：3 个分支的 if-else 比策略模式好读。
- 过度抽象是技术债：YAGNI，能简单就简单。

## 组合实战：多渠道消息发送

策略 + 工厂 + 模板方法经常一起出现：

```java
interface MessageChannel { void send(Msg m); boolean supports(String type); }

@Component class EmailChannel implements MessageChannel { /* ... */ }
@Component class SmsChannel implements MessageChannel { /* ... */ }

@Component
class ChannelFactory {                       // 工厂：创建逻辑收敛
    private final Map<String, MessageChannel> channels; // Spring 按 type 注入
    MessageChannel get(String type) { return channels.get(type); } // 策略：选哪个
}

abstract class AbstractSender {              // 模板方法：流程骨架固定
    final void execute(Msg m) { validate(m); doSend(m); audit(m); }
    abstract void doSend(Msg m);
}
```

- if-else 分支一多→策略模式；创建逻辑散落→工厂收敛；流程固定、细节可变→模板方法定骨架。
- 三者不互斥：工厂里选策略，策略里套模板方法，是企业代码的常见组合拳。
