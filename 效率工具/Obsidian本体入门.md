# Obsidian本体入门

> 本篇只讲 Obsidian 本体：Vault、笔记、双链、图谱、核心插件，以及从 0 建库的最小工作流。第三方插件的具体用法见 [效率工具/Obsidian-插件使用指南.md](效率工具/Obsidian-插件使用指南.md)（25 节），Markdown 语法本体见 [效率工具/Markdown基础语法.md](效率工具/Markdown基础语法.md)。

## Vault：库就是一个文件夹

Obsidian 的 Vault（库）不是数据库文件，就是你电脑上的一个普通文件夹，里面全是 `.md` 文本文件和附件。

- **可多开**：一个 Vault 对应一个用途，如一个放知识库、一个放日记，左下角可切换。
- **可搬家**：整个文件夹拷走就是完整备份，换电脑、换工具都能直接打开，不被厂商锁定。
- **纯文本**：笔记就是 Markdown 文件，哪天不用 Obsidian 了，用任何编辑器、Git 都能继续读、继续改。
- **配置也放里面**：Vault 根目录下的 `.obsidian/` 文件夹存主题、插件、快捷键等配置；跨端同步时它也会跟着走，主题类配置在手机端可能不兼容，改主题前先想想另一端。

## 核心对象一张表

| 对象 | 是什么 | 怎么用 |
|---|---|---|
| 笔记 | 一个 `.md` 文件，文件名即标题 | 一篇笔记讲一个知识点，别把弱相关内容塞进同一篇 |
| 文件夹 | Vault 里的目录 | 按领域分，如 `开发语言/Java/`，最多三层，别建太深 |
| 双链 | `[[笔记名]]` | 在正文里点一下跳到同名笔记，是 Obsidian 组网的基本单位 |
| 反向链接 | 指向当前笔记的所有双链 | 在笔记底部面板查看，“谁引用了我”一目了然 |
| 出链 | 当前笔记指向别人的双链 | 帮你发现一篇笔记到底关联了哪些知识 |
| 图谱视图 | 所有笔记与双链的可视化网络 | 看知识结构、找孤岛笔记（没有任何链接的篇） |
| 标签 | `#标签名` | 跨文件夹聚合，如 `#待办事项` 聚合所有待办笔记 |
| 搜索 | 全库全文检索 | 支持按路径、标签、属性过滤，如 `tag:Java path:开发语言` |
| 书签 | 收藏的笔记、搜索、图谱视角 | 常用入口固定下来，不用每次现找 |
| 大纲 | 当前笔记的标题结构 | 长文快速跳转，也能拖动标题调整章节顺序 |
| 属性 | 文档顶部 Frontmatter 的图形化面板 | 不用手写 YAML 就能改元数据，如层级、标签、更新日期 |

## 核心插件一张表（本体自带）

核心插件是 Obsidian 内置的，开箱即用，不用另外安装；第三方插件才需要去市场里装。

| 核心插件 | 用途 | 入门用法 |
|---|---|---|
| 大纲 | 当前笔记标题导航 | 右侧栏打开，长文跳转、拖动调章节顺序 |
| 反向链接 | 看“谁引用了我” | 笔记底部面板自动列出所有反向链接 |
| 图谱视图 | 知识网络可视化 | 左侧栏打开，按标签、文件夹着色，找孤岛 |
| 搜索 | 全库检索 | `Ctrl+Shift+F`，支持 `tag:`、`path:` 等过滤语法 |
| 书签 | 收藏入口 | 星标笔记、搜索条件、图谱视角，集中回访 |
| 模板 | 新建笔记套用固定结构 | 设一个模板文件夹，新建时一键套用 |
| 日常笔记 | 按日期自动建日记 | 设好日期格式与存放文件夹，每天一篇 |
| 画布 | 白板式自由组织 | 把笔记、图片、卡片拖到画布上连线，适合梳理思路 |
| 属性 | Frontmatter 图形化编辑 | 在笔记顶部面板改属性，不用手写 YAML |
| 同步 | 官方多端同步（付费） | 开 Vault 级同步前先完整备份一次 |

第三方插件（dataview、templater、tasks、obsidian-git 等）一律归插件指南，不在本篇展开。

## 从 0 建库的最小工作流

1. **建库**：新建一个空文件夹当 Vault，别直接拿桌面或下载目录当库，附件和无关文件会全涌进来。
2. **定结构**：先定两级文件夹，如 `开发语言/`、`效率工具/`，再往下按需分一层；结构定下来就别频繁挪，链接靠文件名、挪文件夹不影响双链，但路径链接会断。
3. **写第一篇**：新建一篇笔记，用 `[[ ]]` 链向一篇还没写的笔记——Obsidian 会把它显示为“待建链接”，点一下就地创建，边写边长出网络，比先搭完美目录更自然。
4. **找回**：养成两个习惯——给进行中的笔记打标签，用搜索 `tag:` 过滤；每周看一次图谱，把孤岛笔记（无任何链接）连进网络。
5. **复盘**：每天一篇日常笔记，只记三行：今天做了什么、卡在哪、明天先做什么；周末翻一遍本周日记，把值得沉淀的转成正式笔记。

## 同步与备份观念（点到为止）

| 方式 | 利 | 弊 | 适合 |
|---|---|---|---|
| 官方 Sync | 开箱即用、冲突处理友好 | 付费 | 不想折腾、手机电脑都要用 |
| Git（obsidian-git） | 免费、有完整历史、可回滚 | 要懂一点 Git，冲突要手动解 | 已在用 GitHub/Gitee 的用户 |
| 手动拷文件夹 | 零成本、零学习 | 易忘、易覆盖、无历史 | 偶尔换电脑的轻量用户 |

三条底线，不展开：

- **开同步前先完整备份一次**：把 Vault 文件夹整个拷一份，同步出问题时有退路。
- **别让两个端同时改同一篇**：多端同步的冲突大多来自两边同时编辑，改完一边等同步完成再开另一边。
- **主题与外观配置会跨端同步**：手机端对主题兼容性更敏感，改主题、外观前先确认另一端能正常打开；出问题先查 `.obsidian/themes/` 与 `appearance.json`。

具体插件配置（如 obsidian-git 的自动提交间隔、排除规则）见插件指南。

## 常见误区

- **把 Obsidian 当数据库用**：它就是一堆 Markdown 文件，别指望它做复杂查询与权限管理；查询需求用 dataview（插件指南），权限需求换真正的系统。
- **双链滥用**：满篇 `[[ ]]` 不等于组网。链接要有语义：只链真正相关的概念，泛泛的词（如“方法”“问题”）别链，否则图谱会糊成一团。
- **附件散落各处**：建库时就定一个附件文件夹（如 `attachments/`），图片、PDF 统一放进去，否则换电脑、清库时附件最容易丢。
- **先搭完美结构再写**：结构是写出来的，不是设计出来的。先写十篇，再根据实际内容调文件夹，比空库时纠结目录有用得多。
- **只同步、不备份**：同步不是备份，误删同步到各端就都没了；重要库定期整文件夹拷一份到别处。

## 小技巧与冷知识

【小技巧】找笔记别翻文件夹，用快速切换 `Ctrl+O`：输入几个关键字就能按文件名模糊定位，比在左侧文件树里一层层点快得多。配合命令面板 `Ctrl+P`，几乎所有操作（新建、切换视图、开关插件）都能键盘完成，鼠标只留给点链接和拖画布。

【小技巧】双链可以只链到某一节：`[[笔记名#章节标题]]` 跳过去直接落在那一节，`[[笔记名#^块标识]]` 能链到具体段落。长文里被引用的往往是某一节而不是整篇，链到节可以少让读者在长文里再翻一遍。

【小技巧】链接的显示文字和目标可以分开写：`[[真实文件名|想显示的词]]`，竖线前面是真实笔记名、后面是正文里显示的词。写正文时不用为了链接通顺而改文件名，文件名保持“知识点本名”，行文里的叫法用显示文字兜住。

【小技巧】想在 A 篇里直接看到 B 篇内容，用嵌入而不是链接：`![[笔记名]]` 会把整篇嵌进来，`![[笔记名#某一节]]` 只嵌那一节。适合“总览篇里直接展开某节结论”的写法，但嵌多了会让总览篇变长，超过一屏的引用还是改回普通双链。

【小技巧】给笔记起别名，写双链时就不用死记文件名：在 Frontmatter 写 `aliases: [别名1, 别名2]`，之后 `[[别名1]]` 也能链到这篇。英文术语、简称、旧叫法都放进别名，写链时按脑子里先冒出来的词打就行。

【小技巧】改文件名不用怕链断：Obsidian 重命名笔记时会自动更新全库引用它的双链，链接靠的是内部追踪而不是写死的路径。真正会断的是正文里手写的 Markdown 路径链接（`[文字](开发语言/xxx.md)`），改文件夹结构前先搜一下有没有这类链接。

【小技巧】搜索时加 `-"关键词"` 可以排除含这个词的笔记，`file:待办` 只在文件名里找，`line:(TODO 修复)` 只在行内找。组合起来比如 `tag:Java -file:归档`，能直接筛出“Java 相关但还没归档”的笔记，比先搜出来再肉眼过滤快。

【小技巧】核心插件“文件恢复”是默认开启的后悔药：它会定期给笔记做快照，误删一段内容后在设置里按时间点找回，不用等同步或 Git。快照存在本地 Vault 里，换电脑前先确认新机器上它也在跑，否则快照不会跟着走。

【小技巧】模板里可以用 `{{date}}` 和 `{{time}}` 自动填日期时间：核心插件“模板”新建笔记时会自动把这两个占位符替换成当天日期和时间。日常笔记、周报这类固定格式的篇，先把模板写好，建篇时只填正文，不用每次手写日期。

【小技巧】`Ctrl+点击` 链接会在新标签页打开目标笔记，原标签页不动。顺着双链一路点下去想回头对比两篇时，用新标签页开目标，比来回跳转再用后退键找位置省事。

【冷知识】Obsidian 的开发者之前做的是大纲工具 Dynalist，2020 年才发布 Obsidian。它从一开始就坚持本地优先：笔记存在你自己的文件夹里，不经过他们的服务器，这也是本篇说“不被厂商锁定”的底气来源。

【冷知识】Vault 里的 `.obsidian/` 不只是放主题和插件开关，工作区布局（开了哪些面板、哪个在前台）存在 `workspace.json` 里。换电脑后布局乱了、或者手机端打不开，先看这两个文件是不是被同步带过来的旧版本，删掉 `workspace.json` 让它重建往往比逐项排查更快。

【冷知识】图谱视图里可以按住 `Ctrl` 拖动节点手动摆位置，也可以把鼠标悬停在节点上只看它的一度邻居。节点太多糊成一团时，先用右上角的筛选只显示某个文件夹或某个标签，孤岛和枢纽节点一下子就看清楚了。

【冷知识】Obsidian 本体其实没有“导出 HTML”的一键功能，官方只内置了导出 PDF。想把笔记发成网页，要么用官方付费的 Publish，要么用插件或别的工具转，建库时如果早晚要发布，附件路径和链接写法一开始就按发布友好的方式定。

## 面试与自测

1. Vault 到底是什么？为什么说 Obsidian 不锁定用户？
2. 双链、反向链接、图谱视图三者分别解决什么问题？
3. 核心插件和第三方插件的分界是什么？dataview 属于哪边？
4. 多端同步前为什么要先完整备份？同步和备份的区别在哪？
5. 自测：在一个空文件夹建库，写三篇互相双链的笔记，打开图谱视图，确认三篇连成网络且没有孤岛；再给其中一篇打标签，用搜索 `tag:` 把它找出来。

### 参考答案

1. Vault 就是一个普通文件夹，里面全是 `.md` 文本文件和附件。不锁定用户的原因是数据格式开放：不用 Obsidian 也能用任何编辑器、Git 直接读改，整个文件夹拷走就是完整迁移。
2. 双链解决“从一篇跳到另一篇”的正向跳转；反向链接解决“谁引用了我”，在笔记底部自动列出所有指向当前笔记的链接；图谱视图把全库笔记与双链画成网络，解决“整体结构长什么样、哪篇是孤岛”的问题。
3. 分界是是否内置：核心插件是 Obsidian 自带的，开箱即用；第三方插件要去市场安装。dataview 是第三方插件，归插件指南，不属于本体。
4. 因为同步会把删除、覆盖同步到各端，误删一旦同步就都没了；同步解决的是“多端一致”，备份解决的是“丢了能找回来”，两者不是一回事。开同步前整文件夹拷一份，出问题时才有退路。
5. 检查点：图谱里三个节点两两之间有连线（按你写的双链方向），没有落单节点；搜索框输入 `tag:你打的标签` 能命中那篇且只命中带该标签的篇；若图谱有孤岛，说明某篇的双链写错了文件名或没写链，回去核对文件名。
