# Markdown基础语法

> 本篇只讲语法本体：写出能被所有 Markdown 渲染器正确显示的文档。Obsidian 的双链、Frontmatter 入门附在末尾；Obsidian 第三方插件用法见 [效率工具/Obsidian-插件使用指南.md](效率工具/Obsidian-插件使用指南.md)，不在本篇。

## 标题与段落

```markdown
# 一级标题（全文一个）
## 二级标题
### 三级标题
```

- 标题 `#` 后必须跟空格，否则渲染器会当成普通文本。
- 段落之间空一行才分段；只换行不空行时，多数渲染器会把两行拼成一段。
- 想在段内强制换行：行尾加两个空格再换行，或直接用 `<br>`。中文写作里更稳妥的做法是空行分段，别依赖行尾空格（看不见、易误删）。

## 强调与行内标记

```markdown
**加粗**、*斜体*、`行内代码`、~~删除线~~
```

- 加粗用 `**`，斜体用 `*`，别混用；中文两侧的 `*` 紧贴文字，中间别插空格，否则可能渲染失败。
- 行内代码用反引号，适合写变量名、命令、文件名，如 `docker ps`。
- 想原样显示 `*`、`#` 这类符号，在前面加反斜杠转义，如 `\*`。

## 列表

```markdown
- 无序列表用 - 或 *
- 子项缩进两个空格
  - 子项内容
1. 有序列表用数字加点
2. 数字不必连续，渲染时会自动重排
- [ ] 待办事项
- [x] 已完成事项
```

- 缩进必须用空格，别用 Tab；不同渲染器对 Tab 的处理不一致。
- 任务列表 `- [ ]` 在 Obsidian、GitHub 都能渲染成可勾选框，是看板与读书追踪的基础写法。

## 代码块

````markdown
```java
public static void main(String[] args) {
    System.out.println("hello");
}
```
````

- 围栏用三个反引号，紧跟语言名可获得高亮，如 `java`、`sql`、`yaml`。
- 代码块里再写围栏时，外层用四个反引号，避免内层提前闭合。
- 行内代码与代码块分工：行内贴短片段，超过三行一律用围栏。

## 链接与图片

```markdown
[显示文字](https://example.com)
[站内文档](docs/guide.md)
![图片说明](images/arch.png)
```

- 图片就是链接前面加 `!`，括号里是路径或 URL。
- 链接文字里别嵌套 `[]`，路径含中文或空格时，Obsidian 内可用，GitHub 渲染建议做 URL 编码或改用英文路径。
- 本库规范：正文跨篇引用用从仓库根开始的路径链接，如 `工程实践/Git-运维与工具.md`，不用 `../` 相对路径。

## 引用与分割线

```markdown
> 引用一段话。
> 第二行前面也要加 >，否则会断出引用块。

---
```

- 引用块内换行每行都要带 `>`；多段引用之间空行 + `>` 隔开。
- 分割线用三个以上的 `-` 或 `*` 单独成行，前后各空一行；`---` 放在文档开头会被解析成 Frontmatter，别在正文开头误用。

## 表格

```markdown
| 列 A | 列 B |
| --- | ---: |
| 左对齐 | 右对齐 |
| 居中 | 默认左对齐 |
```

- 表头分隔行的冒号定方向：`---` 左对齐，`---:` 右对齐，`:---:` 居中。
- 单元格内容里出现 `|` 必须转义成 `\|`，否则表格会多出一列。
- 表格不适合写长段落：单元格内容超过一行就该拆成列表或小节。

## Obsidian 风格：双链、嵌入与标签

```markdown
[[笔记名]]              <!-- 双链：点一下跳到同名笔记 -->
[[笔记名|显示文字]]      <!-- 别名双链 -->
![[图片.png]]           <!-- 嵌入图片 -->
![[笔记名#某个标题]]     <!-- 嵌入另一篇笔记的某个小节 -->
#标签名                <!-- 行内标签，点标签可聚合所有带该标签的笔记 -->
```

- 双链靠文件名定位：文件名即标题，禁止重名，否则链接会指到错的笔记。
- `[[ ]]` 只在 Obsidian（及支持 Wiki 链接的工具）里是链接，GitHub 上渲染为普通文本；需要跨平台可读时，正文跨篇引用仍用标准 Markdown 路径链接。
- 标签名不要带空格，用 `-` 连接，如 `#待办事项` 不要写成 `#待办 事项`。

## Frontmatter 入门

文档顶部的 YAML 块，供机器读取元数据，不参与正文渲染：

```yaml
---
知识点: HashMap
层级: 基础
适用版本: JDK 8+
更新日期: 2026-10-25
关联:
  - ConcurrentHashMap
标签:
  - Java
  - 集合
---
```

- 必须是文档最前面两行 `---` 包起来的块，前面不能有空行或标题。
- 本库要求：知识点文档的 Frontmatter 字段固定为知识点、层级、适用版本、更新日期、关联、标签；标签只能用标签索引里登记的词。
- Obsidian 里这块会显示为“属性”（Properties）面板，可图形化编辑，不必手写 YAML。

## 常见渲染坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 标题 `#` 后没空格 | 显示成普通文本 | `#` 后加空格 |
| 段落没空行 | 两段拼成一段 | 段间空一行 |
| 表格里裸 `\|` | 表格多出一列 | 写成 `\|` |
| 列表用 Tab 缩进 | 子项层级错乱 | 一律用两个空格缩进 |
| 围栏里再写三个反引号 | 代码块提前闭合 | 外层用四个反引号 |
| 文档开头写 `---` | 被当成 Frontmatter | 正文分割线别放开头，或用 `***` |
| 中文路径链接 | GitHub 上点不开 | 改英文路径或做 URL 编码 |
| 行尾两个空格换行 | 看不见、易误删 | 中文写作直接空行分段 |

## 小技巧与冷知识

【小技巧】同一链接在文中出现多次时，用引用式链接只写一次地址：正文里写 `[文档名][kb]`，文末统一写 `[kb]: 工程实践/Git-运维与工具.md`。地址改了只改文末一行，不用全文逐处替换；链接一多，正文里也不再被长 URL 淹没，读起来干净得多。

【小技巧】行内代码里本身含反引号时，外层用双反引号包裹：写 `` `` `x` `` `` 才能原样显示 `` `x` ``，单层反引号会在第一个 `` ` `` 处提前闭合。围栏代码块里则不需要转义反引号，直接写就行，行内与块级的转义规则不一样，别混用。

【小技巧】代码块语言名写错不会报错，只是不高亮：围栏后写 `jav` 或拼错的语言名时，渲染器会把它当成普通文本块显示，内容本身不受影响。怀疑高亮没生效时先检查语言名拼写，而不是怀疑代码块语法写错了；GitHub 的语言名以 Linguist 的命名为准，不是所有缩写都认。

【小技巧】列表项里写第二段文字或代码块时，后续内容要缩进到与列表项内容对齐，否则会脱出列表：`- 第一点` 下面另起一段，段首缩进两个空格才算仍属于这一项，不缩进就变成列表外的独立段落。写“列表项 + 补充说明”的笔记时，这个对齐缩进是最常被忽略的一步。

【小技巧】行首出现 `2026. 开头` 这类“数字加点”会被误认成有序列表：渲染器看到行首的 `1.`、`2026.` 就会起一个有序列表，段落结构当场打乱。确实要以数字加点开头写句子时，在点号前加反斜杠转义，写成 `2026\. 开头`，就能原样显示。

【小技巧】图片想做成可点击的，用“图片套链接”：`[![架构图](images/arch.png)](https://example.com)`，点图片就跳到目标地址。缩略图配原图大图、流程图配在线文档时很常用；单独的 `![]()` 只能展示，不能跳转。

【小技巧】想在笔记里藏一段不渲染的备注，用 HTML 注释 `<!-- 备注内容 -->`：它不会显示在渲染结果里，但源码里一直在，适合留“这段待核实”“下次补充”的提醒。注意导出或换渲染器时行为可能不同，重要信息别只藏在注释里。

【小技巧】长篇笔记里用 `<details>` 折叠次要内容：`<details><summary>点击展开</summary>` 包住大段引用、日志或对照表，正文只留一行摘要，读的时候按需展开。GitHub 和 Obsidian 都支持这种写法，比把几百行全摊在正文里清爽得多。

【小技巧】链接后面可以跟悬停标题：`[显示文字](https://example.com "悬停时显示的说明")`，鼠标停在链接上会弹出这段说明。给缩写链接、外部引用补一句“这是什么”，比在正文里另起一句解释更省地方。

【小技巧】标题别跳级：`#` 后面直接写 `###`，渲染出来的字号没问题，但文档大纲会断层——Obsidian 的大纲面板、GitHub 的目录都会按层级嵌套，跳级后小节挂不到正确的父标题下。层级宁可多写一级过渡标题，也别为省事跳级。

【冷知识】表格、任务列表、删除线、脚注都不是原始 Markdown 的语法：John Gruber 2004 年发布的 Markdown 只有标题、段落、强调、列表、链接、图片、引用、代码、分割线这几样。表格这些是后来 GitHub Flavored Markdown（GFM）加的扩展，所以换到只认原始规范的严格渲染器上，`~~删除线~~`、`- [ ]` 可能直接原样显示。

【冷知识】`~~删除线~~` 的 `~` 和 `*` 的转义规则不一样：`*` 是强调符号，在词中间也可能触发斜体；`~` 本身不是强调符号，`~~` 只有成对出现才构成删除线。写波浪线装饰、数学近似号时不用担心被误解析，但写删除线时必须保证首尾各两个 `~`，少一个就失效。

【冷知识】`foo_bar_baz` 里的下划线不会变成斜体：CommonMark 规定 `_` 构成的强调不能出现在单词内部，所以 `foo_bar_baz` 原样显示，而 `foo *bar* baz` 里的星号可以。用下划线给变量、文件名加强调时，`*变量名*` 比 `_变量名_` 更可靠，尤其是在中英文混排的句子里。

【冷知识】标题支持“闭合式”写法：`## 标题 ##` 末尾的 `##` 会被渲染器忽略，显示效果和 `## 标题` 一模一样。这是 CommonMark 保留的 ATX 闭合标题语法，早期 Markdown 教程里常见；现在基本没人写了，读老文档时见到别以为是排版错误。

【冷知识】缩进四个空格的代码块是比围栏更老的写法：原始 Markdown 里没有三个反引号，代码块靠“段落整体缩进四格”表示。围栏语法是后来 GFM 推广的，老文档、老教程里看到缩进式代码块不要误以为是格式错乱；但它和列表缩进共用同一机制，嵌套在列表里的代码块缩进层数容易算错，新文档一律用围栏更稳妥。

【冷知识】裸 URL 自动变链接是 GFM 的行为，不是所有渲染器都认：GitHub 上直接粘贴 `https://example.com` 会自动变成可点链接，但严格按 CommonMark 渲染时它只是普通文本。想保证在任何渲染器上都能点开，写成显式的 `[文字](https://example.com)` 或尖括号形式 `<https://example.com>`，别依赖自动链接。

## 面试与自测

1. 段落之间只换行不空行，渲染结果是什么？为什么？
2. 表格单元格里要写 `|`，应该怎么写？不转义会发生什么？
3. `[[笔记名]]` 和 `[显示文字](路径.md)` 各适合什么场景？为什么本库正文跨篇引用要求用后者？
4. Frontmatter 必须放在什么位置？前面多一个空行会怎样？
5. 自测：写一段笔记，含二级标题、有序列表、任务列表、一张三列表格、一段 Java 代码块，渲染后逐项检查是否都显示正确。

### 参考答案

1. 多数渲染器会把两行拼成一段，因为 Markdown 里换行默认只是空白符、不断段；分段必须空一行。段内强制换行要靠行尾两个空格或 `<br>`，但中文写作更稳妥的做法是空行分段。
2. 写成 `\|`。不转义时渲染器会把 `|` 当成列分隔符，表格多出一列、后续列全部错位。
3. `[[笔记名]]` 是 Obsidian 的双链，适合库内笔记互跳，靠文件名定位；`[显示文字](路径.md)` 是标准 Markdown 链接，所有渲染器（包括 GitHub）都认。本库正文跨篇引用要求用后者，是为了跨平台可读；双链只在 Obsidian 内有效，GitHub 上会退化成普通文本。
4. 必须放在文档最前面，由两行 `---` 包起来，前面不能有空行或标题。前面多空行或标题时，解析器认不出它是 Frontmatter，会把它当成正文里的分割线或普通文本，元数据失效。
5. 检查点：二级标题字号小于一级且正常显示；有序列表序号自动连续；任务列表渲染成可勾选框；三列表格列数与表头一致、分隔行冒号方向正确；Java 代码块有高亮且围栏没有提前闭合。任一项不对，先对照“常见渲染坑”表排查。
